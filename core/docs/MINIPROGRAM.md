# CubeRoot 微信小程序跟踪

> 最后更新：2026-08-30。本文是小程序的架构约定、当前状态、上线清单和迭代记录。后续开发先更新这里，不再另建互相冲突的计划。

## 1. 产品路线

小程序采用“原生外壳 + 网站能力”的混合架构。

- 网站继续负责计时器、公式库、比赛、百科和课程等成熟功能。
- 小程序原生层只负责微信登录、一级导航、加载失败恢复、智能魔方 BLE，以及未来的订阅消息等微信专属能力。
- 网站功能默认通过 `web-view` 复用；只有 `web-view` 做不到、体验明显不合格，或必须调用微信 API 时，才考虑原生实现。
- 原生实现需要算法或数据逻辑时，先从网站提取到 `@cuberoot/shared`，再由两端共同引用；不复制页面组件和业务规则。

这条路线的目标不是把网站再写一遍，而是让网站保持唯一业务来源，小程序提供微信入口和平台增量能力。

## 2. 维护边界

| 改动 | 唯一入口 | 约束 |
|---|---|---|
| 网站首页公开入口、标题、说明、顺序 | `@cuberoot/shared/site-directory` | 网站补视觉素材，小程序补平台动作；两端不得另写第二份目录 |
| 工具 tab、账号管理网页、网页白名单和分享路径 | `apps/miniprogram/src/lib/web-routes.ts` | 工具 tab 固定打开网站 `/zh`；“我的”是原生分享页，登录后仅在用户主动操作时通过账号键打开 `/zh/account`；其他公开路由共享目录派生，另追加隐私和退出私有入口 |
| 网站和 API 域名 | `apps/miniprogram/src/lib/runtime-config.ts` | 只使用已在小程序后台配置的 HTTPS 域名 |
| `web-view` 加载、换票超时、失败和重试 | `apps/miniprogram/src/lib/web-view-page.ts` | 计时、工具和通用网页共用，不各自补丁 |
| `web-view` 加载与错误界面 | `apps/miniprogram/src/templates/web-route-view.wxml` + `app.wxss` | 页面只传状态，不复制 WXML 或页面级样式 |
| 登录、会话和错误文案 | `apps/miniprogram/src/lib/auth.ts` | AppSecret 永远只在服务端 |
| 跨端登录与退出落地 | 网站 `lib/auth-store.ts` + `app/auth/miniprogram/page.tsx` | 小程序只发起受控跳转，不复制网页存储键和清理规则 |
| 移动端与小程序隐私政策 | `packages/client/app/[lang]/privacy/page.tsx` | App、小程序和网页共用一份真实声明 |
| 构建与上传前自动检查 | `apps/miniprogram/scripts/build-state.mjs` + `release-check.mjs` + `release-check-lib.mjs` | 只允许上传当前源码生成且内容未变的完整 `dist`；新增隐私敏感能力时先阻断上传 |
| 跨端计时数据类型和纯逻辑 | `@cuberoot/shared/timer` | 不复制网站计时器 UI |
| GAN v2/v3/v4 协议、解密与魔方状态解码 | `@cuberoot/shared/smart-cube/gan-v2` + `gan-v3` + `gan-v4` + `gan-crypto` + `gan-move-sync` + `cubie` | 网站 Web Bluetooth 和小程序微信 BLE 共用同一解析与状态逻辑 |
| GoCube/Rubik's Connected 协议字节解析 | `@cuberoot/shared/smart-cube/gocube` | 两端只维护各自传输适配器，不复制帧解析、转动映射或命令常量 |
| Giiker/米家协议状态与转动解析 | `@cuberoot/shared/smart-cube/giiker` | 网站与小程序复用同一解析器，传输层分别使用 Web Bluetooth 与微信 BLE |
| MoYu AI MHC 旧协议转动解析 | `@cuberoot/shared/smart-cube/moyu` | 网站与小程序复用同一 UUID、设备名匹配和转动累积解析，传输层各自维护平台生命周期 |
| 智能魔方短时中继协议 | `@cuberoot/shared/smart-cube/relay` | 原生 BLE 只作为数据源，网站计时器只作为数据接收方；不把会话数据写入数据库 |
| 小程序智能魔方连接生命周期 | `apps/miniprogram/src/lib/smart-cube/session.ts` | 页面只展示状态和发起操作，不直接管理 socket、BLE 连接或竞态 |
| 全局视觉变量和通用按钮 | `apps/miniprogram/src/app.wxss` | 页面只写自身布局 |
| 账号落库 | 服务端 `account_auth.ts` + `wechat_miniprogram.ts` | 网站和小程序都只用 UnionID |

新增或调整网站首页入口时，只改共享目录并补测试；网站和小程序会同时消费。新增原生功能前，先在本文件写清楚为什么不能继续复用网站。

路由测试会直接核对 `packages/client/app/[lang]` 中的真实页面或 `next.config.ts` 中的明确跳转。网站若移动入口，小程序测试必须同时失败，避免发布后才发现 `web-view` 指向失效地址。

当前小程序没有原生计时数据层。原生页只连接 BLE，并通过短时内存中继把事件交给网站现有计时器；计时 UI、成绩、统计和设置仍以网站为唯一来源。以后增加协议也必须先提取共享纯逻辑，不能复制网站计时器 UI 或另建备用实现。

## 4. 账号方案

网站扫码登录和小程序登录都以同一开放平台返回的 UnionID 作为：

```text
provider = wechat
provider_uid = unionid
```

禁止在 UnionID 缺失时回退到 OpenID。两者命名空间不同，回退会把一个用户拆成两个账号。

原生小程序的 JWT 存在小程序本地存储中，网站登录态由现有 `applySession()` 写入网页 `localStorage`，两者不会自动共享。现在统一走服务端一次性换票：小程序用 Bearer JWT 申请 90 秒单次 ticket，把 ticket 放在 URL fragment 中交给网页；网页原子核销后获得新 JWT 和当前账号资料，再调用网站已有的 `applySession()`。长期 JWT 不进入 URL，服务端只保存 ticket 的 SHA-256。

“我的” tab 只保留可分享的原生登录门和轻量账号摘要，不复制网站账号资料或设置界面。没有小程序会话时调用现有 `wx.login` 交换入口；获得会话后仍停留在原生页，只有用户主动点“打开账号管理”才走一次性换票进入网站账号页。设备存储不可读、登录失败或票据失败时分别留在可重试状态，不以游客身份绕过登录门。

## 5. 开发和验收

在 `core/` 运行：

```powershell
pnpm --filter @cuberoot/miniprogram dev
pnpm --filter @cuberoot/miniprogram check
```

上传前先在微信开发者工具确认当时的稳定基础库，再显式传入同一版本执行闸门：

```powershell
$env:WECHAT_MINI_LIB_VERSION='<开发者工具显示的稳定版本>'
$env:WECHAT_MINI_SOCKET_DOMAIN_CONFIGURED='1' # 仅在后台配置 wss://api.cuberoot.me 后设置
$env:WECHAT_MINI_BASIC_INFO_APPROVED='1'
$env:WECHAT_MINI_FILING_COMPLETED='1'
$env:WECHAT_MINI_PRIVACY_REVIEWED='1'
$env:WECHAT_MINI_IOS_REAL_DEVICE_TESTED='1'
$env:WECHAT_MINI_ANDROID_REAL_DEVICE_TESTED='1'
$env:WECHAT_MINI_GAN16UI_TESTED='1' # Android 真机完成 GAN 16 ui 全链路回归后设置
$env:WECHAT_MINI_GOCUBE_TESTED='1'
$env:WECHAT_MINI_GIIKER_TESTED='1'
$env:WECHAT_MINI_MOYU_TESTED='1'
pnpm --filter @cuberoot/miniprogram build
pnpm --filter @cuberoot/miniprogram release:check
```

`build` 会保留已有正式 AppID 和明确的数字基础库；不会把已选好的本地版本重置回 `trial`。构建成功后会在被忽略的 `.tmp/` 写入源码和产物指纹，不进入上传包。`release:check` 会先运行类型检查和全部小程序回归测试，再拒绝缺页、源码变化后的旧 `dist`、构建后被改动的 `dist`，扫描源码和上传产物中的服务端凭据，并要求每次上传显式确认稳定版本、socket 合法域名、基础信息审核、备案、后台隐私指引、双平台真机和已支持设备的全链路回归。环境变量只是防遗忘闸门，不能代替真实操作。

微信开发者工具导入 `core/apps/miniprogram`，不是 `dist`。`project.config.json` 和 `project.private.config.json` 是本机配置，不提交 AppID 之外的任何凭据。

每轮完成定义：

1. 先搜索网站和 `@cuberoot/shared` 是否已有逻辑、数据或组件契约。
2. 修改唯一来源，不在页面层复制路由、状态或文案。
3. `pnpm --filter @cuberoot/miniprogram check` 全绿。
4. 微信开发者工具模拟器检查无持续 Loading、无脚本错误。
5. 智能魔方在模拟器执行“连接模拟器”，确认网站计时器收到连接、状态、转动、电量和断开事件。
6. 至少一台真机检查首页、返回、登录、失败重试和窄屏文字；涉及 BLE 时另做兼容设备连接、转动、状态、电量、断开和重连。
7. 更新本文件的状态、风险和迭代记录。

## 8. 已知风险

- 纯 `web-view` 页面会受网站发布影响，因此网站的 Chrome 91 回归测试不能删除。
- 模拟器正常不等于真机正常，尤其是登录、业务域名、网页存储和蓝牙能力。
- `web-view` 与原生层是两个存储环境，不能假设 localStorage、Cookie 或 JWT 自动互通。
- 小程序包体、基础库和审核规则会变化；涉及发布规则时以当时后台和官方文档为准。
- 主体、类目、名称和隐私声明必须与实际产品一致，不能为了审核临时写一套与产品不符的描述。

### 后台隐私指引的实际数据清单

### 2026-08-16：旧换票不得清除新账号

- 网站换票返回 401 时先核对发起请求的 token；只有当前仍是同一登录，才清理确实过期的本地会话。
- 请求期间若用户已换号或重新登录，旧请求只降级打开公开页面，不得删除后来写入的新会话。
- 该约束和成功换票后的 token 复核共同组成账号切换边界；后续异步认证结果写本地状态前都必须先确认仍属于当前会话。

### 2026-08-16：未登录与损坏存储分流

- 本地没有会话时直接按未登录处理，不再把空值误判成损坏数据并反复调用删除存储。
- 只有确实存在但结构、长度或身份字段不合法的会话才自动清理，继续阻止脏数据进入登录与网页换票流程。
- 会话解码和清理仍集中在 `auth.ts`；调用页面只消费“有效会话或未登录”两种结果，不自行判断微信存储返回值。

### 2026-08-16：正式项目类型锁定

- 上传前检查除 AppID、基础库、合法域名和包根目录外，也固定 `compileType=miniprogram`。
- 配置若被其他开发者工具项目覆盖成插件或小游戏，即使 AppID 外形正确也不能进入上传流程。
- 项目类型继续由 `project.config.template.json` 生成；正式检查负责发现生成后的人为漂移，不在页面代码复制配置判断。

### 2026-08-16：发布命令自带质量验证

- `verify` 是小程序类型检查与回归测试的唯一组合入口；日常 `check` 和正式 `release:check` 都复用它，不再各写一套质量命令。
- 正式发布检查不能只看配置和构建指纹：类型错误或行为回归同样会阻断上传，操作员不需要记住额外补跑测试。
- 结构测试固定这条命令关系；以后调整测试工具时只修改 `verify`，不得把发布命令退回为单独执行静态闸门。

### 2026-08-16：页面标题失败不阻断内容

- 导航栏标题属于辅助展示，基础库偶发拒绝或同步抛错时，计时器和工具页面仍必须继续设置 `web-view` 地址。
- 标题兜底留在共享网页控制器，所有网站路由自动继承；页面适配器不得各自捕获或复制这段逻辑。
- 回归测试模拟标题 API 抛错并锁定公开页面仍能打开，避免模拟器兼容问题再次表现成永久“正在打开”。

### 2026-08-16：账号存储异常不伪造成功

- 会话读、写、删全部集中在 `auth.ts` 的受控边界；读取异常降级为未登录，计时器和工具仍可打开公开页面。
- 登录只有在会话真正写入本机后才显示成功；写入失败会提示检查设备存储，不再误报登录后下次启动又丢失。
- 退出登录只有在本地会话确实删除后才更新界面并同步退出网站；删除失败保留当前账号和重试机会，避免残留 token 被误认为已清除。
- 服务端账号资料刷新写入失败时保留原缓存身份供用户识别，但不得显示“已就绪”；只有当前会话已被退出或替换时才跳过无意义的旧结果回写。

### 2026-08-16：非关键平台 API 失败隔离

- 更新管理器、提示框、轻提示和隐私协议入口都可能在旧基础库或开发者工具异常状态下同步抛错；这些能力不得拖垮应用启动、导航锁或账号页。
- 隐私协议打不开时仍回到网站唯一隐私说明；退出确认打不开时保留当前会话并显示可重试状态，不执行未经确认的退出。
- 更新下载和提示失败只影响本次更新体验，当前版本继续可用；下次冷启动仍由微信更新机制重新检查。
- 平台反馈兜底保留在共享导航或对应能力边界，业务页面不复制“捕获后释放锁”的实现。

### 2026-08-16：网页重试调度降级

- 网页失败后的重新打开仍优先等当前视图更新完成，避免旧 `web-view` 和新地址在同一渲染批次互相覆盖。
- 若开发者工具或基础库的 `nextTick` 同步异常，共享网页控制器会立即执行同一个重试回调，不把页面留在空白加载态。
- 页面销毁检查只保留在统一回调中；正常调度和异常降级使用完全相同的生命周期边界，页面文件不得复制重试实现。

### 2026-08-16：请求超时必须收口

- 登录、账号校验和网页换票继续共用 `auth.ts` 的请求硬截止，不依赖微信请求回调一定返回。
- 到达硬截止时会尽力中止底层任务；即使开发者工具的 `abort` 自身抛错，外层 Promise 仍必须按超时结束，页面可以恢复和重试。
- 中止只是资源清理，不是完成请求的前提；后续增加网络能力必须复用该请求边界，不能自行等待微信回调。

### 2026-08-16：上传内容双边界审计

- 隐私能力和服务端凭据同时扫描 `src` 与实际上传的 `dist`，不再假设构建结果必然等同于源码文本。
- 同一种问题在源码和构建产物都出现时合并为一条并列路径，既保留定位信息，也避免发布日志重复刷屏。
- 后续构建插件、资源复制或代码生成即使意外带入敏感内容，也必须在上传前被同一发布闸门拦截。

### 2026-08-16：导航锁异常回收

- 正常页面跳转仍由微信 `complete` 回调立即释放防重复点击锁；回调被模拟器或异常基础库吞掉时，5 秒后自动恢复入口。
- 超时只回收交互锁，不主动发起第二次跳转；用户再次点击时仍重新经过共享路由白名单和失败反馈。
- 共享导航参数删除未使用的成功回调扩展，页面只提供错误文案，不为潜在需求预留无消费者接口。

### 2026-08-16：退出确认防重复触发

- “退出登录”确认框按页面实例加互斥锁，连续点击只打开一个平台弹窗，不重复删除会话或打开网站退出页。
- 用户取消、平台异步失败、同步抛错和正常完成都会释放锁；异常运行时吞掉全部回调时，5 秒后只回收交互锁。
- 本地会话仍只在明确确认后由 `auth.ts` 清理，交互防抖不复制账号状态，也不改变网站统一退出协议。

### 2026-08-16：销毁页面拒绝重新打开

- 共享网页控制器的公开打开入口也检查页面生命周期；页面卸载后，迟到回调或未来新增适配器都不能再改标题、发换票请求或写入视图状态。
- 页面正常加载时仍由统一 `onLoad` 恢复可用状态，微信复用页面实例不会被旧的销毁标记永久阻断。
- 回归测试直接在卸载后调用共享入口并锁定零副作用；后续网页页面继续只调用该控制器，不自行维护第二套存活标记。

### 2026-08-16：退出确认回调隔离

- 每次退出确认都有独立序号；旧弹窗的成功、失败或完成回调不能释放新弹窗的互斥锁，也不能执行新一轮退出。
- 页面隐藏或销毁时作废当前确认，迟到的确认结果不得删除会话、改已离场页面或继续跳转网站。
- 5 秒异常回收仍只释放交互锁；若没有发起新确认且页面仍存活，用户稍后确认原弹窗仍然有效，避免正常思考时间被当成过期操作。

### 2026-08-16：会话请求头字符约束

- 会话令牌在唯一解码入口拒绝 ASCII 控制字符，损坏存储或异常服务端响应不能把换行等内容带入 `Authorization` 请求头。
- 非法本地会话会按既有规则清理；非法登录响应不会写入设备存储，登录、账号校验和网页换票无需分别复制检查。
- 长度、用户结构和请求头字符继续由 `auth.ts` 集中约束；页面与导航模块只接收已经验证的会话对象。

### 2026-08-16：账号页平台弹窗统一互斥

- 隐私协议和退出确认共用账号页的异步交互守卫，连续点击只打开一个平台弹窗，不再各维护一套序号与生命周期判断。
- 页面隐藏或销毁会统一作废当前交互；迟到的隐私失败回调不得从已离场页面跳转网站，迟到的退出确认也不得删除会话。
- 隐私协议正常成功、失败、完成或同步抛错都会收口当前尝试；平台不支持时仍直接打开网站唯一隐私说明。

### 2026-08-16：版本更新提示幂等

- 同一冷启动内重复收到“新版本已就绪”事件时只显示一次更新确认，用户选择稍后后不再被同一版本反复打断。
- 平台异常重复回调确认结果时只执行一次 `applyUpdate`；提示框本身失败才允许后续就绪事件重新尝试。
- 更新守卫留在应用级唯一入口，不下沉到业务页面；更新失败仍只给非阻断提示，当前版本继续可用。

### 2026-08-16：版本更新回调隔离

- 每次更新提示都有独立尝试标识，旧提示延迟返回的成功或失败回调不能再改动新提示的状态。
- 只有当前有效提示可以执行 `applyUpdate`；平台回调乱序时不会重复弹窗或被旧确认意外重启。
- 回归测试主动模拟“旧提示失败后启动新提示，旧回调再迟到”的时序，防止后续维护恢复这个竞态。
