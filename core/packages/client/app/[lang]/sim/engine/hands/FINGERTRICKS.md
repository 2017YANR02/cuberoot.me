## 二至四阶的上层半转

左手中起手、右手偏离中起手时，普通外层 `U2` 由左手沿 `U′2` 的方向连拨。右手维持当前支撑，包括 `R`、`R′`、`R2`、`R2′` 留下的握姿和相应的显式换握。左食指拨前 90°，同时左中指就位，再拨完后 90°。右手半转握时，食指留在下排支撑；角块经过时，靠近顶层的指尖随之让开，转过后回到支点。公式和历史仍记录输入的 `U2`。

双手都偏离中握时按已有握姿组合选手。右手上握或下握时，二阶左上握可直接下按接力，其他左手握姿先换到中握，收指后还原。右手半转握且左手也偏离中握时，沿用该步原有方向。宽层按各自的指法，指针拖动按手动指定的方向。

## 标准四阶

层号由 NxN 引擎给出，按轴从低到高为 0、1、2、3。外侧单层沿用三阶用指，外侧两层以二阶半方为起点，三层转由对侧手固定剩余外列。单内层与中间双层保留实际层号。相邻两步即使同轴同向，也按实际活动层重新预备。四阶沿用现有换握、整转及有符号半转记号。带有尚未标定的指定手指或贴块路径的步骤停在原处。

双中手的单内层四分转按实体贴纸标定。左右内层用同侧无名指，上内层用食指，下内层用无名指。前后内层用食指推动至约 45°，随后释放。每度采样对照该贴纸随块变换后的有限方形区域，测量指腹或甲面的距离；换握、宽层和半转接力另行核对。

双中握的三层上拨（`3Uw`、`3Uw′`）由食指跟随上排的同一块贴纸。三层后拨（`3Bw`、`3Bw′`）由食指压住背面上角，约 70° 后逐渐放开。三层上拨时，对侧拇指与中指夹住底排的前、后两面。三层后拨时，对侧拇指抵住固定前层，食指搭住它的上缘。上内层半转（`2U2`、`2U2′`）沿指定方向连拨，食指跟随第一块上内层贴纸，中指提前靠近第二块，在 90° 附近接力至 180°。以还原态起拨为例，正向由右食指拨 B4、右中指接 L4；反向由左食指拨 B7、左中指接 R7。拖回时，两指随当前层角沿原路退回。松手后，上拨食指和内层接力中指绕开已经停稳的块角，食指先给回收的中指让位。

## 标准二阶

沿用三阶的手模、六面用指和双手整转，按二阶两排角块安排支撑。中起手时，食指搭在背面上角，拇指与中指分别落在前、后面的下角。下层转动时两指让开角块扫过的范围。U / U′ 单拨从指腹过渡到指甲，U2 / U2′ 由同手食指、中指接力。二阶公式里的 `U'2` 与 `U2'` 同为一步逆向半转：左食指先拨 90°，左中指接着拨完余下的 90°。例如 `R U2'` 中右手仍在上握，左手沿用中握的勾拨轨迹。两层一起转时双手抱转，宽转写法与对应的 x/y/z 同义。二阶没有独立中层，打乱或解法出现 M/E/S 时保留原文并停止播放。

- **上层双拨。** 中握和上握都按食指、中指的顺序拨动。`R U2` 采用左手中握的逆向双拨；`L' U2'` 使用左手上握的双拨。直接拖动上层时，中指在首个 90° 就位，越过 90° 后接力。拖回首个象限时，两指沿当前层角退回。
- **半转握。** `R2 U` 由左食指推动上层，右手维持支撑。遇到 `R2' D'`，右手保留反向半转握，左无名指先绕开静止下角，再贴住下层拨动。
- **下层双拨。** 中握执行 `D2` 时，左手掌在转层前下移，小指先拨 90°，无名指接住下一块底面贴纸并完成后半转。`D2'` 由右手镜像执行。
- **前后层。** `R2 F2 R2` 的前层由左拇指推动前半程，随后收手。`B2` 由食指和中指接力，另一只手可以保持半转握。

## 0. 手指记号与总原则

### 关节、腕臂与接触校验

- MANO 加载时在指骨实际绑定屈伸平面测量中、末节静息弯曲。运行时四指 PIP/DIP 的工程屈曲上限为 130°/100°，拇指 MCP/IP 为 95°/100°。无专项轨迹的四指拨动还叠加轻度 PIP/DIP 联动。腕向先限制总偏折 80°，再用模型绑定指根行列限制手相对前臂的桡偏 25°、尺偏 40°（工程余量，参考[腕活动测量](https://pubmed.ncbi.nlm.nih.gov/24322647/)）。这些数值用于模型限位，拇指对掌及四指掌弓仍用专项轨迹。四指活动范围参考 [Ibrahim 等的主动屈伸测量](https://pubmed.ncbi.nlm.nih.gov/39345665/)。
- 半握 IK 的最终姿态约束食指、中指、无名指和小指的 MCP 外展／内收为 ±25°，轴向扭转为 ±18°（原模型绑定姿态的局部角度）。MANO 同时解掌骨和近节的固定骨长链，沿屈曲分支对准原 PIP 目标，最后恢复远端目标朝向。两项数值是模型工程限位。
- 全身模式用中手腕位和模型臂长确定上胸前的持方距离。先保持躯干静止，由锁骨转动调肩，再由肩、肘旋转满足腕目标。锁骨围绕胸侧挂点转动，合成摆幅上限为 35°。连续帧优先维持上一帧的肘弯曲平面，选位同时约束肘部向身体中线穿过。双侧在此位置不可达时才求躯干平移。肘屈伸采用 0°（伸直）至 150° 的定长可达范围，接近深屈时优先调整肩位。胸前持方时肩位优先减少耸肩，让肘保持在身体同侧，并延续上一帧的弯曲平面。跳步重置手臂运动历史。
- 前臂以屈肘平面内拇指朝上为中立位。左右手均以旋前为正、旋后为负。旋前超过 70°、旋后超过 75° 时逐渐收紧，两向最多 90°。该修正绕小臂长轴作用于前臂骨，保持腕点及手指的既定动作。
- x/y/z 整转时双手从起转即随实际层角转动。整转结束后右手先回握，左手维持末姿支撑，随后左手回握。显式换握用同一条两端缓动曲线驱动手根和腕角。
- F 拨动时，食指近节和参与接力的中指保留相邻皮肤三角面的弯曲方向。指根按起手握姿限制局部伸缩，远端指腹和甲片沿原标定轨迹运动。下握 F2 在食指离开、中指接手的过渡中继续修正食指曲面。全身模式复用同一片修正后的手部网格顶点。
- 半转握姿保留末端接触时，单个材质点的接触补偿最多为本指末节骨长的 15%。该限值仅用于接触残差。体积和法线另行计算。停在半转支撑握姿的手保持静止，活动手或换握可以独立推进。
- 常规拇指推以 38° 为腕部偏折目标。标准半转握维持原指腹落点，肘沿掌面倾斜方向分担约五分之一的原始腕部偏折。手部模式下，↑↑ 和 ↓↓ 的就位总偏折分别约 64° 和 57°。全身模式沿实际肩肘腕链计算偏折。半转时的目标随转角渐变至 63°，转动层携带手掌期间也使用该目标。
- 开发模式的逐帧记录在骨架和 IK 求值后读取 `finalPose`，包含各指关节中心的世界坐标、相对绑定骨架的屈曲／侧摆／扭转、腕偏折及小臂朝向。手部模式使用起手腕位与模型比例建立虚拟肩肘参考（`virtual-upper-arm`），全身模式使用求解后的真实骨架（`upper-arm`），另记肩、肘、腕位置。
- 开发模式的手部记录器额外提供 `gestureContactSamples`。开启记录后，每次进入新的 15° 区间，在实际显示帧采样拨指及指定支撑指，保存物理块、贴纸、块内材质锚点及滑移。首次观测到接触才绑定，采样不代表区间内所有帧都已通过。指甲取独立甲片外表面。

- 已标定转动的回撤按每段掌部位移、腕姿和指关节变化分配时长。执行手和支撑手共用同一回撤进度，保留接触终点、既有回撤路径及交接次序。速度预算用于动画回撤；贴纸跟转仍由实际层角驱动。拇指宽层推完后，回撤经过右下棱时在四个标定姿态增加最多 1.15U 的向下余量，消除较密时间采样发现的擦入。

Gc 左中指腹的精细检查以物理贴纸 B5 为参考。推动时同时检查指腹三角面覆盖范围、上一帧接触材质点在下一帧的切向位移，以及已标定顶点 560 的净位移。使用 2.5U 的项目近接触带。带指法标记的宽层转动提交后，模拟手先显示一次 90° 末态，再开始回撤，首个回撤帧单独计量。半掌表面、法线和 MANO 形变只在合成网格上计算。

普通外层单拨 U / U′ 在主动手为中起手时使用同一条左右镜像的食指勾拨轨迹。指腹从背面上角的原贴纸（起手槽位 B0 / B2）随层转到侧面。轨迹以线上中起手的食指屈伸和指根位置为参考，限制掌骨转角与中节偏离屈伸轴的角度。局部蒙皮按起手边长约束指根拉伸，远端指腹和指甲由骨架带动，在 65° 交接同一张贴纸。对手下起手时也沿用这条轨迹。转完后，食指沿静止魔方外侧收回起手。双拨、宽层和上手 U 继续按各自编排。

上握 U / U2 的右食指沿同一实体贴纸推完第一象限，U5 拇指保持固定。第二象限收指经过来向角块时，掌骨稍向侧方展开，给静止中指留出间隙，随后回到原握姿。测量指根时，先扣除绑定四元数，再沿 MCP 到 PIP 的骨轴分解摆动与扭转。逐帧记录保留作者通道 `root.twist`，并提供独立的骨轴角 `root.axialTwist`（度），在轴翻到反向的奇异姿态记为空值。

F / F′ 的越顶和下拨在转动、复位时将部分过量的指根侧摆和扭转分到掌骨及近节。补偿同时依据最终骨轴角与侧摆，绕相邻骨段长轴施加，保留 MCP、PIP 的位置和远端接触。中起手食指滚甲结束到归位时，按原握姿的材质边长约束指根局部拉伸。只调整近节蒙皮，指间关节和远端接触沿用原轨迹。下起手 F2 在两指交接时减弱指蹼修正，中指归位后逐渐撤去该指的修正，为食指回收留出间隙。

中起手 F / F′ 越顶时，食指沿当前层角在标定点间作三次样条插值。起转与离面姿态仍取原端点。在随贴纸转动的坐标系内收小指腹推动和滚甲时多余的切向折返，保留贴纸、接触面和交接角度。越过后棱所需的抬升分配到起手和前伸两段，上握 U 仍使用其独立标定。准备抬指和前伸之间连续变速，转完收指时由两个阶段依次分配同一帧的经过时间。近节蒙皮以中起手为基准限制相邻三角面新增的折角，指腹和指甲沿骨架标定的接触轨迹运动。

三阶双中握做 M 或 M′ 时，只有左无名指离开握位。M 用指腹从 D7（底面靠背的中格）起拨，约 54° 开始滚向甲缘，60° 换成甲缘接触。甲缘可沿同一 M 层滑向相邻的 D4，以便自然收指。约 70° 松开，魔方继续转完剩下的角度。M′ 用指腹从 B7（背面下中格）起拨，约 60° 换成指甲续拨同一张贴纸，70° 开始松开收指。两个方向都从松开处连续收指，层转结束后完成归位。贴纸编号指起拨时的槽位。

M2 沿两次 M′ 的方向连续转动，左无名指腹拨第一拍，左小指腹从刚转入 B7 槽位的新贴纸接第二拍。M2 的无名指拨至 43° 后直接归位，小指于 90° 接手。三个动作中右手都保持中握。M2 准备与收手时，左掌沿面平移以够到第二拨，左拇指、食指和中指的指腹保持在原握点附近，发力时双掌固定。贴纸编号使用零基展开图。三阶手部播放遇到相邻、未指定手指的 `R M′` 时，将两层同时按 `r` 转，沿用宽层的抓握分工和让位。编辑框保留这两个记号。

### 0.0 手模表面（2026-11-03）

- 表面细化保留 MANO 资产、骨骼、手掌比例、默认握姿与指法路径。
- 手、融合前臂及全身人物复用同一个皮肤采样核和贴图材质参数；毛孔、肤色变化及关节细纹在绑定姿态的 3D 空间连续求值，避免 UV 接缝与腕部材质断层。
- 自然甲与甲油统一使用线性顶点色；甲床保留淡粉色、甲根融肤，只有窄游离缘偏白。甲片为贴合指背的薄壳，不使用厚白板或额外贴图指甲。
- 姿态修正后的皮肤形状同步更新面积加权法线，UV 拆点共用法线；只在姿态变化时计算，待机不重复刷新。
- 半球漫射配合侧前主光保留背光侧肤色，降低正面轮廓光，默认视角下保留关节明暗与薄甲高光。
- 验证默认握贴纸位、贴图确定性、自然甲/甲油切换，以及实际页面的正面、背面和转动姿态。

### 0.0.1 播放衔接与加载（2026-11-03）

- 连续使用同一只手前，等待上一拨回撤完成，避免清零残留幅度造成瞬跳；另一只手无冲突的动作仍可接续。保留既有 U 层对侧回撤与 reach 收指保护。
- 转层已提交但渲染帧尚未收尾时，下一步先结算上一手势，再判握姿与前置动作。收尾只作用于该手势，不能重新启动另一只手的回撤。
- 跳步、回到起点与换拼图统一清除活动手势、转前提示、伸指和回撤；模型加载期间记录最后的静态握姿，加载完成后恢复。
- 手部开启时，播放等待手模和皮肤细节就绪；加载失败明确反馈并允许重试，魔方本身继续可用。退出页面取消网络与贴图计算，释放手、人物、骨架和材质。

- 播放 F 族食指越顶时，起始抬指段从约 24 ms 放宽到 58 ms，随后沿既有曲线前卷。收指沿同一速度分段返回；实际转层跟随取原有层角与就位逻辑。

### 0.2 总原则(2026-07-09 用户规格)

普通单层转动保持手掌靠近魔方，需要让位时由手指短暂离面。支撑手让位期间暂停腕部待机浮动。换握和回收沿握姿自身的旋转弧运动，手指张开以越过棱角。

**三阶双层转动先选支撑，再起转。** 两层一起转时，另一层静止。支撑指在静止层提供支点，发力指作用在转动层。是否就位由当前双手握姿、层组、转向和显式手指标记共同决定。

- 已有两个不同指腹在静止层的相对两面形成夹持，且手指和甲片均已让开转层扫过的空间时，保持原位。常见例子是中握的 r、l，同侧手腕带动双层，对侧手夹持静止外列。
- 前宽层 f / f′（含半转）的支撑手为中起手时，原握姿的食指和无名指已贴住静止背层。手掌沿背面上抬 2U，掌腕朝向与四指屈伸保持中握，拇指略松开前面。左右镜像采用同一动作。
- 需要换支点时，支撑手在转层前沿面移向静止层，肘部目标随手掌平移。手指根据握姿先让出棱角，再落到静止层的两张贴纸上。沿原握姿的前、后两面移位时可用拇指和中指形成对夹；需要绕到相邻两面时可用拇指和食指。转层期间固定支撑，结束后沿准备路径收回。

## 2. 记号汇总(解法框)

| 记号 | 含义 | 解析 |
|------|------|------|
| `↑` `↓` `↑↑` `↓↓` `·` | 换握(上 / 下 / 半转 / 中手),**手别由空白定**(见下) | 单标记占一步；双手组合占两步，共享 `parseGripMark` |
| `p` 后缀 | **推法**(push):该步用「指尖推层」指法而非默认拨法 | 紧跟在招式 token 后,如 `U'p`;喂 cubing.js 前剥除,对魔方状态零作用 |
| `[...]` 注解块 | FTN 指法注解（手指 / 相序 / 路径 / 技法），紧贴转动 token | §7 完整设计，当前部分实装：仅无空白块 token 和 `R[R2:@C]` / `R[R2:@C>Q]` pin；喂 cubing.js 前剥除整块 |

**换握手别规则(2026-07-10 用户规格)**:记号**紧贴**后续字符(无空格,如 `↑U`)= **右手**;记号后随**空白或串尾**(如 `↑ U`)= **左手**。
- `↓F` = 右手下手再 F(直达 §4.3 左中右下);`↓ F` = 左手下手再 F。
- **2026-11-16 用户规格替代旧紧贴链语义**：`↑↑` 是一个完整的半转握姿标记：右手为中起手完成 `R2` 后，左手为中起手完成 `L′2` 后。内部使用 `half` 握姿，仅换握、不转魔方；占一步，按整个标记后是否有空白选择手别；`↓↓` 使用 `halfDown`，采用同样的手别和步数规则，但经下起手绕行并保留向下的腕臂扭转；`↑↑` / `↓↓` 串尾无空白为右手，`↑↑ ` 串尾有空白为左手。单箭头和中手标记的串尾规则保持左手。
- 双手换握改用 `↑｜↑`：左侧标记指定右手，右侧标记指定左手，按右、左顺序占两步，不依赖后续空格；也接受半角 `|`。支持 `↓｜↓`、`↑｜↓`、`↑↑｜↑↑` 等组合。原 `↑↑ U` 现在表示左手半转握姿，旧双手写法需改为 `↑｜↑ U`。
- 换握仍各占一步(`↑U` = 换握 + U 两步);紧贴只是词法上的手别标记,对招式解析零影响(剥除后 `↑U` → `U`)。
- **禁**在两招式之间无空格夹记号(`U·F`):剥除按「记号→空格」处理不会粘连,但可读性差,不要写。
- 空白是本记号系统唯一有语义的场合(§7.1 消歧规则的例外):**转写 / 格式化工具不得增删记号周边空格**。

**`p` 记号定义(2026-07-08 本文档发明)**:
- 语法:招式 token 尾接小写 `p`,与招式之间无空格(`U'p` ✓;`U' p` ✗)。助记:push / 推 / 平推。
- 推法含义统一见仓库 `docs/product/cubing/fingertrick-notation.md`：`Up`=L2 推 U、`U'p`=R2 推 U'、`Dp`=R4 推 D、`D'p`=L4 推 D'。当前仅 `U'p` 已编排；其余三种已定义但尚待编排。
- 上述四种之外的转动带 `p` 暂无统一定义；当前解析器剥掉后按默认指法播放（不报错）。已定义但未编排的推法也会回落默认动作，不能据此称为推法已支持。
- 剥除函数与 `stripGripMarks` 同层处理:invert / mirror / 反推打乱 / recon 手递前都必须剥。
- `↑↓·` 与 `p` 是 FTN(§7)的糖形式,完整编码语法见 §7.1。

### 4.1 双指连拨(通则,2026-07-08 用户规格)

一次 180° 转动由同手两根手指接力:

1. 第一指扫前 90°(层角 0 → 90°);
2. **第一指做完不恢复**——保持其 90° 末姿;
3. 第二指扫后 90°(90° → 180°);第二指的就位(预备)动作在前 90° 期间完成;
4. 第二指做完后,**两指一起恢复**回 home。

拖拽路径(不知道目标角度)第二指在层角越过 90° 时反应式接力;播放/键盘路径由 `prepareTwist(…, quarters)` 提示 180°,第二指提前预备。

### 4.2 双中手(L home + R home)

**普通 F、F′ 单拨按双手实时握姿选指**。左中右下时，F 由右食指下拨，F′ 由右拇指从下方向上推。右中左下时，F′ 由左食指下拨，F 由左拇指向上推。两种组合优先于中起手食指越顶。其余握姿沿用方向对应的选指，右中手 F 从 U8 越顶，左中手 F′ 从 U6 越顶。

**F 层接触**。越顶与下拨的主动食指持续跟随起拨贴纸；下起手半转允许中指接力。拇指上推时，先把指腹移至前层底面贴纸，随该块向上推动，再松开并回到下握。F2、F2′ 延续原有半转手法。宽层的支撑与发力分配见 §0.2。

**指间碰撞（同日补充）**：准备、推动、接力与回撤都必须检查主动手指与同手其他手指、对侧手的蒙皮表面。骨骼固定、贴纸接触及手指不穿魔方不能替代指间验收。保持上述固定握姿与接触条件，优先调整主动指的关节路径；下起手半转可调整食指退场与中指接力时序。若这些约束无法同时满足，保留失败证据并向用户说明具体冲突，不自行放开静止手指或贴纸接触。

**掌面支撑与指根测量**：MANO 手的食指至小指各有一条参与掌面蒙皮的定长辅助掌骨，两手共八条。四条骨从各自掌骨基底出发，随掌骨转向；相对绑定姿态的转角分别平滑限制在 8°、7°、12°、18°，小指一侧保留较大的掌弓活动量。这些值是网格驱动参数。拇指沿用原有对掌链。诊断中的 `knuckleLine` 根据最终近节相对掌骨的方向记录屈伸、侧摆和绕近节长轴的转角；拇指取真正的掌指关节。中起手单拨 U / U′ 约在 65° 完成指腹到甲面的交接。

**指间避让路径（2026-11-16）**：中起手 `frontIndexFollow.ts` 只调整食指屈曲、轴向旋转与掌骨关节，终段同时避开固定中指和拇指。下起手使用 `frontDownFollow.ts` 和 `frontDownMotion.ts`：中指在首个 90° 的最后 20° 准备接力，食指完成首拨后向外退场；提交后中指先收、食指后收。三条路径均每 0.5° 一个节点，按当前层角插值。食指在第一拨约 60° 由指腹滚到甲面，直至 90° 均沿原贴纸；下起手第二拨继续用中指指腹。中起手食指从最后一帧的贴纸姿态开始归位。先屈中节和末节，让指尖避开棱块，再逐渐伸回握姿；指根沿自身屈伸面展开。F2 / F2′ 在第二象限就进入同一条回收曲线，层停后接着走完。下起手 F2 的食指用 28° 让开中指，回收抬升由掌骨和指根分担。这些 F 专用编排替代 §4.1 的同时回收，以及旧 `HOOK_FOLLOW.downPush_*` / `DOWN_EXIT` / `RETREAT_LIFT_STYLED.downPush_*` 参数，不改变手掌及未参与手指。

**固定手掌路径验收（同日）**：使用真实 MANO 资产。`hands_f_contact.test.ts` 在实际 rig 生命周期中以 0.125° 步长核对 U8 / U6 实体贴纸接触，在 60° 同时核对指腹与甲面，60° 至 90° 核对真实甲面，75° 后另查指腹已退出原贴纸的接触带；下起手半转还核对中指第二拨的指腹接触；以 0.25° 步长检查主动指与同手其他指、对侧手四种握姿的三角面交叉，另覆盖准备及回撤。中起手自首拨离面至收指结束，以原握姿的指根网格边长为基准，四分之一转的每条受测边拉伸至多 1.50 倍，半转至多 1.92 倍，最终指根侧摆小于 8°、绕近节骨长轴的扭转小于 12°。接触带沿用采样器的 0..2.5U，主动指对理想方块的穿透容差为 0.1U。`hands_lifecycle.test.ts` 验证手掌及未参与手指的世界变换保持不变。`fingerCollision.ts` 仅供离线标定与回归，不进入渲染循环；检测使用实际姿态修正后的蒙皮，排除共用掌蹼三角面。有限采样不等于连续碰撞的数学证明，也不替代浏览器观感验收。

`hands_f_smoothness.test.ts` 另限制路径关节角的一阶、二阶差分，防止重新引入逐点拟合的高频突变；须与上述接触及碰撞回归一起运行。

### 4.7 中起手 R U 提前就位（2026-11-16）

右手为 home、播放器当前为单步 R 且紧接无 push/pin 的单步 U 时，先把右食指放到 **U8 空间槽位中的实体贴纸**，再开始 R。R 期间食指保持同一块面上的位置，随右层刚体转动；R 提交后右手基座成为 up，该贴纸来到 B0，食指保持就位，直接接右食指 U，不先收回默认上握的 D8 停靠位。左手四种握姿均保留各自状态。

上握单步 U 与中握 F 在手局部坐标中等价，复用 `topPush` 的抬指、越顶和就位/释放通道；`topPush` 此处表示局部路径，不表示播放了 F。右食指先用指腹，约 60° 滚到甲面，沿同一实体贴纸完成首个 90°。单独 `↑U` 也先就位 B0，再使用同一路径。U 结束后返回上握。其余握姿 U、U′、push/pin 保留各自指法。

上握 U 与中握 F 共享 `frontIndexFollow.ts` 的掌内轨迹。准备、转动及归位按同一手局部坐标标定。右拇指在 U 的准备、转动、释放与收指期间保持 U5 空间位置及关节姿势，食指皮肤与独立指甲网格均从拇指下方通过。不得通过移动拇指为食指让路；R 期间仍按整手随 R 的原有规则运动。U 收指从最后的甲面姿态屈中节和末节，让过角块，再回到上握停靠位。

右上握遇到普通单层 U2 时，左食指和中指沿 U′ 方向接力。手动指定正向转动时，原有右食指轨迹如下。食指在 B0 就位，前 60° 指腹跟住原贴纸，然后以甲面跟至 90°；后 90° 从 U5 拇指下方撤出，屈指避开扫来的角块。层停稳后直接收回 D8 停靠位，再交给下一步。拇指和其余支撑指保持上握。双中握 U2 仍按 §4.2 由食指、中指接力。

播放器仅前瞻紧邻播放项，换握记号、停顿或其他动作不跨越；R′、R2、宽层及非中握 R 不触发。显式 pin 优先。跳步/编辑重建时清除预备状态；预备后改做其他动作先收指。连续播放与向前单步共用前瞻入口，向后单步不猜测反向手法。向前单步沿用现有前置就位规则：首击摆指，到位后下一击转 R。

本地验证：`hands_ru_contact.test.ts` 使用真实 MANO，覆盖左手 home/up/down/half，逐 1° 检查 R 同贴纸、同局部点及 U 接触（左中握 U 加密到 0.25°），包含准备和收指的食指顶点穿模检查、R→U 连续性及取消预备。R 的指腹接触要求皮肤方向与贴纸外法线点积 < −0.5；U 在交接角同时检查指腹和甲面，随后检查实际朝外的甲面及原贴纸，并独立检查穿入深度，另抽样检查右食指皮肤、指甲与其他右手手指的三角面相交。新增断言锁定拇指关节和指甲的世界矩阵，并检查食指从拇指下方经过。固定原始拇指在层扫过时与理想块体有既存 0.105U 边界重叠，使用同角度冻结拇指作基线，不通过移动拇指掩盖。证据保存在 `.local-data/ru-index-preparation-20261116/` 和 `.local-data/u-under-thumb-20261116/`；不据此宣称整只手的连续三角面碰撞已全量验收。

### 4.8 中起手 S / S′ 食指按 U5 / U3（2026-11-17）

右手为 home、执行正向单步 S 时，右食指在转动前用指腹接触 **U5 空间槽位中的实体贴纸**，再沿中层转动方向下按。左手为 home、执行单步 S′ 时严格镜像：左食指先接触 **U3**，参考左中起手 F′ 下按。落点由前层 U8 / U6 改为中层 U5 / U3，不能直接使用 F 的接触曲线。按用户确认的自然收指方案，**0..45° 用指腹保持接触并发力，45..90° 先抬离，再解开屈曲和扭转，层滑行收尾；提交后收指回握持位**。此方案取代本节此前「贴到 90°」的要求，避免固定手掌时靠过大的指根轴向扭转延长接触。主动手手掌与其余手指保持握持，对侧手保留当前握姿及已有中层避让。一手中握、另一手上握或下握时，S、S′ 均由中握食指完成。顺手方向用指腹下按，反方向从中层侧面的贴纸用指甲向上顶。双中握默认按方向用指腹，在普通 S 或 S′ 上添加下划线可改用对侧食指甲。半转和宽层沿用各自手法。

`sliceIndexFollow.ts` 保存 0..45° 的作者空间关节姿态，左右镜像共用；`sliceIndexMotion.ts` 独立编排前置、提早释放和收指，限制指根与掌骨的扭转，保持指腹朝向发力贴纸。准备沿用 F 的先抬后卷时序；释放先抬离再逐渐退回起手上方，不能倒放 F 的 90° 释放轨迹。`flickLayer` 在准备、转动和收指期间区分中层与前层落点；已准备 S 后改做 F，先收回再重新就位。收指未完成时仍阻止下一步腕转；动作结束后恢复原有待机微动。

本地验证：`hands_s_contact.test.ts` 使用真实 MANO，覆盖两侧动作、对侧 home/up/down/half 握姿、准备时改做 F 和拖拽取消。转动每 0.5°（对侧非 home 为 2°）检查皮肤/指甲穿模；0..45° 检查同贴纸接触和指腹朝向，60° 后检查已释放发力贴纸。三角面相交每 5° 检查，并抽查准备和收指。指腹接触允许沿真实网格边滚动，补充边上采样，避免仅采顶点把贴面误判为悬空；原只读记录器未改变。理想块体穿入容差为 0.1U，指甲不能成为发力贴纸的接触面。关节回归限制根部屈曲、轴向旋转和掌骨偏移，以及动作速度变化；转完后直接进入 200ms 收指，不额外悬停。自然收指版本的扫描与回放证据保存在 `.local-data/s-natural-joints-20261117/`；此前贴到 90° 的证据仍保存在 `.local-data/s-index-u5-20261116/`，不能当作新路径的验证，也不代表整只手的连续碰撞已全量证明。

### 5.2 U 只读接触记录器（2026-11-16）

开发模式 `/sim` 挂载 `window.__simHandRecorder`，默认关闭。打开双手、等待 MANO 加载完成，然后在浏览器控制台执行（接触检查点覆盖不同握姿下的右食指单步 U）：

```js
window.__simHandRecorder.start();
// 用现有公式播放器播放换握记号和单步 U，等待收指结束。
window.__simHandRecorder.read(); // 返回独立数据快照，ready 表示手模型已就绪
window.__simHandRecorder.read().gripEvents; // 换握请求、左右手标签/阶段改变及生命周期事件
window.__simHandRecorder.read().stateFrames; // 独立于 U 动作的最近逐帧状态
window.__simHandRecorder.json(); // JSON 字符串；可在 DevTools 用 copy(...) 复制
window.__simHandRecorder.stop(); // 停止订阅；保留已有记录
window.__simHandRecorder.clear(); // 清空记录；不改变是否开启
```

状态记录覆盖所有已加载手模型的实际握姿，包括 `half` / `halfDown` 两种半转握；接触检查点覆盖**三阶、播放器准备的右食指单步 U**，包括左右手 home/up/down/half/halfDown 的 25 种组合。`↑↑U`、`↑↑ U`、`↓↓U`、`↓↓ U`、`↑｜↑U`、`↑|↓U`、`↑↑｜↑↑U` 都会在换握完成后的 U 记录四个检查点。拖拽、U′、U2、宽层、push/pin 注解不创建此接触实验。它读取现有换握和 `prepareTwist → tick → endGesture → 收指完成`，不改 fit、时间步、骨骼姿态或魔方状态，不补插值帧，也不暂停动画。生产模式不加载记录模块。

每条 `records[]` 保存 `startGrips` 和 `preparedGesture`：双中手为 hook；右上握单步 U 为旋转到上握基座的 topPush 食指路径（含 §4.7 的 R U 衔接），准备到位后记录 start；其余握姿仍为无 style 的既有食指扫动。记录范围扩大不代表所有握姿动画已标定。接触块面逐次从当前蒙皮和全部块体中测得，不预设起手必须位于 U 层或 B0；离面或穿模也照实保留。采样刷新 SkinnedMesh 的当前绑定逆矩阵，避免换握后使用上一显示帧的缓存而重复施加旋转。

- `stateFrames`：独立于 U 实验，滚动保存最近 1200 次帧/事件快照；`gripEvents` 保留最近 200 次标签/阶段变化、换握请求及生命周期事件，稳定状态不会每帧重复追加事件。各自有 `droppedStateFrames / droppedGripEvents` 淘汰计数。`clear()` 同时清空这些数据和 U 记录，`stop()` 保留数据并停止订阅。
- `gripRequest`：保存运行时收到的目标 `name` 与 `sides`，半转请求另存 `halfDirection`（up 对应 ↑↑、down 对应 ↓↓），复用播放器解析结果。`↑↑U`/裸串尾 `↑↑` → R half；`↑↑ U`/串尾 `↑↑ ` → L half；`↑｜↑`、`↑|↓`、`↑↑｜↑↑` 按右、左顺序分别记录请求。它保存解析后的请求，不是原公式文本的逐字备份。
- `hands.R/L.wristAngle` 保存带符号腕转弧度，`forearmRoll` 保存动作指定的附加滚转，`finalPose.wrist.forearmTwist` 记录限位后的旋前／旋后角度（度），`forearmQuaternion` 保存实际前臂骨朝向，`elbowPosition` 保存 rig 坐标中的虚拟肘目标，`wristBend` 保存腕臂偏折弧度；区分同落点的 ↑↑ / ↓↓，播放、跳步及异步加载都保留。
- `grips` 的 home/up/down/half/halfDown 是逻辑基座或目标，未归类方向为 null；**换握开始时标签已经变成目标，不代表已到位**。结合 `hands.R/L.phase` 中的 regripping → stable 与实际手根变换判断。`grip-request` / `grip-set` 在状态赋值后发出，手根变换到下一 `frame` 才反映新应用的姿态。U 接触实验中途换握会以 `grip-changed` 中断。
- `records[].frames`：U 动作内的左右手标签、握姿四元数、实际手根位置/旋转、动作阶段（stable/preparing/turning/returning/regripping）、拨指角与 decay。每次动作保留最多 600 帧，最多 20 次动作，溢出计数可查。
- `checkpoints.start / 45deg / 90deg / after-return`：起手、首次越过 45° 的实际帧、90° 提交、收指结束。`targetAngleDeg / cubeAngleDeg / handDriverAngleDeg` 分列目标角、实际块体角、当前手姿驱动角；45° 可有偏差，90° 提交时手可能仍是上一显示帧。被跳过的点列在 `missingCheckpoints`；切换动作、重置或关闭记录会中断并给出 `reason`。
- `measurement.nearest / contacts`：最近块面及所有满足诊断接触带的块面；`pieceInitial / homePiece / localFace / stickerId` 跟踪实体身份，`currentFace / currentSlot` 表示当前空间位置。斜转时没有六面槽位则记 null。还原态 U 后，原 UBR 的 B0 贴纸到了 R0；回到原 B0 空间位置处的是原 UBL 的 **L0** 贴纸，不能把空间位置或原角块名当成贴纸身份。
- `gapU` 为有符号面间隙，`edgeMarginU` 检查有限贴纸边界；单位为魔方局部 U（块间距 64 U）。接触带暂定 0–2.5 U。`state` 区分 contact/separated/penetrating/unavailable；接触与其他顶点穿入可同时存在，须同时看 `contacts` 和 `penetration`。
- `slip`：固定起手皮肤顶点相对同一实体块面的**净切向位移**，排除块体刚体转动；记录起手接触标志 `startedInContact`、当前参考面接触标志 `contactOnReference` 及锚点间隙。`anchorInContact / anchorEdgeMarginU` 单独检查同一个锚点，防止别的顶点接触造成误判。`contactAtBothCheckpoints` 仅表示起手与本检查点的锚点都满足接触带，不保证中间连续接触；起手悬空或当前离面时仍保留位移，但不能称为贴面摩擦滑移。它也不能仅凭两个检查点区分滑动、滚动或中间离面。

几何基准是当前渲染块体变换下的理想 64 U 方块与标称贴纸矩形，不含圆角、贴纸厚度或材质细节。接触用食指远节掌侧顶点代理，穿模用所有主要蒙皮权重归属食指的顶点对所有块体的最大侵入深度；**没有侵入顶点不等于三角面绝不相交**。只在四个检查点计算几何，不是全轨迹碰撞验收。`measurementMs` 和 `maxFrameGapMs` 用于查看观测开销和采样疏密。

入口：`uContactRecorder.ts`（生命周期、边界与导出）、`uContactGeometry.ts`（蒙皮采样、块面、间隙、位移）；测试 `tests/u_contact_recorder.test.ts` 和 `tests/hands_lifecycle.test.ts`。本地需现有 MANO 资产可加载，否则 `ready: false`，不会用假模型生成实测记录。

## 7. 指法编码 FTN(2026-07-09 定稿)

招式层与编舞层物理分离:招式保持标准 WCA token 原样,指法全部关进紧跟招式的 `[...]` 注解块。
一切可缺省,缺省即回落 §3 默认表 —— 裸 `U` ≡ `U[R2:Q>M]`。`↑↓·` 与 `p` 后缀(§2)原样保留为糖:`U'p` ≡ `U'[R2:@B>A .p]`。

### 7.1 语法(BNF)

```
solution ::= step (SP step)*                            ; SP = 空格,顶层唯一分隔
step     ::= gripmark* (gripmark | move ["p"] ["[" clauses "]"])
                                                        ; "[" 紧贴招式,禁空格;gripmark 不带块
gripmark ::= grip | grip ("｜" | "|") grip             ; 双手组合先右后左，各占一步
grip     ::= "↑↑" | "↓↓" | "↑" | "↓" | "·"              ; 单标记占一步；↑↑ / ↓↓ 无后随空白=右手，有空白=左手（含串尾）
move     ::= 标准 WCA token
clauses  ::= clause (";" clause)*                       ; 括号内空白不敏感;块内禁 "]"
clause   ::= finger ":" [phase] body [tech]
body     ::= path                                       ; 扫掠
           | "~" [evade]                                ; 离场/避让(无 evade = 原地抬离)
finger   ::= ("L"|"R") ("1".."5" | "h")                 ; 1拇 2食 3中 4无名 5小 h整手
phase    ::= "(" num "-" num ")"                        ; 归一化转动进度 ⊆ [0,1],缺省 (0-1)
path     ::= [tier] waypoint (">" [tier] waypoint)*     ; tier 可在途中就地改档
tier     ::= "@" | "~"                                  ; 贴块 | 自由;缺省 = 贴面(§4.0)
waypoint ::= sticker [orbit [ring]]
sticker  ::= "A".."X"                                   ; Speffz,恒大写
orbit    ::= "c"|"e"|"w"|"x"|"t"|"m"|"o"                ; 角 棱 wing x心 +心 midge 斜;恒小写,缺省 c
ring     ::= digit                                      ; ≥5 阶同类轨道环号,必须跟在 orbit 后
tech     ::= ".f" | ".p" | ".t" | ".w"                  ; 拨 推 越顶 weld;缺省按 §3;只挂 clause 尾
evade    ::= dir [num]
dir      ::= ("+"|"-")("x"|"y"|"z") | face "^"          ; 轴向 | 面外法线
face     ::= "U"|"D"|"L"|"R"|"F"|"B"
num      ::= digit+ ["." digit+] | "." digit+           ; 距离单位 U;省略 = 取标定常量(如 HOOK_EXIT)
```

消歧三则:
1. `[` 与招式之间禁空格 —— 顶层只按空白分步,括号自定界,永不与招式序列打架。
2. 贴纸恒大写、轨道恒小写:`M`(角,c 缺省)/ `Me`(棱)/ `Mw`(wing),Speffz 跨轨重名免分隔符即消。
3. `~` 双位不双义:后随 `+`/`-` 或 `X^` 形或直接结束 = 离场 body;后随贴纸起始的 waypoint = 自由档 tier。
同一手指可出现多个 clause = 多段相序(接力 / 早退场);同一招多 clause 以 `;` 并列 = 并发。

### 7.3 剥离(喂 cubing.js 前)

```js
import { stripGripMarks } from '@cuberoot/shared/alg-notation';
const CUBE_ONLY = s => stripGripMarks(
  s.replace(/\[[^\]]*\]/g, '')       // ① 剥注解块(先剥,U'p[…] 塌成 U'p)
)                                    // ② 剥换握，含双箭头、双手组合；换成空格，禁止粘连
  .replace(/(\S)p(?=\s|$)/g, '$1')   // ③ 剥 push 糖(WCA token 无 p 结尾,安全)
  .replace(/\s+/g, ' ').trim();
```

与 §2 `stripGripMarks` / `p` 剥取同层;invert / mirror / 反推打乱 / recon 手递前统一走它。
验证:例 9 → `U2 U' D' F2 U'`;例 8 → `U F U' B'`。

### 7.4 为什么这样设计

招式层零污染是硬约束:注解块自定界,一条正则剥净,永不与招式空格混排。注解是纯叠加 —— 缺省全回落 §3/§4 既有表,写多少细多少,裸招式永远合法。大小写分工(贴纸大写/轨道小写)加缺省 c,根治 Speffz 跨轨重名且不付后缀噪声。相序 phase + 同指多段是唯一时序原语:接力、早退场、并发避让、pin→release 全由它派生,不另设同步/接力算子,符号表最小。`↑↓·` 与 `p` 是糖不是特例,旧记号零迁移成本;写错的注解剥离后招式照播,永不因编舞层损坏魔方层。换握手别的空白规则(§2)是全系统**唯一**空白敏感点(用户权衡:双手同换几乎不存在,单手常见形连后缀字母都不付)——代价是格式化工具不得动记号周边空格,且手别错写不报错只错编舞;剥离对两种形等价,魔方层始终免疫。
