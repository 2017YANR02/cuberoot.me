# Timer Difficulty Progress

计时器「难度」能力的状态跟踪。它是本任务的唯一进度源；后续只更新这里，不另建平行清单。

## 目标与准入标准

让适合的魔方项目复用现有难度控件，按最优步数选择打乱难度，同时保证设置显示、实际生成和真题筛选使用同一口径。

一个项目只有同时满足以下条件才接入：

1. 仓库已有可在浏览器运行的精确状态距离或精确阶段距离。
2. 随机来源能在所选区间内生成状态，不用有限次数拒绝采样后回退到近似难度。
3. 真题来源只有在现有 WCA 数据能用同一度量复算时才开放。
4. 复用 `GenStepsConfig`、`step-metrics.ts`、`gen-by-steps.ts` 和既有设置字段，不再造项目专用选择器。

## 明确不接入的项目

以下不是遗漏。当前没有满足准入标准的浏览器端精确能力，强行显示难度会制造假精确结果。

| 项目 | 暂不接入的原因 | 以后何时可接入 |
|---|---|---|
| SQ-1 | 当前精确整解依赖大型原生表；浏览器现有工具只做记号计数，不是状态最优距离 | 有浏览器可承受的精确距离查询和按距离采样后 |
| 转面八面体、二阶五魔、热帝魔方 | 计时器只有打乱器，没有仓库内精确完整状态距离 | 各自精确求解器完成后 |
| 四阶金字塔 | 现有求解能力是有界搜索，不能把结果宣称为最优难度 | 完整精确距离可用后 |
| 四至七阶、盲拧、接力、五魔、魔表、魔板、镜面 | 没有适合计时器实时运行的精确整解距离；部分项目也不适合用单一整解步数表达难度 | 先定义可信指标，再有精确生成或筛选能力后 |
| OLL / PLL 等案例训练 | 已按案例训练，不属于随机状态最优步数难度 | 不并入本任务 |

## 复用链路

```text
ScrambleSourceBar
  → GenStepsConfig（唯一难度控件）
  → step-metrics.ts（项目、度量、范围、默认带的唯一数据源）
  → gen-by-steps.ts
      → 随机来源：复用各项目精确求解图按距离采样
      → WCA 来源：wca_pool 按同一度量过滤真实打乱
  → SoloView（统一打乱历史、预取和设置变更重置）
```

新增项目不得在页面内复制开关、下拉或滑杆，也不得另存一套难度范围。

## 二阶专项打乱（2026-08-21）

二阶随机来源复用站内 `public/scramble_module.js` 的 csTimer 打乱器，覆盖 csTimer 二阶菜单的完整集合：

| 类别 | 已接入类型 | 生成口径 |
|---|---|---|
| 完整状态 | WCA 11 步、最优 | 沿用既有 `Scramble222ModePicker` 与本站二阶生成链 |
| 随机转动 | 三面随机转 | csTimer `2223`，固定 25 步 |
| EG 系列 | EG、CLL、EG1、EG2 | csTimer 原有 case 权重与状态生成 |
| TCLL 系列 | TCLL+、TCLL-、TCLL | csTimer 原有 case 权重与状态生成 |
| 末槽 | LS | csTimer 原有 case 权重与状态生成 |
| 状态条件 | 无连色 | csTimer `222nb`，直接按无连色谓词采样状态 |

随机来源显示全部专项类型；WCA 真题显示可从最终状态精确判定的 EG、CLL、EG1、EG2、TCLL+、TCLL-、TCLL、LS、无连色。`三面随机转` 描述生成过程，无法从一条历史 WCA 打乱的最终状态反推，因此只在随机来源提供。同步种子仍固定使用完整状态。类型、完整状态口径、按步数范围分别保存，切换来源不会覆盖各来源偏好。专项类型本身已定义目标状态，所以启用时隐藏并旁路“按步数”，避免两个条件互相冒充或产生空集。

`/scramble/solver?event=222&dsrc=nobar` 的“固定两角块、固定底面、CN 底面、无连色、固定底层、CN 底层”是统计分布口径，不等同于六种独立打乱器。计时器原有“底面 / 底层”难度已经覆盖 CN 底面和 CN 底层；专项类型则复用 csTimer 确有定义的状态族，不把纯统计条件伪装成新打乱类型。

异步生成没有新建二阶 worker 或复制算法：`nonwca.ts` 的既有 csTimer 队列已提取为按 `key + length` 隔离的通用队列，非 WCA 项目与二阶专项共用同一桥接。

## 回归约束

- 新项目先在 `step-metrics.ts` 注册，UI 不写项目名单。
- 难度标签必须来自精确状态距离；不得用打乱文本长度冒充最优步数。
- 所选区间没有合法状态时显式失败；不得静默返回区间外或普通随机打乱。
- WCA 真题筛选不得退化成生成打乱。
- WCA 专项只接受能由最终状态精确判定的条件；生成过程型选项不得伪装成历史真题筛选。
- 新增求解器或精确表后，先更新上方“不接入”原因，再评估是否满足四条准入标准。
