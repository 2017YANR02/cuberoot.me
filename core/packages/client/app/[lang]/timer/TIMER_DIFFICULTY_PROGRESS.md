# Timer Difficulty Progress

计时器「难度」能力的状态跟踪。它是本任务的唯一进度源；后续只更新这里，不另建平行清单。

## 目标与准入标准

让适合的魔方项目复用现有难度控件，按最优步数选择打乱难度，同时保证设置显示、实际生成和真题筛选使用同一口径。

一个项目只有同时满足以下条件才接入：

1. 仓库已有可在浏览器运行的精确状态距离或精确阶段距离。
2. 随机来源能在所选区间内生成状态，不用有限次数拒绝采样后回退到近似难度。
3. 真题来源只有在现有 WCA 数据能用同一度量复算时才开放。
4. 复用 `GenStepsConfig`、`step-metrics.ts`、`gen-by-steps.ts` 和既有设置字段，不再造项目专用选择器。

## 明确不接入的项目

以下不是遗漏。当前没有满足准入标准的浏览器端精确能力，强行显示难度会制造假精确结果。

| 项目 | 暂不接入的原因 | 以后何时可接入 |
|---|---|---|
| SQ-1 | 当前精确整解依赖大型原生表；浏览器现有工具只做记号计数，不是状态最优距离 | 有浏览器可承受的精确距离查询和按距离采样后 |
| 转面八面体、二阶五魔、热帝魔方 | 计时器只有打乱器，没有仓库内精确完整状态距离 | 各自精确求解器完成后 |
| 四阶金字塔 | 现有求解能力是有界搜索，不能把结果宣称为最优难度 | 完整精确距离可用后 |
| 四至七阶、盲拧、接力、五魔、魔表、魔板、镜面 | 没有适合计时器实时运行的精确整解距离；部分项目也不适合用单一整解步数表达难度 | 先定义可信指标，再有精确生成或筛选能力后 |
| OLL / PLL 等案例训练 | 已按案例训练，不属于随机状态最优步数难度 | 不并入本任务 |

## 复用链路

```text
ScrambleSourceBar
  → GenStepsConfig（唯一难度控件）
  → step-metrics.ts（项目、度量、范围、默认带的唯一数据源）
  → gen-by-steps.ts
      → 随机来源：复用各项目精确求解图按距离采样
      → WCA 来源：wca_pool 按同一度量过滤真实打乱
  → SoloView（统一打乱历史、预取和设置变更重置）
```

新增项目不得在页面内复制开关、下拉或滑杆，也不得另存一套难度范围。

## 本轮改动

- `step-metrics.ts`：登记斜转、枫叶魔方、齿轮魔方的度量、完整范围和默认带。
- `gen-by-steps.ts`：把三个项目接入统一生成与复算分发。
- `skewb-solver.ts`：复用 3,149,280 状态完整图，按允许距离集合的精确序号均匀抽样。
- `ivy-solver.ts`：复用 29,160 状态完整 BFS 图按距离抽样。
- `gear-solver.ts`：复用 41,472 状态完整 BFS 图按距离抽样。
- `wca_pool.ts`：斜转真题接入同一 HTM 筛选，并兼容现有斜转统计 JSON 的根级 `bins` 结构。
- `SoloView.tsx`：精确按步数生成优先于非 WCA Worker，避免枫叶和齿轮绕过难度设置。
- 未新增难度 UI；中英文度量名沿用现有 `魔方 / Cube` 数据契约。

## 回归约束

- 新项目先在 `step-metrics.ts` 注册，UI 不写项目名单。
- 难度标签必须来自精确状态距离；不得用打乱文本长度冒充最优步数。
- 所选区间没有合法状态时显式失败；不得静默返回区间外或普通随机打乱。
- WCA 真题筛选不得退化成生成打乱。
- 新增求解器或精确表后，先更新上方“不接入”原因，再评估是否满足四条准入标准。
