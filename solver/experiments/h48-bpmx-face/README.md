# H48 同面子分支剪枝实验

本候选在独立的单层 BPMX 补丁上增加同面剪枝，不改原版源码、H10 文件或现用入口，不增加剪枝表。开关与 `h48-bpmx` 保持一致：`cuberoot_h48_bpmx_enable(false)` 为关闭，`true` 同时开启父剪枝与同面剪枝。

## 数学证明

设当前父状态为 `x`，当前孩子剩余预算为 `t`。同一面的三个孩子 `xU`、`xU2`、`xU'` 两两只差一步合法 HTM 转动，所以任意两个孩子 `y,z` 满足 `d(z) >= d(y)-1`。

因此，只要本次真实查询取得一个可采纳下界 `L(y) >= t+2`，就有 `d(z) >= t+1 > t`：该面的三个孩子均不能在预算内复原。对于逆状态/左乘孩子，群字长同样满足相应三角不等式，所以正向和逆向 pipeline 均适用。它不依赖下界一致性。

全父 BPMX 仍优先：当 `L(y)>t+2`，先证明父节点本身不可解并返回；仅剩等号场景才需要同面剪枝。不能把同面阈值放宽到 `t+1`：父状态 `U` 的孩子 `UU=U2` 距离为 1，而同面的 `UU'` 已复原。

## 实现和计数

- 仅在 Stage 1–3 四处新鲜 `get_h48_cdata` / `h48_prune_lookup` 返回后使用证据，紧随原有父 BPMX 判断。
- 只将对应三个 `prune[m].stop` 置 1；不改 `pn/pi`、半转继承值、`lb_normal/lb_inverse`、动作掩码或 NISS 方向选择。
- `stats[6]` 是通过本规则排除的同面组次数，包括该组部分候选本来已停止的情况，不能解释为新增节省节点数。
- `stats[7]` / `stats[8]` 继续保留单层 BPMX 的父剪枝次数/尚待过滤的其他孩子数语义；`stats[0..2]` 不变。
- 开关在每次 solve 开始时快照到线程参数，不在 worker 中读取全局可变开关。

低内存 `engine.test.c` 不调用求解器或生成表。它复用约 1.1 MB 人工 cocsep 数据，覆盖阈值、溢出边界、关闭路径、正逆 pipeline、父剪枝优先级、整面作用域，以及 18 个动作形成的同面一步邻接关系和最多两步的真实魔方反例。

一手参考：[vcube 的 nxsolve.h](https://raw.githubusercontent.com/Voltara/vcube/master/src/nxsolve.h) 在子返回界达到同面阈值时清除同面动作，超过阈值时做 BPMX 父回传。本候选把这一数学规则接到当前 H48 的邻居流水线，收益必须另行实测，不照搬其他程序的倍数。

## 路线 C 的进一步边界

目前没有找到一项已证明能在现有约 30 GB 内存下让任意单个三阶最优求解获得数量级加速的替换算法。标准两阶段不能替代全局最优证明；[Kociemba 本人说明](https://www.kociemba.org/twophase.htm)其常用实现会漏掉进入第二阶段后又退出的最优路径。[Cube20 的整陪集批量算法](https://www.cube20.org/)确有极高摊销吞吐，但面向同一陪集的密集整批，不能把数字套到独立随机状态。

与商空间下界和搜索去重互补的后续小实验是完整状态终盘边界表：对复原态反向 BFS 到半径 3/4，在剩余预算进入该半径时用精确整状态查表完成或否定整个后缀。深度至 4 的完整球只有 46,741 个状态（逐层 `1,18,243,3240,43239`，来源同 Cube20），可以先限制为几 MB；必须保存完整键以消除哈希碰撞，并正确拼接 NISS 两端动作。先量出剩余 2–4 步子树占总搜索时间的比例，若该比例很低就直接否决，不扩大表。该方案保证正确时改变的是终止搜索方式，但目前没有 H48 提速证据。
