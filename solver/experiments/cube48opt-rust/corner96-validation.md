### 补充：表大小 × 节点数

根据 CS 的提醒，先用空间与搜索量的乘积评估算法折衷，再单独看查询实现与实际耗时。
本轮是 Opt8 主表叠加辅助表，计算空间时必须包含 7,782,727,680 字节主表。
下表使用各方案所需的剪枝值与索引数组，忽略共同的小坐标表、对象及少量元数据；
这是逻辑所需表空间的估算，不是本次同时驻留全部辅助表的进程 RSS。

| 方案 | 主表外的数组字节数 | 表大小 × 节点数（基准 = 1，越小越好） |
| --- | ---: | ---: |
| 原 Opt8 | 0 | 1.0000 |
| 角陪集 `u` | 918,540 | 0.9993 |
| 完整角距离 `distance` | 4,188,454 | 1.0192 |
| 组合 `combined` | 5,109,042 | 1.0173 |

`u` 的乘积下降约 0.074%，当前叠加接法整体近乎持平。节点数也会受搜索顺序、

首轮未比较相同完整角信息的 48 与 96 对称存储；这一缺项和查询调度的后续验证

### 为什么局部提升大、相对原 Opt8 的提升小

先区分比较基准：查询微基准的 2.31 倍比较原/新角辅助表实现；6.27% 比较新辅助表
方案和原 Opt8，而原 Opt8 没有这项额外查询。比较同一辅助表方案的优化前后，完整
求解记录为 137.471 → 83.597 秒，用时减少 **39.19%**。不能把两个不同基准的比例
直接相减或套用同一个耗时占比。

另做一次诊断：固定上一轮前 20 条、1 线程、8 contexts，无额外预热，复用现有
`opt10-native-profile` 计数机制；增加独立距离尝试、实际查询和拒绝的按深度计数。
同时修复诊断分类缺项：独立距离拒绝要计入单独类别，早拒绝/晚拒绝均满足节点分类
守恒。此修改不改变剪枝条件。每条诊断结果的节点、主表查询、步数和解均与冻结的
未插桩版本完全相同，20 个解另外经 cubing.js 回放通过。

| 观测项 | 前 20 条诊断结果 |
| --- | ---: |
| 访问节点 | 198,058,758 |
| 原 Opt8 主表查询 | 253,174,387 |
| 剩余 10–12 步的节点占比 | 95.35% |
| 剩余至少 11 步的节点占比 | 48.11% |
| 实际角辅助表查询 | 3,365,282（相当于节点数的 1.70%） |
| 角辅助表额外拒绝 | 112,117（占角表查询的 3.33%） |
| 剩余 10 步：主表已拒绝的比例 | 97.09% |
| 剩余 10 步：角表查询 / 额外拒绝 | 2,752,961 / 2,913（0.1058%） |

完整角表最大距离为 11，剩余预算至少 11 时无法提供拒绝，代码会直接跳过查表。
剩余 10 步时，主表先排除大部分状态；角表对幸存状态的新拒绝也很少。这解释了
辅助查询可以大幅优化、额外剪枝却仍然有限。这里的查询次数与节点比例不是 CPU
耗时占比，也不能直接换算为某项优化的整体提速上限。

按深度每 256 次调用抽样一次的计时，估算此诊断内实际角查询 hook 合计约 0.376 秒；
插桩搜索共 10.888 秒。样本包含计时开销，插桩会改变代码布局及访问成本，因而只
用于判断量级，不将其 3.45% 比例当成未插桩版本的准确 CPU 占比或性能成绩。
之前完整 WCA100 中，新增角表让主表查询总数仅减少 0.0299%，节点减少 0.0458%；
因此那次 6.27% 用时差还不能全部解释为剪枝收益，编译布局与运行波动尚未分离。

下一阶段优先研究剩余 10–12 步的主表坐标/访存，以及能在该区域补充更多剪枝的
角棱联合投影。继续压缩返回相同角距离的小表，无法减少大部分主表工作。
当前结果不构成 96 对称取逆约简无效的证据，也没有验证全局联合投影粗化的效果。

证据保存在 `.tmp/cubeopt-reverse/corner96/opt8-profile-v1/`，由
`corner-benchmark.mts report-profile` 核对冻结输入/程序、原始结果及保护记录。
求解 PID `16798`、guard PID `16790` 全程常驻，峰值进程树 RSS 7,910,080,512 字节，
最低保守余量 22,179,987,456 字节，同一 boot、Swapouts 0、压力级别 1，正常退出。
此次诊断不重新排名、不覆盖或重跑之前的速度成绩；仍然仅本地。

### 2026-10-22：角块与一枚棱的联合投影

维护者回复“试试”后，实际生成并验证了一个新联合 PDB，随后做了一轮真实搜索
诊断。结论：**补充了剩余 9–10 步的剪枝，但未证明能改善 11–12 步的主要工作；
暂不接入正式版本，也不把诊断耗时当成提速成绩。**

投影保留所有角块的相对状态及棱 0 的位置/翻转，用一个正向空间旋转将角 0
固定在位置 0、朝向 0。状态数为 `7! × 3^6 × 24 = 88,179,840`，文件
`corner-edge.dat` 为 **88,179,864 字节**（24 字节头加逐状态 u8 距离）。
这是角与棱的同一张距离表，不是两项距离相加。它商掉了自由整体旋转，因此也不能
声称每个状态都强于原固定朝向的全角表。

正确性依据：右乘空间旋转通过共轭重命名 18 个 HTM 转动；规范化前后的完整后继
集合一致，每个实际转动仍映射为一条单位代价的抽象边。忘掉另外 11 枚棱仍是图
投影，故抽象目标距离不超过整魔方距离。规范化后，角排列、角朝向、棱位置/翻转
的转移分别可预计算。全表 BFS 覆盖全部状态，并逐项验证：唯一零值、没有未知值、
全部 **1,587,237,120** 条有向边的距离差不超过 1、每个正距离状态有下降邻居。
同时核验 24 个实际全魔方旋转的封闭性、HTM 共轭、因子坐标以及随机可达状态。
不能用只对角块正确的 `R L'` 代替全魔方旋转。

最大距离为 **12**，各层数量为：
`[1, 12, 99, 787, 5913, 42682, 287985, 1780915, 9504996, 35542705, 39377725, 1635942, 78]`。
生成、全表证书校验和落盘共 7.263 秒，保留完整 BFS 断点
`corner-edge.chk`（440,899,232 字节）；中断的临时写入不会覆盖已完成断点。
生成经既有 guard，峰值进程树 RSS 552,992,768 字节，Swapouts 0、压力 1。
