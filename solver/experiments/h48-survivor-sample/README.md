# H48 真实存活节点采样库

本目录只提供库和独立补丁，没有 H10 启动程序。补丁应用于原 vendor 的另一个副本，不叠加角块或 BPMX 候选；原源码和已计时的候选不修改。实际运行必须接入现有受监控入口。

## 采样位置与界

两个 DFS 分支均在 `h48_prune_restore_normal/inverse` 之后、递归调用之前采样。记录的是已经通过当前 H10 pipeline 的子状态，`remaining` 是该子状态剩余的 HTM 步数预算；正逆下界也在方向恢复后读取，分别对应输出 `cube` 与其逆状态。合法的半转继承界保留原语义，不额外查表。

只观察预算 10、11、12。若 `remaining > base+3`，原 pipeline 整段跳过 H48 查表，该节点不能采样。已经复原、解数已满足、任一正逆界超过预算的节点也排除。观察器只给 `h48h10` 求解上下文挂载；没有附加剪枝，不改变搜索顺序或动作掩码。

使用 `writecube` 输出 23 字符标准 nissy 编码，整体朝向固定 `ORIENTATION_UF=0`，最后一字符为 `A`。编码包含全部角块和棱块信息，不使用投影坐标或 SIMD 内存作状态身份。

## 固定种子的 bottom-k

每个预算层保留最小的 k 个 `(priority,完整cube)`，k 为 1–64，默认建议 32。优先级是固定种子的 SipHash-2-4，哈希相同按完整状态字典序破平；重复访问已选状态不更新其来源和界。

输入序列化固定为 24 字节：第一个字节是预算值 10/11/12，后面是 cube 的 23 个 ASCII 字符，不包含字符串终止符。种子作为 SplitMix64 的初始状态，连续两次输出分别作为 SipHash 的 `k0/k1`；8 字节消息块按小端读取。测试核对 [SipHash 官方已知向量](https://github.com/veorq/SipHash/blob/master/vectors.h)。这是可复现的伪随机哈希优先级抽样，不声称固定哈希函数提供严格独立均匀随机性。

同层的抽样单位是本次跨例数据流出现过的不同完整状态。选中集合不受访问顺序或同状态重复次数影响；不同预算层可以保留同一完整状态。阈值只会下降，已经淘汰的状态不可能再次入选，所以只维护至多 k 个选中状态即可正确去重，不需要无界的已见状态集合，也不会因集合满而偏向搜索前缀。

`seen_total` 仅表示符合条件的访问次数，包含重复状态。全部不同状态数未知，输出 `unique_total:null`。样本的 `case_id/lb_normal/lb_inverse` 来自首次被保留的访问上下文，受遍历次序影响，不能解释成访问均匀样本或该状态出现过的最强下界。多线程的搜索访问流本身还会受调度影响；短实验使用单线程。

## 接口与 JSONL

`create(seed,capacity)` 创建跨例采样器；每次求解前 `set_case`，随后 `attach`，调用原 `nissy_solve`。所有求解结束后 `write_jsonl` 输出到调用方的 `FILE*`，最后 `attach(NULL)` 或 `free`。`clear` 清空样本和来源并重置种子；读取、设置来源、清空、挂载和释放只在所有求解结束后操作。采样回调内部对跨线程写入加锁。

JSONL 第一行是 `type=metadata`，包含 schema、十六进制 seed、容量、抽样单位、上下文含义，以及三个预算层的 `seen_total/retained/unique_total`。后续每行 `type=sample`，包含 `case_id/cube/remaining/lb_normal/lb_inverse/priority`；priority 以十六进制字符串输出，避免 JavaScript 整数精度损失。每层样本按优先级与完整状态排序。

`engine.test.c` 不加载 H10、不调用求解器。它检查官方哈希向量、改变访问次序与加入重复访问后的选中集合一致性、完整状态碰撞破平、预算和状态过滤、标准编码和 JSON 转义。真实采样仍需独立验证输出状态、预算覆盖及后续投影结果。
