# Mac 快捷指令入口

先从仓库的 `package.json`、脚本和 AGENTS 找到任务的正式命令、工作目录与副作用。快捷指令只做本机启动层，不复制业务编排，也不把个人路径写进跨平台命令。现有快捷指令或启动文件先检查再修改。

需要实时查看长任务输出时，可让「运行Shell脚本」用 `open -a Terminal` 打开一个轻量 `.command` 文件；该文件再进入正确目录调用正式命令。让仓库位置可由环境变量覆盖，并为可能重复点击的长任务加启动检查。短任务若不需要终端窗口，可直接在「运行Shell脚本」中调用正式命令，不必额外造文件。

用电脑 UI 操作快捷指令；「允许运行脚本」、系统隐私授权及密码提示按当前用户授权和交接要求处理。给 Dock、菜单栏或键盘入口时按用户选择设置，避免未经询问覆盖现有快捷键。不要把允许执行脚本误认为允许访问受保护文件夹。

先用无副作用的 `--plan`、小型探针或已有进程保护验证启动链路；核实快捷指令确实保存、目标终端/脚本确实启动，且未重复运行昂贵任务。只有用户要求实际执行时才启动完整任务。记录本机特有的路径和验证结果；另一台 Mac 应重新核对，不能假定个人 `.command` 文件已经存在。

本机已完成的「跑打乱统计」及 `~/Documents` 路径问题见 [实例记录](../../../docs/mac-stats-shortcut.md)。这是一台机器的观察，不是所有 Mac 的限制。仓库内发布、commit 和 push 仍遵循 AGENTS 的授权与工作流边界；创建快捷指令不自动授权发布。
