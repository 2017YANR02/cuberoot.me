## C. 三阶整解最优 HTM（`solver/333opt/`）

整个 3x3 魔方的最优解 HTM 步数分布，对应前端难度 tab 的「333」方法。运行前读 `solver/333opt/README.md`。离线统计与长度样例统一用原生 nissy-core **H48 h10**，旧 opt9 `solve.mjs`、`solve_loop.mjs`、`gen-table.mjs` 不再是入口。

在 `solver/` 运行 `cargo run --release --bin table_generator` 生成全部表；只补 H10 可加 `-- --only h48-h10`。生成器自动记录逐表时间与 RSS，H10 表大小必须是 30,336,314,216 字节。表目录可用 `CUBE_TABLE_DIR` 配置。不要单独调用上游建表工具。

本地一键建表并跑全部统计，在 `core/` 运行：

```sh
pnpm exec tsx ../solver/scripts/generate_and_build_stats.mts
```

已有表时可在 `core/` 运行：

```sh
pnpm stats:scramble:local --jobs 333opt
```

脚本自动用 `solver/333opt/solve_h10.mts` 按 id 续解，随后 `inject.mjs`、`inject_first_appearance.mjs` 和 `export_optimal.mjs`。语料从管道同源的 `wca_scrambles_no_wide_move.txt` 读取；数据位置由 `CUBEROOT_DATA_ROOT` / `CUBEROOT_WCA_DATA_DIR` 配置推导。求解结果 `out.0.csv` 每行 `id,htm,solution`，可断点续跑。本地入口只生成本地数据，不提交、推送、上传或灌生产库。

最优打乱为 `solution` 的逆序，同状态且 HTM 最短。`inject.mjs` 依据真实 WCA id 和比赛元数据注入 `distribution.json` / `examples.json` 的 `variants['333']`；`inject_first_appearance.mjs` 注入首次出现时间线。stages 构建会覆写这些 JSON，因此一键管道在 stages 后重注入。`export_optimal.mjs` 为 `/timer` 导出 333 / OH / feet / FMC 同态最优打乱。若修改 JSON 形态，还须更新前端类型与资源版本。

H10 首次全量求解的本机耗时应读取实际记录，不能采用旧 opt9 的速度估计。表和求解结果在本机，源码提交不会自动带上它们。
