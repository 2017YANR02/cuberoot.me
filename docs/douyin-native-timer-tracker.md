### 基准与范围

1. 产品基准是维护者实际使用的微信小程序计时器。先记录微信包/所加载页面版本、仓库提交、设备及内容视口、语言、主题、账号状态、项目、来源、设置和数据样本，再对照抖音；目前尚缺完整的微信同状态截图基线，AC-00未通过。不得用任意旧截图、App未完成迁移版本或仅凭印象代替。
2. 微信当前计时页面为WebView，实际产品源复用`SoloView` → `TimerSoloPage` / `TimerChrome` / `TimingSurface`及`timer-ui`。抖音继续使用原生TTML/TTSS/Canvas，外观和效果对齐，不引入H5主要功能页。React DOM组件不能直接运行不等于可以删功能：提取既有纯逻辑和布局参数，由原调用方与原生适配共同消费。
3. 唯一明确的产品内容排除项仍为维护者要求下线的教程、课程和专项训练。它们的入口和直达链接均应关闭；其他功能不得因实现成本而自行划出范围。
4. 当前`shared/douyin-content.ts`还限制多人、replay、reconstruct、hints等入口。这是待核对的现有实现差异，**不自动成为维护者批准的验收豁免**。AC-11须逐项区分基础工具与已排除教学/训练；有平台限制须记录平台原文及实际能力证据。未处理的基础功能仍算缺口，不能改成“不适用”来完成验收。
5. 仅允许已说明的宿主差异：平台导航栏/胶囊/底部安全区、系统授权及文件选择方式、确实不可用的硬件能力。它们也须记明微信行为、抖音差异、依据、替代方式及验收结论；业务区布局、功能结果和保存数据不因此豁免。
6. 本任务仅本地和开发预览；2026-10-20 维护者授权按功能颗粒度本地提交，取代此前“不提交”限制。不推送、不上传发布版本、不提审、不发布。写验收标准不等于授权恢复被下线内容或发布。

### 固定验收方法与证据要求

- 每个AC项使用固定记录：`微信基准/设置 → 抖音包标识与设备 → 操作步骤 → 期望 → 实际 → 截图/日志/数据证据 → 状态/剩余差异`。同一AC中还有未验子项时，不整行勾通过。
- 主界面对照至少覆盖：空闲未连接、观察/准备、运行、停表、有成绩、GAN已连接/未匹配/已匹配、设置、来源选择、成绩详情。使用相同主题、语言、项目、打乱和数据；不能通过换主题、隐藏元素或挑选不同状态掩盖差异。
- 设置使用共享注册表的稳定ID建立逐字段对照记录，并追踪真实微信consumer是否可达。旧审计中的66/67或项目43等数字是历史快照，不是当前完整性的证据；新增、退役、条件项和被排除训练项都须说明，不能仅凑数量。
- 业务数值必须精确核对；布局按同内容视口对照实际控件、字体、相对位置、尺寸和交互区域，平台系统栏单列。完成前保留成对截图并交由维护者确认视觉一致，不能只靠构建或静态源码断言。
- iOS与Android分列结果；GAN默认型号为GAN 16 UI，其他品牌的发现或连接不能代替它。真机用例需要实体转动/扫码/账号认证时才交接，已确认的型号和权限不反复问。
- 当前验证只确认iPhone已连接并收到能更新实况图的状态。不能反推30秒窗口一定是唯一根因；也未证明自动起停/保存、电量、Android或长期重连已通过。
- 修改前必须找到复用源；修改后完成适用的最小验证和必要构建。保留其他任务WIP，不为本验收重写共享实现，不以大量重复测试代替真机检查。
