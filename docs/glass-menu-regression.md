# 毛玻璃菜单回归检查

菜单自身的 `backdrop-filter: blur(...)` 不代表它能模糊后面的页面。父工具栏的 `backdrop-filter` 会建立 backdrop root，菜单伸到工具栏以外时，背景采样会被截断。父级 `filter`、透明度、mask 等也可能产生同类边界。另一个常见问题是后方图表建立 stacking context，反而盖住菜单。

比赛日历、列表、成绩汇总和选手分布的工具栏外层保持透明，不绘制额外底框；保留控件和菜单自身的玻璃及必要层级。确实需要玻璃底色的工具栏，将其画在独立 `::before` 层上，菜单与装饰层平行，参考 `components/site-surfaces.css` 的计时器工具栏。不能把全屏遮罩或菜单完全处于其内的对话框一概当成缺陷。

## 三层检查

### 公式与复盘内容区回归（2026-10-15）

`site-surface-policy.mts` 的 `scenery-content` 清单登记已清理的 11 类内容区：公式列表、复盘统计与备注、统计表外层、姓名统计单元，以及计时器复盘内层面板。场景材质开启时不允许重新加中性底色、外框、阴影或模糊层；普通主题回退和子控件/状态色保留。不要把这些纯内容区重新加入 `site-surfaces.css` 的面板材质组。

同一个扫描器接入既有写入 Hook 和 CI；CI 另检查这些内容区的透明适配仍存在，防止只删除修复规则。2026-10-15 已用真实 `apply_patch` 尝试恢复公式列表底色，Hook 拒绝写入，探针文件确认未创建；无需新增 Hook 注册。材质守卫 47 项检查通过。

规则只能锁定已登记的选择器，不能识别所有新命名、内联样式、祖先叠色或动态内容。新增/修改相关 UI 时检查真实截图：普通页面与弹窗内是否重复叠底，按钮、焦点、选中状态和表头是否仍清晰；新区域需先确认实际问题，再登记，不全局清空背景。按需视觉验收不能由 CSS 字符串检查代替。

### 日常成本与约束边界

- **只锁定已确认的问题**：`site-surface-policy.mts` 中的布局容器禁止恢复装饰底色、边框、阴影和伪元素底框；标题只禁止恢复分隔边线，不限制强调底色。普通卡片、输入框、弹窗、焦点轮廓及未登记的新容器不受这项底框规则约束。
- **复用现有自动检查**：Hook 只比较当前写入的新增违规；CI 在已有材质扫描中顺带检查，选择器匹配预编译，不增加一次全仓遍历、独立 job、依赖安装或网络请求。
- **浏览器巡检按需运行**：仅在排查截图问题、修改相关布局或主动审查时运行，优先指定受影响页面；不接入日常开发、每次提交或默认 CI。候选不能自动成为禁用规则，不要求为无关改动清空候选报告。
- **允许有理由的调整**：设计确实变化时可更新已登记规则，或沿用同一行 `allow-site-material: 具体理由` 的现有例外；无需为此新设审批流程。例外仍应符合全站材质和无障碍要求。

1. 现有 `hook-detect-site-material.mjs` 写入守卫重建修改后的 CSS，包括只改一条声明的补丁，拒绝已登记菜单容器重新加模糊。沿用既有 hook 注册，无需新增启动项。真实 `apply_patch` 已验证整块违规新增和单行回归均被拒绝，合法写入放行。
2. `tests/site-material-guard.test.ts` 在现有 CI 中遍历 client 的全部 app/components CSS，并验证分组选择器、前缀属性、伪元素及局部修改。静态规则认识 `.toolbar`、`.shell-topbar`、`.sor-race-bar` 和空间工具栏容器；它不是完整的 CSS/DOM 推理器，动态样式、新类名和表面属性仍需浏览器检查。
3. `scripts/audit-glass-menus.mts` 实际打开外观、比赛国家/筛选菜单、成绩汇总国家菜单、选手分布搜索、空间项目菜单，遍历全部 8 个 fixture × 6 种环境：系统浅/深色、显式浅/深色、390px、图片底图。检查比赛工具栏及其伪元素没有额外底色、边框或滤镜，并检查菜单的计算样式、越过父级背景采样边界、遮挡和横向溢出；失败返回非零。该浏览器检查按需运行，不依赖 CI 启动完整网站或线上数据。

## 快速定位多余底框

在 `core/` 运行 `pnpm --filter @cuberoot/client audit:surfaces`。它顺序访问主要公开入口和已登记页面，以图片底图检查实际渲染的导航、工具栏、分类标题及其 `::before/::after`，生成系统临时目录 `cuberoot-surface-audit/index.html` 和 `report.json`。截图用轮廓标出候选位置，每页最多截图前 8 类，其余候选仍列在报告中；同一类重复项合并计数。候选不是确定错误，不自动删除。

- 指定页面：`pnpm --filter @cuberoot/client audit:surfaces /zh/wca '/zh/wca/comp?country=cn'`
- 浅色或窄屏：追加 `--theme=light` 或 `--width=390`，用 `--output=/绝对路径` 保留不同轮次。
- 扩大到源码内全部静态路由：追加 `--all-static`，可能触发较多开发编译；仍串行访问，不启动额外开发服务。

仅扫描匿名页面里已挂载、可见且符合布局特征的元素。动态路由、登录角色、折叠内容、新的类名和超出尺寸范围的容器可能漏报；已登记但未挂载、HTTP 错误和超时单独报告，不能算通过。吸顶头、分组导航等可能合理地需要背景，须看截图确认。确认应去除后，修正所属 CSS，并在 `scripts/site-surface-policy.mts` 的同一清单登记选择器；不要靠全站清空所有背景或边框解决。

清单同时供 Hook、现有 CI CSS 守卫和浏览器巡检使用。Hook 拦新写入，CI 扫全部 client CSS，按需浏览器巡检补查继承、通用选择器和运行时渲染造成的覆盖。已实测真实 `apply_patch` 恢复比赛工具栏伪元素底色被拒绝，探针文件未创建；本次沿用现有 hook 注册。Hook 不能拦截任意终端写文件或所有内联样式，不能将这些检查宣称为全站视觉正确性的保证。

```bash
cd core
pnpm --filter @cuberoot/client exec vitest run tests/site-material-guard.test.ts
pnpm --filter @cuberoot/client exec node scripts/audit-glass-menus.mts
```

浏览器脚本默认复用 `http://127.0.0.1:3000` 和已安装 Chrome。可用 `AUDIT_BASE_URL`、`AUDIT_BROWSER_CHANNEL`、`AUDIT_OUTPUT_DIR` 指定预览环境、浏览器通道与输出位置；默认报告和截图位于系统临时目录的 `cuberoot-glass-audit`。脚本不启动、重启或构建服务。选手搜索使用真实公开数据，接口异常按失败记录，不能算通过。

## 本轮排查范围

除全量 CSS 守卫外，做了主要公开页面的菜单巡检（首页、比赛、成绩、复盘、模拟器、公式、打乱、工具、文档与设置等），再根据 JSX 中共享选择器的祖先定位隐藏面板。修复比赛工具栏、成绩汇总工具栏、选手分布工具栏、空间工具栏；手机分布搜索的固定宽度溢出一起修复。

广泛巡检不是所有 URL、登录角色和动态状态的穷举：初轮自动点击在计时器和世界最好成绩页遇到状态变化/元素失效，不能把自动点击次数当作全部验收证据。发布或新增菜单时仍需打开对应真实页面，补充 fixture，检查滚动后的吸顶与菜单，以及无场景背景、系统减少透明效果和浏览器不支持滤镜时的实底回退。不要用只检查 CSS 含有 `blur` 的断言代替视觉检查。
