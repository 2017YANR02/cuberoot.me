# 后台与增长监控跟踪表

状态：`COMPLETED`。最后更新：2026-09-02。

## 目标

补齐统一的 `/admin` 后台入口，并把 `/admin/users` 建成可核对、可筛选、适合日常观察的用户与会员增长页面。

本轮覆盖：

- 管理后台首页及现有管理工具入口。
- 注册用户总量、每日注册量、账号绑定情况和设备信息。
- 当前有效的个人会员、企业会员数量。
- 每日新增个人会员、企业会员数量。
- 7、30、90、365 天快捷范围和自定义日期范围。
- 桌面端、窄屏、浅色和深色主题下的可视化与交互。

本轮不覆盖：

- 新会员套餐、支付渠道或会员权限体系。
- 历史订单金额、收入和退款财务报表。
- 线上部署。本轮只完成本地实现、验证和提交，不 push。

## 统计口径

| 指标 | 定义 | 时间字段 | 备注 |
| --- | --- | --- | --- |
| 注册用户总数 | `app_users` 总数 | `created_at` | 不受日期范围影响 |
| 每日注册 | 当日创建的 `app_users` 数量 | `created_at` | 按 UTC 自然日分组，空日期补 0 |
| 当前个人会员 | 当前未过期且套餐非 `enterprise_` 的会员 | `expires_at` | 终身会员的 `expires_at` 为空，视为有效 |
| 当前企业会员 | 当前未过期且套餐以 `enterprise_` 开头的会员 | `expires_at` | 不把过期会员计入总数 |
| 每日新增个人会员 | 用户第一次获得个人会员的日期 | 优先 `membership_orders.paid_at` | 续费不重复计数 |
| 每日新增企业会员 | 用户第一次获得企业会员的日期 | 优先 `membership_orders.paid_at` | 从个人升级企业时，在企业序列计一次 |

历史人工会员可能没有已支付订单。此类记录以 `memberships.started_at` 作为兜底日期，但只有在同一用户、同一会员类型找不到已支付订单时才使用。退款、失败和待支付订单不计入新增会员。

## 日期与接口契约

- 默认显示最近 30 个 UTC 自然日，包含开始日和结束日。
- 快捷范围为 7、30、90、365 天；自定义范围使用全站 `DateRangeInput`。
- 页面 URL 使用 `from=yyyy-mm-dd&to=yyyy-mm-dd` 保存状态，刷新、前进后退和复制链接都能还原。
- 开始日期不得晚于结束日期；最长范围为 366 天；非法日期由入口直接拦截并给出双语原因。
- API 接收可选 `from`、`to` 参数；未提供时保持原有最近 30 天行为。
- API 返回完整日期序列，数据库没有记录的日期补 0，前端不自行推断缺失天。
- 时间范围只影响趋势数据，不影响用户总数和当前有效会员总数。

计划新增响应字段：

```ts
type AdminActivity = {
  from: string
  to: string
  timeZone: 'UTC'
  registrations: Array<{ date: string; count: number }>
  memberships: Array<{
    date: string
    personal: number
    enterprise: number
  }>
}

type MembershipSummary = {
  activePersonal: number
  activeEnterprise: number
}
```

原有 `daily` 字段先保留为注册趋势兼容字段，等现有调用全部迁移并验证后再决定是否删除，不在本轮制造破坏性接口变更。

## 页面设计

### `/admin`

后台首页是简洁的管理目录，不做通用 SaaS 卡片墙。页面按“账号与增长”“内容与社区”“运营与系统”分组，入口只链接到已经存在且管理员可使用的页面。每个入口显示名称、用途和当前最重要的一项状态；内部跳转使用真实链接，支持中键和新标签页。

### `/admin/users`

页面的信息层级如下：

1. 紧凑总览：注册用户、个人会员、企业会员、今日注册、资料完成度等核心数字。
2. 统一时间工具栏：快捷范围、自定义日期和 UTC 口径提示。
3. 注册趋势：每日柱形图，适合辨认离散新增和零值日期。
4. 会员趋势：个人与企业双序列柱形图，不把两类会员混成一个总数。
5. 用户明细：保留现有身份绑定、设备、注册时间和资料信息。

可视化采用“精密仪表”方向：数字使用等宽数字对齐，坐标和网格克制，颜色只承担数据分类和选中状态。图表是页面主要视觉记忆点，其余内容依靠留白和字号建立层级，不增加多余外框、渐变或阴影。

桌面结构：

```text
用户与增长
注册用户  今日注册  个人会员  企业会员  WCA 已绑定  资料完整

[7 天] [30 天] [90 天] [365 天] [开始日期 ~ 结束日期]

每日注册趋势
刻度 ─────────────────────────────────────
     ▂ ▅ ▃ ＿ ▇ ▂ ▆ ...                 悬停提示

每日会员新增       个人会员  企业会员
刻度 ─────────────────────────────────────
     ▅ ▂ ▇ ＿ ▃ ▆ ...                 悬停提示

用户明细
```

窄屏结构：

```text
用户与增长
核心数字两列或单列流动
快捷范围横向滚动
日期范围独占一行
图表可触摸横向查看，提示跟随触点
用户明细保持现有窄屏布局
```

## 交互与无障碍

- 鼠标悬停、键盘焦点和触摸滑动都能读取日期与精确数值。
- 图例可明确区分个人会员和企业会员，不只依赖颜色。
- 图表提供可访问的文字摘要；精确每日数据可由屏幕阅读器读取。
- 窄屏不压缩成无法触摸的细柱，允许横向滑动查看完整日期序列。
- 空范围显示 0 值基线和清晰说明，不伪造趋势。
- 加载、错误、无权限和空数据状态沿用站内双语反馈方式。
- 动画遵守 `prefers-reduced-motion`；数据更新不引发布局跳动。

## 边界情况

- 没有任何注册或会员新增时，日期序列仍完整返回且全部为 0。
- 日期跨月、跨年、闰日时按 ISO 日期连续补齐。
- 未来日期、无效日期、开始晚于结束、超过 366 天在接口和客户端两层拒绝。
- 会员续费不计作新增；个人转企业只在首次企业会员日期计入企业新增。
- 已过期会员不计入当前有效总数，但其首次加入日期仍可出现在历史趋势中。
- 同一用户同日重复订单只计一次首次加入。
- 没有 WCA ID 的普通账号仍计入注册数据；会员统计以现役会员记录为准。
- 时区固定为 UTC 并在界面标注，避免管理员本地时区导致日期错位。
