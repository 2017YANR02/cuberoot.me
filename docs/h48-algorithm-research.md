## 目标与边界

直接优化保证全局最短 HTM 的搜索与剪枝，衡量搜索节点数与实际耗时。线程池、编译参数及加大 H10 主表不是本轮算法方案。允许失败的候选；不能把减少节点自动等同于加速，也不能用仅能复原证明解最短。

用户随后要求从数学原理和底层进行优化，追求大幅提升，并明确要求多个 Agent 协作。完整角块下界降级为对照实验，不因小幅正收益而结束研究。后续路线分为：A 子群/商空间及表的信息损失，B 最优搜索与状态去重，C 其他最优求解器的一手算法对比。候选需要先写可采纳性/完整性依据，再实现可证伪实验；不承诺尚未测出的提升倍数。

研究中的一个具体方向是双向路径最大值传播（BPMX）：若一步相邻状态的可采纳下界为 `L`，当前状态的真实距离至少为 `L-1`；当前预算为 `r` 时，`L>r+1` 可剪去整个当前子树，而不仅是这一条子分支。需确认它与 H48 的正逆状态切换、半转缓存兼容，并实测现有启发式出现这种不一致的频率。理论参考：[Zahavi 等，Inconsistent Heuristics，AAAI 2007](https://tzin.bgu.ac.il/~felner/2007/incaaai.pdf)。论文中的旧求解器加速数字不是当前 H48 的预测。

2026-10-12 用户明确修改现有规则：H10 求解允许在持续运行时监控下启动，不再要求系统级防换出机制或本任务 hash 白名单。根 `AGENTS.md`、`solver/AGENTS.md` 与 `.codex/hooks/block-unprotected-memory-compute.mts` 同步执行。仍保留 Swapouts 增量、压力、RSS 和至少 2 GiB 保守余量的停止保护，不重设基线自动重启；这不是操作系统禁用 swap。H10/H11 大表重建未获授权。

## 实验 A：完整角块距离下界

H48 的 COCSEP 记录角块朝向与分组，没有记录完整角块排列。复用现有 `coord/corners.h` 的固定中心完整角块距离，共 `984 × 2187 = 2,152,008` 个对称约简坐标，最大距离 11。独立文件实测为 1,242,756 bytes（包含辅助坐标、表头与四位距离），不是另一张 30 GB 主表。

算法等价于联合下界 `max(H48 下界, 完整角块距离)`。实现位置在 H48 深搜已接受的节点上，若剩余步数小于 11，则查询完整角块距离；距离大于剩余步数才剪枝。距离等于预算必须保留。

最优性依据：任何复原整方的路径必定同时复原全部角块，因此完整角块最短距离不大于整方最短距离。前转/后转混合路径同样满足该必要条件。原 IDA* 深度递增与终止规则保持不变。

**重要实现边界**：角块下界不能写入 `lb_normal/lb_inverse` 或 `pn/pi`。原 H48 半转排除和反向下界缓存依赖特定子群性质，完整角块目标不具备这些性质。第一版仅独立剪枝，不改变动作掩码、NISS 或原表格式。

2. 用上游原生成器产生独立角块小表并校验表头、实际距离分布、辅助坐标范围和代表元；不改 H10。
3. 固定语料：复用 2026-10-04 的全部 60 个 15–19 步历史样本，并增加短解、半转及正逆路径样本。每个结果用独立 cubing.js 状态模型复原验证，历史样本还必须严格等于原最短步数。
4. 同机、同表、同编译参数，分别测原源码、候选关闭角块下界、候选启用角块下界；预热与正式轮分开，交错顺序，保存逐例耗时、节点、H48 查表、角块查表和新增剪枝数。
5. 先看正确性，再看节点与耗时。多线程找到首解的顺序可变；不能用一轮节点差异判定算法收益，补单线程对照隔离调度因素。没有实测不填提速比例。

## 实验 B：从相邻状态向父节点传播距离下界

令 `d(x)` 为整方状态 `x` 的真实最短 HTM 距离。对于任何面转 `m`，有 `d(x) ≥ d(xm)−1` 以及 `d(x) ≥ d(mx)−1`；同时 `d(x)=d(x⁻¹)`。因此，无论当前搜索选择正向还是逆向分支，某个实际一步邻居的可采纳下界 `L` 都给出父节点下界 `L−1`。

当前实现对每个子状态做流水线查表。若子状态预算为 `t`，它只在 `L>t` 时丢掉该子状态。新的候选在 `L>t+2` 时直接剪掉父节点：父节点预算为 `t+1`，但它至少需要 `L−1>t+1` 步。该结论只用可逆面转与可采纳性，不要求压缩后的 H10 启发式满足一致性。

实现保留独立开关及统计，只使用本次实际查出的下界，不把传播值塞回原 H48 的半转缓存或正逆动作掩码。无需新增大表。第一版是一层传播；进一步向祖先逐层减一传播也是合法方向，但需独立处理返回值和早停状态并实测收益。

对照与验解复用实验 A 的同一套程序、输入及资源监控，避免两套基准口径。新轮次按完整样本 ID 的字节奇偶交错先后顺序，连续轮次将同一样本的 A/B 顺序反转；旧日志继续按原顺序规则解释。

两个后续候选分别隔离验证：

- 递归传播：把已证实的下界继续向祖先逐层减一传播；未找到解、取消或停止本身都不能当作新的数学下界。
- 同面剪枝：`x·U`、`x·U2`、`x·U'` 两两只差一步。子预算为 `t` 时，只要任一子界 `L≥t+2`，该面的三个候选均不能在 `t` 步内完成。它比整父节点剪枝的严格 `L>t+2` 多利用了等号情形。灵感及交叉核对：[vcube nxsolve.h](https://github.com/Voltara/vcube/blob/master/src/nxsolve.h)。实现仍只改候选停止标记，保留 H48 特有缓存语义。

## 更大幅度改进的数学路线

完整推导和下一阶段探针设计见 [H48 数学路线](../solver/experiments/h48-mathematical-options.md)。三个 Agent 分别负责子群/信息损失、搜索及反向传播、其他最优引擎与交叉验证；所有路线均以全局最短 HTM 为目标。

- H10 的关键损失来自把两个 H11 坐标取 min：在 `≥13` 阈值处，有 48,628,415,077 对的两个值分处阈值两侧，占所有合并对约 40.39%。这不是稀疏残差；统计对象是表坐标，并非实际搜索节点。
- H11 四桶分布的零阶熵约 1.248 bit/entry，理想数据本身约 37.56 GB，尚无依据保证通用无损编码能塞入原 30 GB。更强相关压缩仍是开放方向，不把熵下界当实现结果。
- 优先研究联合投影：同时复原「全部 8 个角块 + 指定 1 个棱块」或「指定 8 个棱块」。它补充 H48 忽略的内部排列和动作相关性；联合条件的最短路可以严格强于独立下界取 max。前者按当前构造估算约 271 MB 主数据，尚未建表。先对真实搜索存活节点进行有限预算的按需精确抽象求解，证明经常能多剪一层，再投入亿级坐标生成。
- 不直接相加 H10 与角块距离：同一转动可能同时解决两者，直接求和会破坏最优性。新大表和按需探针的潜在提升均未实测。

## 本地入口

在仓库根运行（不进入 `core/`）：

```sh
node solver/experiments/h48-corners/run.mts --check --threads=18
node solver/experiments/h48-corners/run.mts --run --threads=18 --rounds=3
node solver/experiments/h48-corners/run.mts --run --threads=1 --rounds=2
node solver/experiments/h48-corners/run.mts --run --threads=1 --rounds=2 --variant=bpmx
```

`--check` 编译三份独立产物并运行低内存检查，不加载 H10。`--run` 在正常内存压力、至少 34 GiB 可回收内存且没有其他 H48 计算时开始；运行上限 32 GiB RSS，每 0.5 秒采样整个任务树，保留至少 2 GiB 保守余量。每阶段最长 10 分钟。每行结果即时落盘，保护触发会终止本任务子进程并保存原因，不自动重启。

源码补丁、原版、候选与低内存检查产物在 `solver/target/h48-corners/<源码摘要>-t<线程数>/`；结果在 `.tmp/h48-corners-research/run-*/`。资源基线单独持久化，重跑不能忽略旧的保护停止或接受新增换出。构建摘要包含全部 vendor 源码、实验文件和编译参数。正式分析器的表加载没有变化，所以 `/dev/solvers` 的现用 `TABLES` 快照不加入这张实验表。
