# Mac 断电与整机故障取证

维护者于 2026-10-11 要求记录突然关机前的系统状态。此工具独立于 Codex 聊天运行，不是定时 AI 跟进，不启动求解器，也不替代双底计算的交换保护。

## 查看

- 日常内存读数改由 Stats 菜单栏显示。用户要求移除重复功能后，已停止生成 `status.md`，旧文件移至废纸篓；底层故障采样保留。
- `~/Library/Logs/CubeRoot-SystemRecorder/latest-incident.md`：最近一次检测到新开机时生成的证据索引。
- `incidents/<时间>/`：上一会话末尾记录、诊断报告索引、可读取的系统和电源日志。仅根据资源异常不能自动认定关机原因。

可回收估算采用 `(Pages free + File-backed pages) × pageSize`；文件支持页不一定能立刻回收，脏页可能需要先写回磁盘。该估算不能保证某个内存规模的任务不会换出。各进程 RSS 可能包含共享页，不应简单相加当作总内存。

## 安装与停止

源实现：`core/scripts/mac-system-recorder.mts`，使用 Node 24 的原生 TypeScript 支持。安装时复用现有 LaunchAgent XML 工具，复制一份独立运行脚本至 `~/.local/share/cuberoot-system-recorder/recorder.mts`，不会因移动仓库而立即失效。

在仓库根运行：

```sh
node core/scripts/mac-system-recorder.mts --install
launchctl print "gui/$(id -u)/me.cuberoot.system-recorder"
```

停止并取消当前已加载实例：

```sh
launchctl bootout "gui/$(id -u)/me.cuberoot.system-recorder"
```

要永久停用，再将 `~/Library/LaunchAgents/me.cuberoot.system-recorder.plist` 移出 LaunchAgents（保留到备份或废纸篓）。再次安装可恢复。源文件修改后需要重新安装，已运行的副本不会自动更新。

这是用户级 LaunchAgent：**登录后自启**，登录前或退出登录后的区间没有此记录器覆盖。意外退出由 launchd 拉起。检测到不同 boot 时保存上次记录并尝试发出 macOS 通知，通知展示受系统权限与勿扰设置影响。

## 记录范围与限额

- 约每 10 秒：boot、vm_stat、内存压力、系统负载、内存前 15 / CPU 前 10 进程、采样延迟；保留 PID、父 PID、程序名，不收集命令行参数。
- 约每分钟：系统公开的热状态、磁盘余量和磁盘 I/O 累计统计。热状态没有告警不等于有全部硬件传感器温度记录；不取得电源插座电压。
- 实时：kernel、WindowServer、watchdogd、powerd、loginwindow 的错误或与关机、panic、热状态、阻塞相关事件；相同事件合并计数。每轮最多保留 128 种、每条最多 2048 字符，超出明确记录丢弃数。
- 每次写入请求 `fsync`，尽力跨断电保留。硬断电仍可能丢失最后一个采样周期或磁盘尚未持久化的尾部，不能承诺必然记录最后原因。
- 原始采样与系统事件最多保留 14 天，合计最多约 256 MiB；每种当天日志保留当前及一个前代文件，每个约 16 MiB。高事件量可能使覆盖时长短于 14 天。已提取的 incident 证据另行保留。
- Node 堆限制 96 MiB，自身 RSS 超过 192 MiB 退出；采样串行，不叠加超时命令。系统日志子进程也有额外内存和 CPU 开销，应从进程记录核查。
- 文件仅在本机用户私有日志目录，不上传。系统事件正文和诊断头可能含设备或进程信息，分享前应检查脱敏。
- 不控制操作系统 swap，不杀其他应用，不修改供电设置，不恢复计算任务。
