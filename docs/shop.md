# CubeRoot 商店

## 入口与维护

- 中文店铺：`/zh/shop`；英文店铺：`/shop`。首页右上角有「商店」入口。商品详情、购物车、结算与购物帮助统一在 `/shop` 下；旧 `/platform/shop` 及其子路径直接返回 404，不做跳转。
- 管理员通过 `/zh/platform/admin/products` 维护商品；`/zh/platform/admin/products/new` 添加商品。店铺里的「店铺管理」「添加商品」仅管理员可见。
- 首批只售卖 CubeRoot 周边，统一使用 `lifestyle` 分类；店铺列表固定查询此分类，新建商品默认归入此分类。前台不展示魔方、润滑油和配件入口，也不预设未确认的周边品类。
- 商品支持中英文名称和说明、主图、附图、规格、SKU、价格、会员价、库存、配送说明与上下架状态。编辑器里的金额按元输入，由现有金额转换工具转成最小货币单位。
- 价格未确认时保留商品草稿，或暂不添加规格。未配置价格的商品显示「价格待定」，不能加入购物车；新增规格的价格默认为空，不会自动变成免费商品。
- 已确认的魔方垫图案以带名称的款式卡片展示，完整保留 2:1 比例：新款「魔方游乐城」和原蓝色款「逐梦星图」。名称、简介、图片和 slug 的唯一前台来源为 `lib/shop-designs.ts`。SVG 存放在 `public/images/shop/`，文件名带内容 hash。保留原图的 SIM 魔方与 SQ1，去掉旧日期和署名。
- 款式详情使用既有 `/shop/:slug`。没有后台商品时显示只读预览、价格待定和待开售；不生成规格、价格、库存或收藏 ID。后台添加相同 slug 的真实商品后优先使用 API 数据，接入既有购物车与支付。列表会移除同一页中已由 API 返回的重复款式。API 只有明确的 404 才视为不存在，网络或服务器错误仍展示重试。
- 制作提示词、画面描述与设计状态归档在 [店铺图案档案](shop-artwork/README.md)，不进入顾客购买界面。
- 店铺结构参考 TheCubicle 首页和 Apparel & Lifestyle 列表（2026-11-04 实际浏览）：紧凑导航与顶部商品搜索、整幅海报、标题与排序、商品网格、明确的规格入口、分组服务页脚。搜索可从店铺详情、购物车等页面返回商品结果；保留系统主题。仅使用自己的品牌与图片，不复制对方商品、价格、评价或政策。
- 标题直接展示，不添加装饰性眉题、口号区或海报下方的虚构编号。首批只有周边，不展示无意义的多品类筛选；新图案经用户确认后再加入展示。

## 交易流程

商店复用现有平台商品、收藏、地址、报价、订单和支付能力。购物车只在浏览器保存商品 ID、规格 ID 和数量；商品价格与库存从 API 读取。结算必须由服务端重新报价，商品、地址或优惠码变化会使当前报价失效。订单提交仅携带规格和数量，不提交客户端计算的金额；同一次提交重试保留幂等键，创建成功后跳到已有订单支付页。

购物车在返回窗口时重读库存；待定价、售罄、库存不足、不可用商品或混合币种会阻止结算。订单创建成功只扣除本次购买数量，保留请求期间新加入的商品。

## 开售前仍需配置

目前已展示两款已确认图案，未写入真实商品、库存、价格、地址或订单，也未发布。本地展示款式不等于后台已开售。开售需要维护者提供价格、尺寸规格及可售库存，并明确配送范围、运费和售后政策。

现有后端订单运费目前固定为 0；本次未新增运费规则，不能将其视为已配置好的物流报价。需在开售前确认采用包邮，或另行接入运费规则。

2026-11-05 只读确认服务器已有支付宝、微信 Native/H5 与地址加密配置；未读取输出密钥内容。配置存在不等于商户权限、证书有效性或支付域名已验收。本轮未发起真实付款、退款或写入正式交易。正式开售仍需前后端发布、真实商品资料与价格、配送政策以及支付宝/微信各一次真实付款与退款验收。银行卡按维护者要求暂不接入。

## 支付实现（2026-11-05，本地）

- 结算按钮突出展示「提交订单并支付 + 金额」。订单页首部集中展示应付金额、支付宝/微信选项和全宽 58px 付款按钮；取消订单使用次要按钮。订单导航只保留购物、收货地址和联系入口。
- 支付方式由 API 按配置与币种返回；当前仅 CNY。电脑使用微信 Native 二维码或支付宝电脑支付，手机外部浏览器使用微信 H5 或支付宝手机支付。微信内置浏览器提示到外部浏览器付款，不创建无法唤起的 H5 支付。小程序仍只放行已有比赛报名原生支付，不开放周边支付。
- 活跃支付保存到订单接口，刷新后可恢复。重试复用原付款单号；H5 的短期链接通过同一付款单刷新，不另建一次付款。活跃支付期间不能另选渠道创建第二笔支付。
- 支付返回原语言的订单页；微信 H5 返回链接由服务端生成，订单页保留 origin Referer。微信的 [H5 接入要求](https://pay.wechatpay.cn/doc/v3/merchant/4012791845) 要求商户域名与发起/返回域名匹配，并限制微信内置浏览器，因此正式域名仍需真实验证。
- 页面每三秒读订单；API 对同一订单最多每十秒主动查单，使用支付商验签后的结果弥补漏掉的回调。回调与主动查单复用同一结算事务，校验商户、订单、金额、币种和交易号；前端跳转不能把订单标成已支付。
- 服务端保留幂等、库存预留与原子结算。实物商品支付后进入待发货；重复回调只扣一次库存。等待买家付款的非终态通知不会释放支付占位；已关闭订单的迟到付款记录到对账队列，不重新出售已释放的库存。
