## 实测方法与发布边界

- 使用当前本地源代码临时打包，SSH 标准输入送入 API 主机的独立进程；真实 Qwen、真实公开数据、真实账号认证及当前 WCA 绑定查询。没有替换线上服务，没有改服务器配置、运行生产迁移、提交或推送。
- 每题测到完整 JSON 答案返回，包含鉴权、模型各轮及工具读取。请求级资料缓存每题重新创建；模型提供商的缓存不受测试控制。旧诊断元数据中的 cold:true 仅指应用请求缓存，不表示模型/操作系统的冷启动。
- 基准测试为串行；每题创建独立速率窗口，避免测试本身因每账号每分钟 6 次而连续得到 429。正常生产的速率限制与并发上限保持不变，这不是并发吞吐测试。
- 大批量诊断使用单进程、单独记账的 800 问/北京时间日上限；生产仍保留原 100 问上限，二者合计小于用户授权的 1000 问。失败也记账。它没有替代生产原子额度表的验收；本地 PostgreSQL 并发验收见[性能目标文档](site-assistant-performance.md)。
- 全量运行后只对有新增修正的题目定向复测；原结果完整保留，最新统计按同一题最后一次结果计算，不能把它描述成另一轮未发生的完整运行。
- 所有统计问题实际命中的目录、模型轮次、答案、来源、表格、耗时和错误均保留在[最终原始结果](benchmarks/site-assistant-2026-09-28-final-100.json)。结构检查发现项：无（来源、对象单元格、表头/行宽检查通过）。

## 修正与保留的缺口

- 姓名解析改读已有 WCA 人员数据库，复用规范化匹配；不再为中文姓名额外等待 WCA 官网。
- 复盘使用真实驼峰字段，区分 WCA 人员 ID 与比赛 ID；查询数量与项目在服务端校验。OLL/PLL 只显示原始标注与解法，不让模型把其他方法强行改称 OLL/PLL。
- 统计目录在首轮提供，减少额外模型轮次；与页面目录分离，避免误传 wca-stats。完整遍历 sourcePanels 等结构，读取 37 MB 的滚动平均文件时使用固定来源的 64 MB 上限。
- 用户先问筛选条件时，直接展示已有非空分表的真实组合；澄清与实际排行榜分开计数。20 道明确条件的补充题另行验证真实取数。最终统计列表说明由已读取的表格与原文口径生成，避免模型把 1 席说成前三席、把历史统计中的仍有效纪录说成已被打破；解释和分析问题仍可使用模型归纳。
- 针对真实观察到的顶层调用数组，在严格工具校验后兼容；重复读取有明确收尾，瞬时模型故障最多恢复一次，共用原来的总期限和额度。
- **S40、S41**：已发布文件为空，无法给出前五名；不声称无人达成。这是统计生成/导入缺口，未在本轮生成或发布数据。
- **S45**：现有目录提供“年均比赛数”，不能冒充各国每个日历年的逐年序列。
- **S47**：现有目录提供“个人在一场比赛的纪录数”，不能冒充全场所有选手的纪录总数。原问题仍需要对应聚合数据。
- 表格来自真实工具输出；模型正文仍需持续回归，不能将一次测试宣传为任意问题都准确或全面领先竞品。
