# 智能魔方视频采集与 AI 读取

在 CubeRoot 保存一把智能魔方成绩后，管理员打开对应复盘，选择「添加视频」，即可把原视频、打乱、未经化简的动作及已有陀螺仪记录绑定为一个采集样本。第一版面向带原始动作的标准三阶记录，不依赖 CFOP 化简结果。

视频使用已有 Drive 的私有存储、8 MiB 分块校验及断点上传；不会经过公开复盘视频上传入口，也不会自动压缩。原始记录按样本 ID 固定，人工同步锚点另行保存。每个视频最多 1 GiB，仍受 Drive 的存储额度和上传有效期约束。

## 拍摄者操作

当前首批按用户选择采用**第一人称视角、手机原生 1080p60**，保留未剪辑、未变速的原片。
该批次与第三人称及项目原定的 1080p50 验收素材分组记录，不将其结果直接视为其它机位或帧率的质量证据。

1. 连接 GAN 16 UI，用 CubeRoot 记录动作，同时用手机正常拍摄。
2. 打开这把成绩的复盘，在顶部「用这条打乱」旁点击「添加视频」，选择手机原片。该入口仅向已登录的管理员显示，且成绩须为带原始动作的标准三阶；未登录和普通用户不显示。
3. 等待上传完成。断网或停止上传后，重新选择同一原片继续；文件的完整分块指纹必须一致。
4. 可选：在视频中补充动作完成位置的同步锚点。没有锚点时仍已保存，保留「待对齐」状态，不会把视频起点或日志时间直接当成动作完成时刻。

重新选择原片仅用于恢复浏览器对文件的读取权限；系统沿用既有上传进度，按完整分块指纹判断是否是同一份文件。复制或重命名不改变原片字节时可以继续，剪辑或转码后的文件不能混入原上传。手机录像与动作收集尚未合并成一个录制入口，也没有后台持续读取手机相册。

选错原片或原上传已过期时，可点「新建采集」为这把成绩重新绑定视频；旧样本和 Drive 文件保留。上传完成后移除浏览器内的大份临时记录，重新打开时读取服务器样本。保存的动作时间沿用计时器已有的相对时间，本轮没有新增设备原始时钟与接收时钟的双轨采集。

## 在 dev.cuberoot.me 本地使用

已有前端开发服务继续运行。在 `core/` 启动采集服务：

```sh
pnpm recon:capture:dev
```

入口使用本机已安装的 PostgreSQL，默认通过 `pg_config --bindir` 定位。必要时以 `RECON_CAPTURE_PG_BIN` 指定其 bin 目录；不会自动安装软件、启动另一个 Next 或修改个人 `devsite` 配置。

首次启动会创建独立 PostgreSQL 集群，绑定 `127.0.0.1:5433`，只供 `recon_intake_local` 使用，并启动 `127.0.0.1:3011` 的本地采集 API。helper 自动准备最小本地表结构；线上仅用于只读核验管理员身份，不复制生产业务数据。数据库的共享缓冲区为 32 MiB，最大连接数为 20。

本机持久数据位于已 gitignore 的 `core/.local-data/recon-capture/`：

- `postgres/` 保存独立数据库；`postgres-owner.json` 记录其归属和配置指纹。
- `drive/` 保存原视频及未完成上传。
- `runtime.json` 保存本入口启动的 API 和 PostgreSQL PID；`postgres.log` 保存数据库日志。

本地管理员 key 和数据库密码随机生成到 gitignored 的 `core/.env.recon-intake.local`，文件权限为 0600，启动输出不显示密钥。该配置的 `RECON_CAPTURE_MANAGED_POSTGRES=1` 仅标识本入口管理的集群；没有归属记录的已有数据库目录不会被接管。

启动就绪后，在现有 `https://dev.cuberoot.me` 计时器的成绩复盘中使用「添加视频」。前端需包含本轮本地代理改动，使采集和 Drive 上传同时连接本地 API；不能把线上 Drive node ID 绑定到本地样本。

按 Ctrl-C 只停止本入口启动的 API，PostgreSQL 保持运行供下次复用。再次启动会核对目录、配置、进程和端口归属；未知服务占用 3011 或 5433 时停止启动，不关闭他人的服务。数据库和视频属于真实采集资料，保存在持久目录，手动清理前需自行备份。

已有 `.env.recon-intake.local` 且没有 managed 标记时，入口只使用其中明确配置的本地 PostgreSQL，不初始化或重启该服务。主机必须为 loopback，数据库名必须为 `recon_intake_local`，API 地址也必须指向配置中的本地端口。

## AI 只读命令

命令均从 `core/` 执行。`RECON_CAPTURE_API_URL` 和 `ADMIN_API_KEY` 优先读取进程环境，其次读取已 gitignore 的 `core/.env.recon-intake.local`。未设置地址时默认 `http://127.0.0.1:3011`，不会根据其他命令或网页地址切到生产。

```sh
pnpm recon:capture list
pnpm recon:capture list --status needs-review
pnpm recon:capture show CASE_UUID
pnpm recon:capture pull CASE_UUID --out ../research/reconer/artifacts/captures/CASE_UUID
```

需要读取线上样本时，显式将 `RECON_CAPTURE_API_URL` 设为 `https://api.cuberoot.me`，通过现有授权环境提供管理员 API key。密钥不写进文档、命令历史或生成文件。远端地址必须使用 HTTPS；请求拒绝重定向，避免把密钥转交给其它站点。

`list` 有界分页并输出摘要，`show` 输出样本详情。`pull` 仅接受上传完成且原片仍可访问的样本，下载过程中不解码视频，也不修改服务器记录。

下载目录包含：

| 文件 | 内容 |
| --- | --- |
| `sample.json` | 服务器样本快照，包含版本、原片元数据、原始记录和同步信息 |
| `raw-recording.json` | 未经化简的智能魔方记录，显式标为未审核标签 |
| `sync.json` | 未对齐状态，或人工锚点及拟合结果；`qualityVerified` 保持 false |
| `video.mp4`、`video.mov` 或 `video.webm` | 按服务器确认的媒体类型命名的原片；不会用远端文件名构造本地路径 |
| `download.json` | 样本 ID、版本、内容指纹、原片 SHA-256 和完成状态 |
| `video.*.part` | 下载中断时保留的字节；完成并核对 SHA-256 后才发布正式文件 |

网络中断后，重新运行相同 `pull` 命令和 `--out` 即可续传。脚本核对样本版本、动作指纹、视频指纹、强 ETag、Content-Range 与字节数。服务器同步信息更新后，使用新的目录保存新版快照，不覆盖旧研究输入。完整文件不匹配时停止并保留现场。

同一目录不能并行下载。正常退出会移除 `.download.lock`；异常终止留下锁时，先确认没有拉取进程在运行，再手动移除该锁。目录中存在无关文件、符号链接或不匹配的元数据时，脚本拒绝写入。

## 确认和使用边界

采集完成只进入 `needs-review`。智能魔方日志可以辅助动作顺序标注，但不自动提供像素掩码、可见性或准确视频时间；人工同步锚点的拟合也不等于真值已经通过审核。下载不会生成正式 GT、修改 [既有收录队列](recon-intake-workflow.md) 的预期、启动推理或训练。

训练分组、人工像素审核与独立评分沿用 [Reconer 实施方案](../research/reconer/implementation-paths.md)。同一原片的裁剪、转码和相邻帧仍属于同一录制组。原始输入、人工修订和模型输出分别保存。
