## 官方依据与结论边界

[运营规范重点解读](https://partner.open-douyin.com/docs/resource/zh-CN/mini-app/operation/management/specification/mini-app-operation-interpretation)要求全部或核心页面原生，并要求提交功能可完整使用。[WebView 开发说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/tutorial/basic-ability/web-view-component)仍支持配置业务域名的网页容器。该能力不适用于个人主体；本项目抖音端按个人主体全部原生化。原生页面覆盖不能证明所有审核条件合格。

本次没有通过审核状态判断或账号白名单改变审核人员看到的功能。维护者已确认将抖音端联系功能永久改为平台反馈，网站和微信保留社群目录。当前登记页面均已使用原生视图，但不能据此保证过审或宣称已与网站功能完全对齐。

## 本机提审阻塞复核（2026-10-20）

维护者已明确按个人主体推进：最终目标是所有可达功能页均无 WebView，而非仅核心页面原生。旧网页入口已替换为原生路由分发，未知页面或参数明确报错。

- 维护者提供正式 AppID，本机被忽略的 `project.douyin.config.json` 已更新；AppID 不是密钥，不涉及 AppSecret。旧文档中其他机器的配置记录不能证明本机已配置。
- **按个人主体执行**：[WebView 官方说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/tutorial/basic-ability/web-view-component)明确个人类型暂不支持；企业仍须满足全部或核心页面原生的要求。当前构建对全部登记页递归检查，账号辅助页也不使用 WebView。
- **内容安全未闭环**：`POST /auth/profile` 展示名写入路径目前只做格式校验，尚未发现抖音内容安全接口接入；需核对公开展示文本的检测、失败处理及上线凭据，不能以字符校验替代内容安全。
- **联系功能调整**：[第三方引流规则](https://partner.open-douyin.com/docs/resource/zh-CN/mini-app/operation/management/specification/drainage)涵盖站外账号和群引导。抖音联系页及我的页均改为平台反馈说明，不再向视图传入站外社群、二维码或复制动作；不是审核临时分支。使用[右上角菜单反馈与后台反馈中心](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/open-capacity/basic-capacities/feedback-violation/handle-user-feedback)，不伪造未开通的 IM 客服按钮。后台接收、回复和真机操作仍待验收。
- `pnpm --filter @cuberoot/miniprogram audit:douyin` 只读检查正式 AppID、域名校验开关、独立构建指纹、页面完整性、全部登记页原生模板及 sourcemap；它不验证平台主体、域名白名单、隐私后台或真机，不输出“已具备全部提审条件”。

## 本次新增的防回归检查

- 旧 WCA 授权参数在抖音我的页不打开浏览器、不复制授权链接、不发起授权请求；微信原行为和已有身份保留。

- 原生政策页面逐段使用共享全文，中文和英文均检查文本完整性与联系链接复制；导航检查协议按钮不再打开网络页面。
- 联系页复用完整目录，检查匿名访问、联系方式复制、二维码和原生分享。抖音构建目标下检查旧链接按目标跳转、失败可重试、旧回调不能污染新尝试、未知参数不被丢弃，且没有网络换票请求。
- `scripts/native-page-check.mjs` 在抖音构建时递归检查全部登记页面及包内所有 TTML（含组件与未引用模板），拒绝 WebView、动态模板路径和越界模板路径。它不代替运行态、JS 导航、服务端功能及业务域名验收。
- Windows 构建使用已有的保留产物根目录同步方式，避免开发者工具占用目录时重命名失败。该同步不是多文件原子事务，更新后需要开发者工具重新编译。
