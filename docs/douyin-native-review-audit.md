# 抖音原生化审核核查

核查日期：2026-10-20。范围为本地源码和构建产物，未上传、提审、发布或完成开发者工具及真机验收。

## 官方依据与结论边界

[运营规范重点解读](https://partner.open-douyin.com/docs/resource/zh-CN/mini-app/operation/management/specification/mini-app-operation-interpretation)要求全部或核心页面原生，并要求提交功能可完整使用。[WebView 开发说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/tutorial/basic-ability/web-view-component)仍支持配置业务域名的网页容器。因此保留辅助网页并不自动构成违规，但“存在原生首页”也不能证明主要功能或所有审核条件合格。

本次没有通过隐藏入口、审核状态判断或账号白名单改变审核人员看到的功能。当前不能声明“全部原生化”或保证过审。

## 本次新增的防回归检查

- 原生政策页面逐段使用共享全文，中文和英文均检查文本完整性与联系链接复制；导航检查协议按钮不再打开网络页面。
- `scripts/native-page-check.mjs` 在抖音构建时递归检查核心页面及其 include/import 模板，拒绝 WebView、动态模板路径和越界模板路径。它不代替运行态、JS 导航、服务端功能及业务域名验收。
- Windows 构建使用已有的保留产物根目录同步方式，避免开发者工具占用目录时重命名失败。该同步不是多文件原子事务，更新后需要开发者工具重新编译。

## 仍需收尾的工作

1. 账号管理与获取登录码仍使用网站；若目标是零 H5，必须在沿用既有身份、绑定、解绑、注销 API 和安全确认的前提下完整原生移植，不能删掉入口或用静态账号概览替代。
2. 联系页及通用分享深链需要逐路由原生目标映射；不能把所有链接直接切到首页而丢失参数或功能。
3. 全功能对齐仍以 [原生计时器验收跟踪](douyin-native-timer-tracker.md) 为准，含尚未补齐的高级设置、图表及回放功能，不能用审核原生要求替代产品验收。
4. 在抖音开发者工具打开 `core/apps/miniprogram/dist-douyin/`，关闭域名校验跳过选项，验证登录、网站辅助入口、API、授权拒绝与恢复、断网政策阅读、数据保存与设备连接。当前没有这部分运行证据。
5. 在平台后台核对服务类目、简介、隐私声明、业务/请求域名、测试账号与所需资质。此次未访问后台，不能声称这些条件已经满足。
