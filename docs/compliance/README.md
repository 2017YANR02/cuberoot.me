# 备案、认证与商店审核

先按平台核对当前文档与外部控制台证据；代码就绪、材料提交、审核通过和正式发布分别记账，不能相互推断。

事实源：平台后台/用户明确反馈、准确日期与主体；仓库只记录核对结果，不存凭据。

开始：[备案与主体迁移汇总](filing-and-identity.md)，再按具体平台读提审/支付说明。

## 审批、备案和上架的交接

每次完成提交、收到补件要求、核实审核通过或拒绝、发布、变更或撤回后，当次更新[工作台总排期](https://cuberoot.me/zh/admin/team?section=schedule&schedule=bb5a92ca-79f6-4b19-a548-9af52de60225)中的「新公司备案与上架（目标排期）」并回读确认，同时更新[备案跟踪](filing-and-identity.md#当前进度与下一步2026-11-26)或对应平台跟踪文档。本地入口为[工作台排期](http://localhost:3000/zh/admin/team?section=schedule)。

优先更新已有任务，缺项再新增。写明核对日期、经营主体、平台与地区、应用或版本、外部页面显示的状态、证据入口、卡点及下一步。把「已提交」「审核结果」「正式上线」记成独立节点。审批没有变化时沿用已有任务，记录最新核验即可。暂排日期注明用途，审核中不得凭预计时间标记完成。须等待审核或人工操作时，留下触发条件和续办入口。工作台保存失败或无权编辑时，在跟踪文档记明尚未同步，并在当次交付说明。证件、密钥及私人联系资料按仓库敏感信息规则保存。
