## 目标与边界

- 参考已登录的 Google 日历真实页面，补齐重要功能与 UI，不复制全部产品功能。
- 导入 Google 日历时保留时间、时区、重复规则和来源；先核对重复导入/覆盖语义及可恢复方案，避免叠加重复事件。
- 为所有已登录且已绑定 WCA 身份的用户展示本人参加过、已报名的比赛；未来比赛单独标明，不把未报名比赛说成已报名。
- 比赛至少包含名称、起止日期、地点和详情入口；交通查询提供明确目的地与日期，机票/铁路预订由用户完成。

### WCA 数据与显示规则

- 历史：复用 `fetchWcaPersonCompetitions`；未来报名：复用 `fetchUserUpcoming` 与站内已有选手报名索引（含中国报名来源）。关注与比赛目录复用比赛中心，不引入第二套身份绑定。
- 当前维护者账号实际显示 111 场已参赛、2 场已报名；未来两场为 `BeijingAutumnRivalry2026`（2026-10-01~03）和 `GuangzhouGrandOpen2026`（2026-10-05~06）。这个数字是本次观测结果，不是固定配置。
- 登录且绑定 WCA ID 后默认显示本人参赛/报名及已关注未来比赛；全部未来比赛默认关闭，可手动开启。按 ID 合并时，参赛/报名优先于关注/全量目录；关注不能证明报名。
- WCA 来源为动态只读展示，不重复写入个人事件表；修改来源记录后按现有数据缓存刷新。全天日期遵守比赛当地日历日，结束日包含在展示范围内，不臆造轮次时间。
- 公开报名记录可能滞后，也不包括未公开的待审核报名。WCA upcoming 内存缓存已从长期保留调整为 5 分钟；静态报名索引沿用现有生成任务，比赛目录沿用页面缓存，详情沿用 24 小时缓存。“刷新比赛”重新读取现有来源，不能强制上游即时更新。
- 任一来源失败或报名 ID 无法匹配比赛目录时，显示不完整提示；失败不能等同于没有报名。切换账号立即隔离旧数据，未完成请求不能写回其他账号。
- 详情展示比赛名称、日期、城市、可获取的官方详细地址与赛程链接。地图地址附上城市/国家，缺地址时使用目录坐标；历史比赛未公开详细地址时提示查官网。

### 用户要求先研究更简单的带色导出方式

- 通用 Google 授权导入暂未开始编码，先核查导出方式；不能把本次个人数据修复说成所有用户 ZIP 导入已经保色。
- Google 官方数据导出说明列出的活动内容仍为 iCalendar；JSON 部分为会议分组配置，没有承诺导出颜色。尚未实测一份新的 Takeout 包，不能声称 Takeout 可保色。
- 可行的文件方案：一次只读授权，通过官方 Calendar API 或 Google Apps Script 读取活动与颜色，生成包含颜色的 JSON/扩展 ICS，再上传 CubeRoot；这是自定义导出器，不是 Google 网页原生导出按钮。Apps Script 同样有授权/脚本使用门槛。
- 新发现：Google 官方已有 eventLabelVersion=1、eventLabelId 和 calendar.labelProperties.eventLabels 自定义颜色标签接口。未来通用导入不能只支持旧 1–11 colorId；需保存标签定义、默认色、显式颜色及重复实例关系，并实际验证现代深浅主题显示。

## 通用带颜色备份入口（本地实现，2026-09-28）

### 用户流程

日历设置 → 导入和导出 → 连接 Google（只读）→ 选择日历 → 下载带颜色 ZIP；同页可预览并导入刚生成的备份，也可稍后上传 ZIP。普通 Google ICS/ZIP 仍支持，但明确不含颜色。

### 备份范围与完整性

- 复用现有 GIS 加载器及 OAuth client ID，仅单独请求 `calendar.readonly`。不扩展普通 Google 登录/绑定权限，不把 Google 令牌发送给 CubeRoot；取消、关闭或导出成功后清除页面内存令牌。
- 浏览器直接读取选中日历，不经境内 API 转发 Google 请求。完整分页读取日历目录、设置、配色、日历元数据、未展开的全部事件和新版标签事件视图；不限制日期、参与人数或事件类型，也不使用 fields 裁剪。
- ZIP 内 `cuberoot-google-calendar.json` 原样保存 API 响应字段，包括参与人、会议数据、附件元数据和链接、扩展属性、重复例外及取消墓碑；README 说明边界。不保存访问令牌。
- 不含附件文件本体、Google Tasks、共享 ACL、无权限读取或已永久删除的数据；不是整个 Google 账号的全量备份。原始 API 响应保留不代表所有 Google 行为已在本站实现。
- 分页错误、权限失败或新旧颜色视图事件发生变化时中止；不生成部分备份冒充成功。读取和压缩有 100 MiB 上限，超限明确失败。ZIP 识别与导入拒绝版本不符、重复 ID、末页未读完及颜色无法解析的备份。

### 导入与颜色

- 上传先预览条数、日历名称/时区、取消条数和本站恢复限制，点击确认后才写入。不会向原参与人发邀请。当前仍是追加导入，重复上传不会自动去重；可用现有批次撤销。
- 复用原 ICS 解析器处理重复改单次、取消例外和全天事件；保留原时区供夏令时展开。无法表达的重复规则整组跳过并报告，不静默改成错误的重复时间；完整记录仍留在备份。
- 显示字段仍受现有 API 限制：标题/地点 300 字、说明 5000 字；最多 5 个提前 28 天内的弹窗提醒。邮件提醒及其他 Google 独有行为不恢复，预览明确提示。
- 11 个经典颜色及已实测的 24 个现代标签色支持深浅色映射；自定义 hex 原样保存。日历默认色保留 API 原值，已实测的旧 API 孔雀蓝/蓝莓映射到现代 UI；其他旧版日历默认色与 Google 现代主题的逐色映射仍待实页扩充，不声称所有 API 色值都等于屏幕像素。
- 创建日历失败会中止，不再悄悄塞进主日历。后端 bootstrap 增加 `colorFormatVersion: 2`；精确 hex/新版标签色导入前检查服务器能力，旧后端不支持时在开批次前停止，防止静默丢色。
