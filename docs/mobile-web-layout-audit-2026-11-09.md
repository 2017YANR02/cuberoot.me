## 建议实施顺序

1. **共享菜单可视范围**：复盘、导航、公式库。验收不仅看横向溢出，还要测上下边界及最后一个菜单项是否可达。
2. **核心操作同屏**：识别训练 → 计算器 → 帧数工具；覆盖667px和844px横屏及旋回竖屏。
3. **全站浮层避让策略**：宠物与工具操作、弹窗的关系，避免每个页面各做一套。
4. **工具栏精简**：马赛克、求解/阶段分析、WCA筛选、转动记号。
5. **说明/配置密度**：盲拧查询、SQ1练习等，再补登录态工具和真实视频状态。

不建议为了统一把全部按钮都收进菜单：当前任务的核心操作应常驻；只集中低频配置、视角、显示与辅助操作。

## 修复后的验收标准

- **菜单**：在三种基准尺寸内，外框保持可见安全边距；内容超高时内部可滚动，最后一个选项可达；点击外部/关闭/横竖屏旋转行为正确。不能只用 `overflow:hidden` 隐藏问题。
- **训练和工具**：核心图像、当前任务输入与主要动作应能同屏操作；低频配置可集中，但不能丢失功能、数值或状态。旋回竖屏后布局和当前进度保持正确。
- **视觉**：同一行控件垂直居中，标签/输入边缘对齐；中文不出现无意义的逐字断行，英文较长标签不挤出容器；触控区域以44px为目标，不能为了紧凑只缩小按钮。
- **浮层**：验证视觉覆盖和真实点击命中；工具核心操作不被宠物/菜单遮挡。需测试滚动及打开弹窗后的情况。
- **回归范围**：修改涉及的页面补查中英文、深浅色和一个桌面宽度；共享菜单修改至少复查本清单三个菜单问题及原调用方。只跑与改动风险匹配的必要检查，遵守 dev 运行时禁止 `next build` 的规定。
- **真机限制**：浏览器模拟通过不等同于iOS/Android验收。软键盘、动态地址栏和刘海安全区仍需单独记录。
