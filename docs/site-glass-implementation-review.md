# 全站背景与玻璃：实施独立审核

日期：2026-09-10。审核 Agent：`implementation_review`。

本次审核覆盖共享背景、玻璃材质、外观入口与主页接入，结合源码和本地 Chromium 浏览器实测。产品代码未由审核 Agent 修改；本文件是唯一获准写入的审核产物。未暂存、提交或发布。

## 结论与边界

共享基础层的低对比度变量、减少透明度降级已经独立复验通过。审核发现的 LiquidGlassChips 编译后丢失标准 `backdrop-filter` 声明，已在最新源码调整声明顺序，但尚待浏览器复验。菜单和外观比较卡片的不透明问题由实施 Agent 修复，审核尚未复验最新运行效果。

**不能据此认定全站全部页面验收通过。** 本次实际访问 `/zh`、`/zh/appearance`、`/zh/stroop`；只有后两页保存并查看了截图。路由清单、选择器覆盖数量与 computed style 均不能替代每页视觉验收。完整范围见 [实施方案](site-glass-rollout.md) 和 [路由审核记录](site-glass-route-audit.md)。

## 发现与复验

| 项目 | 直接证据 | 最新状态 |
| --- | --- | --- |
| 低对比度材质变量在根节点提前解析 | 原实现切换 `data-contrast=soft` 后，body 的 `--card` 已混入灰色，但玻璃背景仍引用根节点纯白，控件颜色不变 | 已在 body / contrast scope 重新定义材质变量；独立浏览器复验显示玻璃变量随 soft 配色重新解析，已恢复临时属性 |
| LiquidGlassChips 在减少透明度下仍半透明 | 原组件用 currentColor 的固定低透明度背景，没有消费材质降级变量 | 已改用共享 surface / popover 变量；模拟 `prefers-reduced-transparency: reduce` 时，2 个容器和 2 个滑块均为实色白底且滤镜为 none；模拟设置已恢复 |
| LiquidGlassChips 的模糊声明在编译产物中缺失 | `/zh/stroop` 正常模式下变量包含 blur(10px)，但 computed backdropFilter 为 none；生成 CSS 仅保留 `-webkit-backdrop-filter`，Chromium CSSOM 中对应标准属性为空 | 最新源码已将 prefixed 声明放前、标准声明放后；浏览器最终复验待补，不能只凭源码关闭此项 |
| 外观菜单仍为实色底 | 390 × 844 的主页外观菜单 computed 背景为 rgb(255,255,255)，backdropFilter 为 none | 实施侧已接手修复；最新效果待独立复验 |
| 外观比较页 `.ac-card` 仍为实色底 | `/zh/appearance` 的 `.ac-card` computed 背景为白色，滤镜为 none | 实施 Agent 报告已补入玻璃规则；尚未独立复验。用于准确比较配色的色板自身保留实色属于有意边界 |
| Auth 路径可能标记有景物但不渲染景层 | 原 active 计算与 auth 提前返回分离，存在 body 激活而景层缺席的路径 | 最新源码已把 auth 排除纳入 active；未执行真实认证流程，运行验证待补 |
| body MutationObserver 调度范围过宽 | 原监听将子树文本更新也用于调度主题重新计算 | 最新源码过滤文本节点，只有插入/移除包含 class 的 Element 才调度。仍可能被列表元素变化触发；未做性能测量，不宣称性能已验证 |
| 自动背景图片加载失败后的恢复 | 源码 failedScene 随 choice 重置；自动模式下随明暗切换的重试边界需要实测 | 合成 error 事件的验证调用未完成，不认定通过，也不作为已确认缺陷 |

实施 Agent 报告最新 typecheck 通过；这是实施侧证据，本审核 Agent 未重复执行。文档本身不涉及 TypeScript 逻辑。

## 基础层源码审查

- 景层首次 ready 为 false，浏览器存储不在 SiteBackground 首次 render 中直接读取；激活后由共享偏好驱动背景。
- 景层使用负层级，body isolation 和激活后的透明底共同允许景物显示；实际外观页与 Stroop 截图证明这两页景层可见。
- 新共享玻璃材质未使用前景颜色渐变，场景遮罩属于背景层；未发现本次基础材质重新引入用户反对的左右着色渐变。
- 共享 SVG 引擎、UA 降级和清理分支已读源码；真实 Safari / Firefox 和移动端内核尚未运行，不能把源码分支当作兼容性通过。
- 未发现可复用的独立 JS 暗锁页面清单。现有 globals.css 的暗锁选择器是事实来源，不建议为 observer 优化复制第二份路由或 class 清单。

## 仍需补充的验收

1. 浏览器复验最新 Chips 声明顺序、外观菜单、外观比较卡片，确认实际景物透过、模糊生效与文字可读。
2. 依路由审核清单逐页打开页面；认证、权限、动态数据和受保护入口应分别记为实际通过或待验，不能以路由源码枚举代替。
3. 320px 窄屏、全部背景、明暗及配色组合、无背景、图片失败恢复、存储异常和首屏刷新。
4. 弹窗与 portal、固定控件、移动端菜单、全屏工具、打印等不同绘制层级，以及实际 Safari / Firefox。
5. 需要性能结论时另行测量 observer、共享滤镜和密集控件的开销；本次没有性能通过证据。

## 本地开发环境与操作记录

Stroop 首次进入期间曾出现 `Router action dispatched before initialization`，栈含 HMR refresh / WebSocket，随后展示启动失败提示。刷新审核页面后恢复正常。这是实际观察到的开发环境故障；尚无证据把它归因于产品玻璃逻辑，也不应隐去此次失败。

审核未写浏览器持久身份或外观偏好，只使用临时 DOM 属性与已恢复的媒体模拟。最终图片失败恢复测试的浏览器调用未返回，可能停留在临时主题状态；已告知实施 Agent 刷新其接管页面恢复。因疑似共享 MCP 页面竞争，按实施 Agent 要求停止发起浏览器操作且未关闭标签页。未返回调用不计入通过证据。
