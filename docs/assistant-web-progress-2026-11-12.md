## 行为

- 在现有 SSE 中增加可忽略的 `progress` 事件，每次请求最多 64 个步骤。实际模型调用、工具执行、证据复核开始时发送 running，结束时更新同一编号的完成、信息不完整或失败状态。只传阶段、工具标识、耗时及实际读取的来源数；不传原始推理、参数、证据正文或未核验草稿。来源数不表示已验证正确，复核步骤结束也不表示每个结论被接受。
- 前端显示当前阶段、经过时间和可折叠步骤；完成后折叠。停止或断线后未结束的步骤显示中断，不补造成功。旧服务器的 status/answer/done/error 仍可使用，JSON 客户端不受新增事件影响。
- 保留原有正文释放条件。普通回答继续流式显示；需要复核的答案仍待复核完成。去掉额外的逐字播放队列、逐字 DOM 包装和 280ms 尾部等待，完整答案与表格收到后即可显示。

## 测量口径

复用 `site_assistant_requests.metrics` JSONB，无新增数据库迁移。原 `duration_ms`、`first_answer_ms`、模型用量及费用记录保留。

| 字段 | 起止与含义 |
| --- | --- |
| `timing.version` | 新测量口径版本，当前为 1；历史比较必须区分版本 |
| `timing.requestReadyMs` | 服务端收到请求到完成认证、附件准备、记忆恢复、监控入库及配额准入 |
| `timing.firstProgressMs` | 服务端收到请求到首个真实执行进度事件发出；不是首段回答 |
| `timing.responseReadyMs` | 成功请求的答案准备完成时间，测于完成记录持久化之前；失败与取消不填此字段 |
| `stages.model` / `stages.review` | 规划/生成与复核分别累计，包含该阶段重试。旧版本 model 包含复核，不可直接横比 |
| `toolTimings[工具名]` | 每种工具累计执行时间、调用次数与抛错次数；证据不完整另由进度状态表示 |
| `models[].durationMs` | 每次 provider 调用的时间，失败尝试也保留 |
| `models[].firstActivityMs` | 每次模型调用到首个实际文本、推理或工具输出事件；不记录事件内容，不计 SDK start/保活 |
| `models[].firstTextMs` | 到首个模型 text-delta；可能是 JSON 框架，不等于用户可读正文。非流式调用不伪造这个值 |
| `browser.firstProgressMs` / `firstAnswerMs` | 从用户提交到浏览器收到首个真实进度／首段非空正文，包含附件准备与网络时间 |
| `browser.responseMs` | 从提交到浏览器收到最终答案（SSE done 或完整 JSON） |
| `browser.visibleMs` | 从提交到 Markdown 提交后两帧的绘制观测点；同期表格已挂载。不是图片解码或异步图表全部就绪的证明 |
| `browser.renderDelayMs` | visibleMs 减 responseMs，反映回答到达后的显示等待 |
| `browser.wasHidden` / `transport` | 请求及显示期间是否进入后台、使用 SSE 还是 JSON |

浏览器测量是客户端自报，单独存储，不作为计费、配额或可信服务端性能指标。只允许当前用户给自己 30 天内成功的 chat 请求提交一次，字段有严格上限与先后顺序校验。重复上报不覆盖首份样本；独立限流，不占用反馈限流桶。记录失败不会改变答案。页面提前关闭、刷新、后台停留过久或完成入库延迟可能缺样本；缺失不能按零耗时处理。

后续通过现有管理员请求明细的 metrics 读取。按版本、模型、思考模式、图片与否、任务类型分组，分别报告成功、失败、取消、样本覆盖率以及 P50/P95。前台显示指标排除 `wasHidden=true`，后台样本单列。`total`、`model/review` 与嵌套的 `tool/data/page` 不是互斥时间，不能全部相加当成总耗时。
