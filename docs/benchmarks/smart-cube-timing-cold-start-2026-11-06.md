# 智能魔方冷启动与首批消息偏移：同一组 441 用例

冷启动阶段已经走过的时间，现在会用本局结束时学到的速率重新计算；有效设备时间的成绩也不再受首批到达时刻与绝对停表截断影响。软件基准中，慢 0.7% 的冷启动 10 秒成绩由上轮 9.992 秒变为约 10.000 秒，四手一批的 9.700 秒变为 10.000 秒。

这是本地产品修复与确定性软件回放，尚未推送、发布或做真实设备验收。固定漂移组 28 例的最大误差小于 0.1 ms，不代表任意冷启动环境都有此精度：很短的还原、观测不足或强抖动仍可能无法可靠估计速率。

## 产品实现与接线

- 共享 MoveClock 继续输出连续在线时间；每手附带独立 epoch、原始设备时间、当前速率和宿主时钟估计。结束时用最终速率计算整段原始设备时间差，消除早期速率尚未收敛的残差。
- 校准窗口从 128 个独立接收观测扩到 512 个，仍至少需要 8 个观测、1000 ms 设备跨度；同一批只用最新一手作为接收观测，保留稳健拟合与噪声门槛。
- 共享 timer machine、动作 recorder 和 attempt producer 使用同一校正。专项观察的起点随最终模型校准；手动观察保持宿主时间语义。无时间戳的历史回补沿用前一校正时刻，不混入旧在线时间。
- 陀螺仪保持宿主时间尺度，只平移到校正后的成绩原点；不按设备时钟速率拉伸，人工记录的初始握持仍在 0。该时间对齐仍是软件估计，未经真实设备验收。
- Web 单人、多人、联网、连续多魔方；安装端单人/对战；Watch 桥接与小程序均传递同一份校准信息，不复制平台算法。同步多人只有发起者使用自己的设备 epoch。
- 手动/盲拧起表不改成首转起表；无设备时钟、重连/计数重置、不同设备、回调 token 不匹配继续走原有回退。
