# 聊天助手第一阶段：证据与交付边界

检查基于 `f3d1491332` 的本地工作目录，2026-10-26。本轮没有提交、推送、部署或写入生产知识索引；保留其他任务的未提交修改。真实调用使用隔离进程、现有只读数据工具和现有供应商，不写生产聊天监控。

## 方案与实现

继续使用一个对话模型按需调用导航、站内检索、结构化计算与联网工具。一般知识、写作和翻译保留直接回答。先用真实问题找资料与检索缺口，再决定是否引入额外模型，不把每个问题都强制经过知识库。

- `assistant-evaluation.ts` 定义题目契约、资料覆盖审计与结构检查；`audit-assistant-knowledge.ts` 仅读取公开索引，不产生模型费用。60 道人工编写的合成问题分为普通交流、网站说明、导航、计算、时效信息、追问六类；40 道开发题、20 道保留题。保留题尚未执行，不是用户聊天样本。
- 复用 `benchmark-site-assistant.ts` 的真实 API handler、身份校验及独立诊断额度，新增 JSON 题组、显式分组、A/B/C 策略和内存指标捕获。A 为按需检索；B 在首次回答前强制读资料；C 为按需检索加重排序。B 只允许内部程序入口，公开 API 不能选择该实验。
- 可选 `site_assistant_rerank.ts` 使用百炼原生 `qwen3-rerank` 接口：原词法与向量各取至多 20 条，RRF 合并去重后最多 40 条，重排序选 6 条。每条最多 2,000 字符、查询最多 500 字符，默认 2.5 秒期限，响应最多 64 KB；固定可信 HTTPS 端点，禁止重定向。返回引用沿用本站 ID/URL，不接纳供应商生成的链接。
- 重排序默认关闭；拒绝、超时、异常响应保留原 RRF 前六条，不自动重试；用户取消继续向上传播。单独记录用量、状态、耗时及价目快照，缺少用量或未知端点保持未估价。
- 修复导航合并时丢失完整页面标题：保存同一路径的名称并融合原问题与工具查询的排名，避免 `/timer` 被正文偶然提及的页面挤出。
- 世锦赛日期捷径仅处理明确年份或历届查询；“下一届”回到正常工具选择，避免误答历届列表。
- 计时器双人/联机说明补入既有中英双语帮助，页面和索引共用一个来源。没有另建仅供 AI 阅读的功能说明副本。
- 分析工具说明明确 SQL 聚合/窗口结果在最终显示上限前计算；明细截断不代表总数无效。此说明不能保证模型总能正确选择统计粒度，仍需评测。

接口依据：[百炼重排序 API](https://help.aliyun.com/zh/model-studio/text-rerank-api)、[重排序模型](https://help.aliyun.com/zh/model-studio/rerank)。复用现有 AI SDK 主循环；已安装的兼容供应商适配器未提供该原生重排序入口，因此只增加一个有明确边界的适配器，没有增加第二套 Agent 框架。

## 实测

模型配置为现有 `deepseek-flash`，服务端内进程调用真实 handler。A 的 40 道开发题完成，HTTP 成功 39/40，P50 3,706 ms、P95 10,953 ms；已知标价估算合计 2.3117501 元，另有 3 次未估价调用。39/40 不能称为回答正确率。

在同一原始代码包、同一公开索引、同一配置下，对 G01–G06、S01–S06 做 A/B 配对：

| 12 道共同题 | A：按需检索 | B：强制检索 |
| --- | ---: | ---: |
| HTTP 成功 | 12/12 | 12/12 |
| P50 | 4,543 ms | 3,852 ms |
| P95 | 8,213 ms | 8,405 ms |
| 已知标价估算 | 0.5473955 元 | 0.510183 元 |

B 在六道一般问题上都多做了资料读取；尚无已验证的质量收益，原本缺说明的 S01 仍无法回答。不能由这组数据声称强制 RAG 一定更慢或更贵，也不能据此全站开启。供应商缓存、模型别名和外部实时数据没有冻结，样本小且只有单轮，统计仅作描述。

评测规则曾依据实际路由修正：马赛克/数帧以帮助页检查正文；打乱目标为 `/scramble/gen`；规则入口接受摘要或完整页；时效纪录允许 `records` 工具。汇总保留 HTTP、路由/工具结构检查与人工语义验收的区别，语义结论默认 `pending_review`。

修复后最小复查：N06 返回实际计时器入口；C04 查询下一届赛事并返回对应来源。两题仍有非必要说明，不能称为最佳体验。D06 从失败恢复为 HTTP 200，返回城市总数 21，但额外校验把成绩轮次 178 错标为比赛场数，与正确的 30 场表并列，因此**语义验收仍不通过**。不要把这次 HTTP 恢复登记为计算问题已解决；下一步需针对结果粒度、重复校验及冲突表格的发布规则改进。

仅替换计时器帮助正文的模拟公开索引复查了 S01、S02、F04，均能区分同设备多人和多设备联机，分别耗时 7,200 / 6,859 / 3,555 ms。没有更新生产向量库，因索引指纹不匹配实际走本地词法回退；这验证的是资料补充后的可回答性，不是新向量索引或重排序效果。S02 仍夹带无关训练设置，F04 仍读取开发者组件页，后续应进一步约束说明的相关性。

重排序接口首次探测返回 403 AccessDenied。用户登录正确账号并明确批准后，只给现有 CubeRoot 服务端密钥增加 `qwen3-rerank` 权限；重新打开控制台确认保存，再从服务器复验返回 HTTP 200、281 ms、60 tokens，正确排列两条公开测试文本。没有更换密钥或修改其他模型/IP 权限。

C 使用与 A/B 相同的原始代码包和原始索引完成相同 12 题：HTTP 12/12，P50 4,392 ms、P95 7,467 ms，原始记录已知标价估算 0.5504965 元；5 次重排序当时尚未配置价目而记录为未估价。实际重排序均成功，候选 33～38 条，耗时 252～341 ms，合计 124,086 tokens。其余题没有调用重排序（无需资料或候选不足 7 条）。

随后按[百炼北京官方标价](https://help.aliyun.com/zh/model-studio/model-pricing)核实 `qwen3-rerank` 为 0.5 元/百万输入 tokens，并将价目快照加入监控：本组重排序另估 0.062043 元，总标价估算约 0.61254 元；不回写原始评测记录，不等同于账单实付。独立接口探测另外消耗 60 tokens。

这轮 C 没有解决 S01 缺操作说明；S02 仍从资料未提及推断联机入口不存在；S04 的排序偏离计时器自身设置而引向打乱生成器。因此没有证据支持默认启用，生产开关未改。不能以接口成功或小样本耗时下降代替质量验收。
