## 上线前阻塞与后续实现

1. 按驳回提示完成客服电话认证；由商户管理员操作，不虚构电话号码或认证结果。
2. 以网站为目标核实 H5 纯签约资格。H5 支付申请与 H5 纯签约权限不同；后者需单独申请。官方 H5 纯签约文档列出的 AppID 类型为公众号或移动应用，不能直接假定当前小程序 AppID 可用。
3. 核准签约通道后申请月、年模板，取得相应模板 ID。不要把未审核的价格修改直接应用于已有合同。
4. 后端实现签约记录、验签回调、查询与解约；签约成功不等于付款成功。
5. 实现周期任务、扣款前通知、幂等扣款、订单对账、失败处理、支付成功后发放权益及退款流程。处理中或失败不能延长权益。
6. PC 入口需引导至获批的手机签约流程，不能把 Native 一次性支付二维码冒充自动续费签约码。
7. 获批后验证首次签约、拒绝/退出、首次扣款、续费、失败重试、重复回调、网站解约、微信解约及退款，再开放套餐。

## 后续实现契约与验收清单

以下是实施要求，不是已建表或已上线的 API。

- 合同：关联本站用户、商户/AppID、模板、微信合同号，保存用户确认的价格/周期/协议版本快照；只有本人能查询和解约。不要用新套餐价直接覆盖老合同。
- 状态：待签约 → 生效 → 解约处理中 → 已解约；拒绝、超时、失败另记。付款状态独立，签约和浏览器跳转均不发放权益。
- 账单：合同与周期唯一；支付单号唯一；回调和查单统一幂等入账，事务中确认金额、币种、商户与订单一致后延长权益。
- 通知：按获批产品的通知时序发起；重复任务不重复扣款；发送失败、失败重试、用户通知留可核对记录。不能把某个 API 版本的时序套到所有产品。
- 取消：网站真实解约及微信侧解约都同步；已支付当期权益不因取消续费直接删除；取消不是退款。并发扣款先查合同状态，结果不明先查单不盲目重扣。
- 安全：回调验签、防重放、订单绑定、敏感字段脱敏；密钥只存安全配置，不放前端、截图、MD、日志或 Git。普通支付 APIv3 密钥不直接当成所有代扣接口的凭据。
- 时间：月末、闰年、跨年、时区、到期续费边界用固定测试样例；以批准的计费规则定义周期，不用固定30/365天冒充自然月/年。
- 验收：拒绝/退出/超时、首次支付失败、正常续费、重复与乱序通知、通知验签失败、金额不符、两份定时任务并发、取消与扣款竞态、退款与对账差异都要有测试。
- 发布：仅在另获发布授权后部署；对应 CI 和线上只读检查通过，再做明确授权的真实小额验收及退款。最后才允许开放连续套餐。
