## 后续实现契约与验收清单

## 2026-09-09 退订实现与接入边界

### 正式页面路径

`会员页 → 管理自动续费 → 登录 → 查看本人合约 → 取消自动续费 → 一次确认 → 微信确认结果`。

只有微信签名、商户/AppID、模板、商户合同号及已知微信合同号均核验通过，才能更新本地结果。解约成功显示“自动续费已取消”；超时或结果不明保留退订请求并显示待确认，可刷新、重试，不能伪装成功。微信侧取消可通过刷新查询、签名通知触发查证或显式启用的后台同步发现；均未部署或实商户验收，不保证实时到达。

列表只展示本人合约的套餐价格快照、状态和核实日期，不把微信合同号或支付凭据传到浏览器。退出或切换账号清空旧数据并取消旧请求。没有本站记录只表示“本站暂无关联记录”，不等于“微信没有授权”。单次月/年购买不产生自动续费合约。

### 后端接口与数据库

- `GET /v1/membership/subscriptions`：登录后查询本人记录，并核实未终止合约的微信状态；禁止缓存。
- `POST /v1/membership/subscriptions/:id/cancel`：本人 UUID 路径，JSON `{ "confirm": true }`；先持久保存取消意向，再请求微信解约。微信确认终止返回 `200`，结果仍未确认返回 `202`，配置未就绪返回 `503`，不存在或非本人返回相同 `404`。
- `POST /v1/membership/subscriptions/wechat/notify`：无需浏览器登录，但必须通过 APIv2 签名和成功码校验；64KiB 请求限制，未知合约不入库。绑定已有记录后再次向微信查询，核对通知中的微信合同号和 openid；仅在查证并持久化后返回 XML `SUCCESS/OK`，失败返回 `FAIL/RETRY`。已确认终态的重复通知只做绑定及幂等 ACK，不再查证本次 openid，也不修改状态。
- `0222_membership_contracts.sql`：保存用户归属、商户/AppID/模板/合同标识、价格周期和协议版本快照、取消意向与核实时间；账号合并/绑定同步归属，未终止合约阻止账号注销。
- 本轮不会创建假签约记录，也没有开放管理员随意绑定别人合同的接口。未来签约流程必须先基于服务端认证账号保留记录并锁定模板/价格，在微信验签和查询后确认状态。
- 解约不写 `memberships` 或支付订单，不截断已付会员有效期，也不自动退款。

### 必需配置（仅变量名，不含密钥）

本次对接商户平台的 APIv2 委托代扣合同接口，不是 APIv3 的预约扣费产品。需要三个专用服务端环境变量：`WECHAT_PAPAY_APPID`、`WECHAT_PAPAY_MCHID`、`WECHAT_PAPAY_API_V2_KEY`。APIv2 密钥必须独立核实，**不能把现有 Native APIv3 密钥复制过来代替**。AppID/商户号必须与记录及获批能力一致。未读取、迁移、改写现有支付密钥。

这三个配置只是退订管理配置，不开启自动续费销售。关闭新签约销售时，也应保留已有合约的管理能力和所需凭据。

### 通知和后台同步接入

- 计划回调地址：`https://api.cuberoot.me/v1/membership/subscriptions/wechat/notify`。本轮未发布，不能视为已可用；获准发布后需同时配置签约请求 `notify_url` 和模板的解约回调地址，直接 HTTPS 可达且不带查询参数。[官方通知说明](https://pay.wechatpay.cn/doc/v2/merchant/4011987586)

- 不直接采信 ADD/DELETE 事件状态，因此晚到 ADD 不能复活终态；签约通知或浏览器返回不会发放权益。远端查询可能超时，通知返回失败让微信重试；不承诺通知必达。
- 后台入口 `startMembershipContractSync()` 已挂载，但只有 `WECHAT_PAPAY_SYNC_ENABLED=true` 才启动。本轮没有写入或启用这个开关。启用后会查询真实接口，并重试用户已提交的取消请求，必须在迁移、配置和发布授权完成后启用。
- 每分钟调度，单轮最多 10 条串行处理；每条至少间隔 5 分钟。进程内防重叠、数据库 advisory 跨进程互斥、账号锁优先及 `SKIP LOCKED`；失败也保存 `last_sync_attempt_at`，避免坏记录反复占队首。积压时不保证每条 5 分钟内更新。
- 后台任务不签约、不发起扣款、不退款，只核对现有非终态记录或重试已保存取消意向。它不能弥补目前缺失的可信签约预留/入库流程。

### 本地只读预检

在仓库 `core/` 运行：

```powershell
pnpm --filter @cuberoot/server exec tsx scripts/check-wechat-renewal.ts
```

默认只检查当前进程继承的三个 PAPAY 配置格式，不读取 `.env`，不访问微信或数据库，不输出值。可加 `--db` 核对本地数据库；必须显式配置 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASS`、`DB_NAME`，只允许回环地址。数据库事务只读，只核对 `0222` 迁移 SHA256 和 19 列类型/可空性，不读取合约或用户行。

当前脚本固定 `readyForProduction: false`、退出码 `1`，因为签约预留和完整扣款链尚缺；配置存在不等于商户获批。默认烟测显示当前进程的三个 PAPAY 变量缺失，**不代表已检查本机其他配置文件或线上环境**。远端主机拒绝已测试；`--db` 尚未实连数据库，只完成 schema 夹具测试。

### 安全和后续扣款约束

取消意向独立事务保存，即使微信超时也不丢失；账号锁先于合同锁，与账号合并/注销保持一致，锁等待超过 1 秒返回可重试的 `503`（`Retry-After: 2`），避免重复刷新无限排队；已终止合同不能被旧查询重新激活，取消意向不能被清空。将来扣款任务必须在相同锁约定内检查 `state = 'active' AND cancellation_requested_at IS NULL`，不允许对已申请取消的记录发起新扣款。本轮尚无周期扣款任务，不能据此宣称扣款竞态已经实单验收。

所有自动化支付结果都来自签名夹具或 mock，浏览器夹具不写入产品代码、申请材料或生产数据库。数据库 DDL 使用本地 `pg13` 独立 schema 和事务回滚验证，未修改生产数据库。
