## 1.5 三阶 HTM 距离分布收敛成单一源(C1 / C2 / C14 / C15 / C16)

搬 A1(0..20 深度分布)前先清地基。站上原来有 **七份** 手抄表,d=16..19 互相打架;其中一份写到
`1_100_531_606_815_050_000` 这种 cube20.org 从没公布过的位数。全部收进
`lib/god-distance-333.ts`,锁在 `tests/god_distance_333.test.ts`。

### 这份源怎么分级

| 字段 | 档位 | 含义 |
|---|---|---|
| `GOD_DIST_333[d].count` | `exact` d ≤ 15 | Rokicki 等人穷举,逐位精确。**界面显示的就是这一列** |
| | `approx` d = 16..19 | cube20.org 只给两位有效数字。四项相加比真实尾部大 1.03%,那是四舍五入,不是抄错 |
| | `atLeast` d = 20 | 490,000,000 是「已经找到这么多」,是下界不是计数 |
| `GOD_TAIL_TOTAL` | 精确 | `\|G\| − Σ(d ≤ 15)` —— 对 d ≥ 16 唯一能说的硬话 |
| `GOD_DIST_333_NORMALIZED` | 派生 | 只把四个 `approx` 等比缩到尾部真值,Σ 由构造恰为 `\|G\|`。**只用来画条 / 算占比 / 算期望,不许显示** |

关键取舍:**显示走公布值,几何走归一化值**。归一化后的 d=18 是 19 位数,端到界面上就是拿伪精度
换掉伪精度(C16)。`GOD_KIND_MARK` 给三档统一记号(`` / `≈` / `≥`)。

### 顺带修掉的四条硬伤

- **C2** `Patterns.tsx`「全 4.3 × 10¹⁹ 里只有三个状态需要满 20 步」→ superflip 是**第一个**被证明的
  (Reid 1995),满 20 步的已找到约 4.9 亿个。`math/group/page.tsx` 的 superflip 特写同病同修。
- **C14** 六处写「17-19 步占 >99%」→ 真值 **97.25%**;99% 那句只有把 d=16 也算进去才成立
  (16-19 = **99.77%**)。两条改由 `godShare()` 出,正文插值 `GOD_SHARE_17_19_PCT` / `GOD_SHARE_16_19_PCT`。
- **C15** `OpenProblems.tsx` 把**分支因子 17.97** 当成平均最优步数 → 平均是 **17.70**(`GOD_MEAN_HTM`)。
  17.97 只在 CayleyGraph 讲分支因子时是对的。
- 「FMC 16 步纪录难在打乱稀有」→ 最优解 ≤16 的打乱有约 **2.7%**,难的是人在一小时里把它找出来。

### 守卫

`tests/god_distance_333.test.ts` 七项:精确档逐位、尾部真值、1.0103 超额、归一化 Σ = |G| 且只动

## 1.6 A4 四色底 Cross:不抄那个均值,把整条分布跑出来

表格只给了一个 `avg 5.019`。站内 `exactColorsOf()` 对 4 字符 key 直接 `return null`,
四色底在精确集是空的。与其把 5.019 抄进去,不如把分布算出来 —— 它本来就便宜。

### 怎么算的

`solver/src/bin/dist_cross_6col.rs` 原本就是「6 张单面 BFS 表 + AVX2 逐状态取 min」。
取 min 的面集合抽成 `--faces <UDLRFB 子集>` 参数即可,全空间(12!·2¹¹ = 980,995,276,800)
与编码一个字都不用改 —— 所以任意色数出来的分布都躺在同一个分母上,可以直接互相比。
单次 ~35s(RAYON_NUM_THREADS=14)。

### 参数化本身对不对,拿已有金标验

| `--faces` | 期望 | 结果 |
|---|---|---|
| `U` | 5,160,960 × `cross_1_col` 金标(190,080 子空间在全空间里的重数) | 九档逐位一致 |
| `UD` | 192 × `cross_2_col` 金标 | 九档逐位一致 |
| `UDLRFB` | `cross_6_col` 金标 | bit-exact,内置金标自检也过 |

这三条不是走过场:`_1col` / `_2col` 用的是完全不同的算法(子空间 BFS、495×495 mask 容斥),
它们和参数化后的全空间 min-reduction 对上,才说明新路径没写歪。

### 四色底

「四色底」= 去掉一对相对色。`LRFB` / `UDFB` / `UDLR` 三种取法各跑一遍,**九档逐位相同** ——
颜色对称性在这里是跑出来的,不是假设的。

```
20635791 309065792 3241839115 27981105637 175574881766
514537441534 256994694935 2335611639 591          Avg 5.0194
```

`5.0194` 对上表格的 `5.019`。另外两条现场自证:平均步数随可选底色数单调下降
(5.8121 > 5.3872 > 5.0194 > 4.8095),且累积分布逐档「六色 ≥ 四色」。

### 白送的第四重验证

四色底一进 `exact_dist.ts`,页面上的「叠加 WCA 真题对照」就自动接上了 ——
1,317,565 条真题的四色底经验分布与这条理论分布**最大逐档偏差 0.0137 个百分点**。
穷举、真题两条独立的路走到同一处。

覆盖矩阵顺手改了一处:四色底那一列多出四个空格,原来会渲染成和「不适用」一模一样的灰字。
「未实现」现在有自己的样式与图例条目 —— 说得通只是没跑,和「这个阶段根本没有这个槽位」
是两回事。

## 1.8 A10 部分还原(5c / 5e):表格那两个平均值也是错的,而且错法一样

表格给「5c?」1152 / avg 13.10763889、「5e?」3272 / avg 11.969437652811736,只留了一条
speedsolving 链接。顺着链接读原帖,cuBerBruce **自己写了**:

> the equivalence classes are not all the same size so you can't calculate the exact average
> from these numbers

也就是说,那两个平均从一开始就不该算。表格照算了。

### 这两族到底是什么

除了 5 个角(或 5 条棱)首尾相接转一圈,整个魔方是好的。状态数有闭式:

| 族 | 构造 | 状态数 | 等价类 |
|---|---|---|---|
| 角 5-循环 | C(8,5)·4!·3⁴ = 56·24·81 | 108,864 | 1152 |
| 棱 5-循环 | C(12,5)·4!·2⁴ = 792·24·16 | 304,128 | 3272 |

3⁴ / 2⁴ 而非 3⁵ / 2⁵ —— 5 个块的朝向和被整体约束定死,少一个自由度。

### 三步复算(没有一个数是抄的)

1. **枚举 + 对称归并**:全部 108,864 / 304,128 个状态,按站内 `_sym_core.ts` 的 48 元对称群
   + 取逆(96 个操作)归轨道 → **1152 / 3272**,与上游逐位相同。这一步同时证明「我们枚举的
   族和他的是同一个」,后面的 classCounts 才敢直接引用。
2. **逐类代表求最优解**:本机 cube48opt + h48 剪枝表,一个类一个代表(1152 + 3272 次,
   各 ~1 分钟,22/s)。按轨道大小加权 → **逐深度状态数**,上游从没给过这一列。
3. **交叉验证**:另取该帖 #38 楼给的「固定 5 个角」非归约分布,独立生成那 1944 个状态
   (cubing.js 建态 → 校验 → 最优解),跑出 `24 52 372 716 744 36`,与原帖**逐位相同**,
   均值 13 + 67/486 = 13.1379。

### 结论:那两个平均恰好就是类平均

| 族 | 表格值 | 类平均(复算) | 真平均(复算) |
|---|---|---|---|
| 角 5-循环 | 13.10763889 | **13.10763889** | 13 + 64/567 = 13.1129 |
| 棱 5-循环 | 11.969437652811736 | **11.969437652811736** | 11 + 2039/2112 = 11.9654 |

逐位重现即实锤:表格不是精度差一点,是把 1152 / 3272 个**大小不等**的等价类当等权样本。
轨道只有 48 和 96 两种大小(角族 36 + 1116,棱族 208 + 3064),所以类不是状态。
两族同时中招,说明是口径问题而非笔误。

## 1.9 B1 / B3 跳步速查表:一套容斥同时吃掉三族,顺带证实表格的 CN 222 是精确值

### 为什么要先有一套通用容斥

表格里「OLL 跳步 1/216」这类是直接数出来的,没什么可说的;真正麻烦的是十字与 2×2×2 块那两族 ——
**同一族里的几个目标共用块**。CN 十字是 6 个面取并集,相邻两面共用 1 条棱;CN 222 是 8 个角取并集,
相邻两块共用 1 条棱。任何「6 × 1/190,080」式的加法都会重复计数。

所以 `lib/skip-probability.ts` 只写两个原语,其余全部由它们推:

- `statesWithSolved(角, 棱)` —— 固定 `s` 角 `e` 棱后剩下的合法状态数
  `(8−s)!·3^max(7−s,0)·(12−e)!·2^max(11−e,0)`,两个自由群都不足 2 个元素时不再除 2(奇偶约束失效)
- `statesWithAnySolved(目标集)` —— 目标间容斥,子集的并集直接喂回上一条

全程 BigInt。全群 43,252,003,274,489,856,000 早就越过 `Number.MAX_SAFE_INTEGER`,任何一步走浮点都静默丢位
(测试里专门锁了这一条)。

### 凭什么信它

四档十字 + 任一槽 XCross 的 0 步状态数,solver 那边是用**完全不同**的路子算的(子空间 BFS /
495×495 mask 容斥 / 全空间 AVX2 min-reduction),已逐位对齐 C++ 金标并落在 `exact_dist.ts`。
本文件的通用容斥与它们**分数相等** —— 测试里交叉相乘比 BigInt,不比浮点:

```
statesWithAnyCrossSolved(faces) × exact_dist.total == exact_dist.counts[0] × |G|   四档全过
statesWithAnyXCrossSolved(['U'])                  同上                             过
```

十字对得上,才敢让同一套代码去算 2×2×2 块 —— 那一族站内外都没有独立金标。

### 三条与表格的对账

1. **CN 222 = 31,688.602055**,表格写 31688.60205470051 —— 逐位吻合到 10 位有效数字。
   那一格没标来源,本来疑心是模拟值;既然与本机精确容斥对上,它就是精确算出来的。反过来也第三次确认了这套容斥。

## 1.13 B10 斜转:四个数逐位对上,一个注解否掉,一组数口径不明

### 「棒」和「灯」是什么,是从数字反推出来的

表格给了 `No bar 51568/3149280`、`No bar & no light 1040/3149280`,没给定义。斜转一个面上,中心是转 45°

**只有一种组合逐位对上**:

- **棒** = 中心与同面某个角块同色 → 51,568 ✓
- **灯** = 一条棱两端的两个角块同色 → 与「无棒」一起 = 1,040 ✓

- 某色四块凑成完整一面(六个面都算)= `6·20!/(4!)⁵` —— 约掉恰好 **1/1771**;
- 另一条路:抓住其中一块,另外三块要落进同一面剩下三槽 = `3/23 · 2/22 · 1/21 = 6/10626 = 1/1771`。
  两条路对上,测试里断言的是 `23·22·21 == 6·1771` 这种整数恒等式,不比浮点。
- 一对相对色都成面 = `6·16!/(4!)⁴`(3 对面 × 2 种朝向),精确 **1/8,580,495**,与表格逐位一致。

### 五魔(B8):OLL / PLL / LL 对,EP 与 CP 两格错

顶层 5 角 5 棱,朝向各差一个总和约束 → 3⁴ 与 2⁴,OLL = **1296** ✓;LL = **933,120** ✓。

排列这一半表格错了:它按 5! = 120 来分,写 `EP 24 = 120/5`、`CP 30 = 120/4`。但五魔的**每个面转都是
角上的 5-轮换、也是棱上的 5-轮换**(都是偶置换),所以角排列与棱排列**各自必为偶** ——
顶层各只有 A5 的 **60** 种。正确的档是:

| | 表格 | 本机 |
|---|---|---|
| EP 跳步 | 24 | **12**(60 模掉 5 个 AUF) |
| CP 跳步 | 30 | **12** |
| PLL 跳步 | 720 | 720 ✓ |

`720` 之所以还对,是因为 `120·120/(5·4)` 与 `60·60/5` 数值恰好相等 —— 乘积撞上了,两个因子都不是。
注意 PLL 也**不是** 12 × 12:AUF 是角棱共用的,EP 好了之后 AUF 就被用掉,角只剩 60 种,
`12 × 60 = 720`。

「各自必为偶」不是新主张:站内 `god_data` 把五魔写成 `20!·3¹⁹·30!·2²⁷`,那个 2²⁷(而不是 2²⁹)
折进去的正是这个 /4。测试里两种写法互推,并核对位数(69 位,1.01 × 10⁶⁸)。

## 1.15 B9 金字塔:strong bar 逐位命中,weak bar 十几种口径都复现不出来

表格 `Pyra` 页只有两行:`No strong bar 348053/933120`、`No weak bar 180/933120`,都没给定义。

### 面上什么和什么算相邻 —— 不看贴纸坐标图,块结构就定死了

金字塔一个面 9 格:3 个尖(不在这 933,120 里)、3 个轴块(三个倒三角)、3 个棱块(三个正三角)。
核心六格连成一个**轴、棱交替的六边形环** —— 同面两个轴块不相邻、两个棱块也不相邻,所有相邻都是
「轴 + 棱」。哪个轴邻哪个棱不必读图:

> 轴块 A 在顶点 V 上,3 格落在含 V 的三个面;棱块 E 在棱 VW 上,2 格落在同时含 V、W 的两个面。
> 于是 **A 与 E 相邻 ⟺ E 的两个面都在 A 的三个面里**(V 是 E 的一端)。

4 个轴 × 3 条邻棱 × 共享 2 个面 = **12 对邻居 / 24 条面内相邻**。这条推导与 `pyraminx_svg` 头部那张
ASCII 图无关(那张图与实测的槽位分类对不上:实测每面尖 = 0/3/6、轴 = 1/4/7、棱 = 2/5/8,是**按顶点**
分组而不是按行),所以宁可从群结构推,不抄图。

### strong bar = 一个拼好的「块」

一对相邻的(轴, 棱)共享两个面,于是天然分两档:只在一个面同色 = 面上看到的一根**棒**;两个面都同色 =
这条棱已经贴着这个轴块拼好了,是一个**块**。按「块」枚举全空间:

```
一个块都没有 348,053   ← 表格的 No strong bar,逐位命中
块数分布 348053 336408 172752 57248 14739 3192 600 96 15 16 0 0 1
```

顺带两条现场自证:**恰好 10 块、11 块拼不出来**(分布里那两个 0),而 12 块只有还原态那一个;
把「块」换成「翻转块」(棱在位但两色对调)再扫一遍,得到的也是 **348,053** —— 翻转是全空间上的双射,
两边必须相等,不等就是枚举写歪了。

### weak bar:定义清楚,但那个 180 不是任何一档

按「一个面上相邻两格同色」(还原的棱自然也算在内)枚举,**一根棒都没有的态是 1,897**,不是 180。
试过的口径与各自的「无此特征」态数:

| 口径 | 无此特征 |
|---|---|
| 面内相邻同色(24 条) | **1,897** |
| 同面任意「轴格 = 棱格」(含不相邻的,36 对) | 651 |
| 相邻 + 同面两条棱同色 | 96 |
| 相邻 + 同面两个轴同色 | 128 |
| 三格连成一行(棱 轴 棱)全同色,12 行 | 514,742 |
| 块(两面都同色)/ 翻转块 | 348,053 |
| 轴块已还原、只在 11,520 个棱态上数 | 483 |

一个都不是 180,最接近的一档也差着一个数量级 —— 不是舍入、不是差一。唯一像线索的是
`180 = 11,520 / 64` 正好整除(即棱空间的 1/64),但把轴块钉死在还原位再数,得到的是 483 而不是 180。
所以 weak bar 那格**存疑不采纳**,只把口径和我们自己的 1,897 落地(与 §1.13 斜转的 `0c..5c` 同样处理)。

顺带一个结构事实:**轴块还原时棒数恒为偶数** —— 这时每个面的两个轴块格都是该面颜色,一条棱只要在
某面显出该面颜色,就同时与两个邻居各成一根棒。所以那 483 个态的棒数分布里所有奇数档都是 0。
