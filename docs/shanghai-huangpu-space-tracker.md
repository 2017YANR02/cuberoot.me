# 上海黄浦江双岸场景跟踪

更新：2026-09-06。状态：完成首轮可行性与开源方案调研，尚未接入上海数据或开始城市建模。关联：[魔方空间总跟踪](cube-space-tracker.md)。

## 用户要求与边界

- 从北外滩出发，沿黄浦江向南，经陆家嘴、徐汇滨江至前滩；全程必须同时覆盖浦西、浦东两岸，能够连续切换视角和漫游。
- 延续现代写实、电影质感和多轮网页截图迭代要求；保留魔方摆放、移动、转动及天气系统。
- 本次先核实能否实现、寻找热门 GitHub 项目并记录计划。城市运行时代码、资产安装和模型导入尚未执行；海面打磨继续作为当前实现任务。
- “向南”描述镜头游览方向，不据此推断江水流向。徐汇滨江与前滩在黄浦江两侧，不能当成同一岸上的顺序站点。

## 连续范围与分段验收

以下为设计范围，精确边界及各模型坐标在数据检查阶段落图；不把官方“两岸 45 公里公共岸线”误作本项目的单程航线里程。

| 段落 | 浦西侧 | 浦东侧 | 主要验收画面 |
| --- | --- | --- | --- |
| A 起点与天际线 | 北外滩、苏州河口、外滩 | 陆家嘴滨江与核心高楼 | 北外滩望陆家嘴、江心回望外滩、双岸高空全景 |
| B 南下连接 | 十六铺、南外滩、董家渡 | 陆家嘴南侧、塘桥滨江 | 沿江连续移动到南浦大桥，岸线及桥体不跳变 |
| C 世博河湾 | 黄浦滨江至日晖港附近 | 世博滨江与后滩 | 河湾、桥梁、码头与两侧城市的连续关系 |
| D 终点片区 | 徐汇滨江、西岸沿线 | 后滩至前滩滨江 | 卢浦大桥以南的河道、徐汇滨江与前滩对岸关系 |

建议第一版详细走廊覆盖双岸各约 0.8–1.5 公里腹地，并为远处天际线增加低精度背景；这是设计预算，需按实际可见建筑修订。首个美术样段选 A，其余三段仍属于完整交付范围。

## GitHub 候选与选择

2026-09-06 通过 GitHub 官方仓库及 API 核实星数，后续会变化。软件负责渲染，不等于附带上海模型。

| 项目 | 本次星数 | 能解决什么 | 对现有项目的判断 |
| --- | ---: | --- | --- |
| [CesiumJS](https://github.com/CesiumGS/cesium) | 15,678 | 地理坐标、地球/地形、大范围 3D Tiles 流式加载与相机 | 最成熟的地理场景备选；换主渲染器需重新适配现有 Three.js 魔方、镜面与 ABYSSAL 天气 |
| [MapLibre GL JS](https://github.com/maplibre/maplibre-gl-js) | 11,555 | 矢量底图、地图交互，可作为路线与数据覆盖检查工具 | 适合地图视图；单靠建筑拉伸不满足写实近景目标，暂不新增第二套地图运行时 |
| [NASA 3DTilesRendererJS](https://github.com/NASA-AMMOS/3DTilesRendererJS) | 2,451 | 在 Three.js 中加载、调度与释放 3D Tiles，支持大模型分块 | 当前优先验证；星数少于前两者，但与现有 Three.js 最直接兼容 |

建议继续使用 Three.js，待实际数据样本通过后接入 NASA 的 3D Tiles 渲染器，保留 CesiumJS 作为数据兼容性与大范围地理能力的备选。本轮没有找到并核实一个同时满足“热门仓库、该河段双岸完整数据、写实精细建筑、开箱即用”的上海开源成品；不把搜到的数字城市演示当成交付级数据。

## 数据现状与缺口

| 层级 | 已核实的来源能力 | 上海目标河段仍须核实 |
| --- | --- | --- |
| 河道、道路和建筑轮廓 | [Geofabrik 中国 OSM 下载](https://download.geofabrik.de/asia/china.html) 提供可本地裁剪的数据 | 双岸覆盖、河道多边形闭合、道路及桥梁拓扑、地标是否完整 |
| 建筑底模与高度 | [Cesium OSM Buildings](https://cesium.com/platform/cesium-ion/content/cesium-osm-buildings/) 提供全球 3D Tiles 建筑；[Overture 建筑 schema](https://docs.overturemaps.org/schema/reference/buildings/building/) 定义轮廓与可选高度字段 | 不能以全球覆盖推断本河段逐栋有可靠高度；须统计缺失率、来源、数据日期，估计高度明确标记 |
| 地标近景 | 支持独立 glTF/GLB 地标覆盖底模；模型来源尚未确定 | 东方明珠、上海中心、环球金融中心、金茂、外滩历史建筑、白玉兰广场、南浦/卢浦大桥及西岸/前滩重点建筑的准确外形与材质 |
| 实景重建 | 3D Tiles 可承载摄影测量模型；[Google 官方覆盖说明](https://developers.google.com/maps/documentation/javascript/3d/coverage) 区分全球地形与有限的精细表面覆盖 | 尚未实测上海具体覆盖，也未取得全段可用 tileset；不承诺接一个 API 就有整段写实上海 |
| 滨水细节 | 当前仓库已有海水与天气渲染 | 江水色、短风浪、岸墙、水位、码头、船只、尾流及桥下阴影；大洋长涌浪与沙滩冲浪不能直接套给黄浦江 |

地理范围参考：[上海“一江一河”十四五规划](https://www.shanghai.gov.cn/2021hffwj/20210830/6a27a89d0f2540a79a8e58ed3ea3a7e9.html)，该文件明确外滩—陆家嘴—北外滩及世博—前滩—徐汇滨江的空间联系。它用于范围核对，不是可下载的三维城市资产。

## 实施顺序与验收门槛

- [x] 记录双岸完整范围、现有 Three.js/天气兼容边界及热门项目比较。
- [ ] 裁剪真实河道与双岸建筑样本：先 A 段，再检查 B/C/D；记录范围、日期、数据大小、高度完整率、地标缺口。
- [ ] 核实坐标系与高程基准，统一到 WGS84/局部米制坐标；不同来源不能直接叠加造成岸线、建筑错位。
- [ ] 验证实际 tileset 的层级细节与加载释放；采用局部原点/随相机重定位避免长距离浮点抖动，限制同时加载范围，不把全城一次塞入 GPU。
- [ ] A 段完成写实样段：地标比例、玻璃/石材、植被、码头、江水、晨昏/雨天/夜景；从真实照片可辨认同一地点。
- [ ] 连续扩展 B/C/D 两岸，并建立完整江心航线、沿岸地面视角及鸟瞰；不得以孤立地标传送代替连续城市。
- [ ] 接入现有天气与魔方交互，江水采用独立于外海的参数和岸界；需考虑河道宽度、岸墙及船只尾流。
- [ ] 多轮固定机位对照：每段双岸近景、跨江远景、桥下及转弯处；逐项记录截图、缺口和修正，不能用蓝色发光楼块代替写实验收。
- [ ] 桌面与 <480px 实测：冷启动、沿江持续漫游、往返重复加载、帧时间、纹理/几何体数量、触摸操作；30fps 为初始移动端目标，需真实设备验证后才能宣称达到。
- [ ] 保存/恢复、天气切换、魔方转动/撤销及资源释放回归；总跟踪表同步实际完成状态。

质量分层：第一层是地理关系正确且可连续漫游；第二层是地标和主要双岸街区可辨认；第三层是电影级近景与光照。前两层通过不代表第三层完成。全城逐栋 1:1、每栋室内、真实水动力/交通仿真不在本次已明确的范围内。
