# 统一指法记号契约

更新：2026-09-13。适用 `/alg`、教程、`/sim`、公式导入/导出和 AI 编辑。

保留富文本与纯文本两种记号，共用同一套指法含义。本文是跨功能的语义与转换事实源；模拟器的握姿、动作轨迹、接触和穿模验收由 [FINGERTRICKS.md](../core/packages/client/app/[lang]/sim/engine/hands/FINGERTRICKS.md) 负责。

**规范、解析支持、动画支持分别记录。本文不代表转换器或动画已经实现。** 修改实现时同步第 5 节状态；不得用“能剥除记号并转动魔方”代替“能执行指定指法”的验收。

## 1. 一步指法的含义

| 信息 | 约定 |
| --- | --- |
| 转动 | 保留原转动，包括 `2` 后的撇号；终态相同不代表用指和行程相同 |
| 手别 | `L` 左手、`R` 右手；没有指定时保留未指定，由握姿与动作规则决定 |
| 手指 | `1` 拇指、`2` 食指、`3` 中指、`4` 无名指、`5` 小指；`h` 整手 |
| 动作 | 推、拨、滚动、单指连拨、双手连拨分别表达；没有标记时采用适用的默认动作 |
| 握姿与路径 | 单独记录；明确指定的握姿、接触点和相序不能被默认映射覆盖 |
| 原始记号与来源 | 保留原文本、原 `algHtml` 及采用的约定；未知或冲突标记必须可追溯 |

删除线 `U'` 明确的是“中指”，不单独指定左右手或“推”；`U'p` 明确的是“推”。手指标记与动作标记可以组合，但可表示不等于已有动画。不能把以上信息压成一个“特殊指法”布尔值。

## 2. 富文本记号

证据：[原教程指法表](../stats/tutorial/posts/finger-toe-tricks.json)、[CFOP 指法记号表](../stats/tutorial/posts/cfop-tutorial.json)，以及用户确认“删除线表示用中指做”。这些 JSON 中的 `<u>`、`<s>`、`<em>` 承载记号，不能只搜索“下划线”等文字名称。

| 写法 | 含义 | 转换条件 |
| --- | --- | --- |
| 删除线 `<s>…</s>` | 中指 `3` | 不凭线型推断手别；不表示删除转动 |
| 斜体 `<em>…</em>` | 拇指 `1` | 不凭斜体推断推或拨 |
| 普通下划线 U / U'，且来源明确为推法 | 推 U / U' | 可对应 `Up` / `U'p` |
| 普通下划线 D / D'，且来源明确为推法 | 推 D / D' | 可对应 `Dp` / `D'p`；原教程有下划线 D' 和左无名指推 D' 的说明 |
| 下划线 R、U2' 等 | 原教程还用来表示滚动、单指连拨、反拨 | 结合具体转动和原文说明；禁止统一改成 `p` |
| 下划线 F2' | 原教程有双手连拨用例 | 保留双手接力语义，不能当成单指推 |
| 波浪线 `<u class="wavy">…</u>` | 当前未确认完整映射 | 必须区别于普通下划线，保留原标记；不可因导入结果同为 `<u>` 就猜含义 |
| 加粗、上下标 | 未建立通用指法对应 | 保留格式，不擅自赋予指法含义 |

原教程还有下划线 M/M2/U 等复用记号的情况；当前导出格式不足以唯一判定时，保留原文并标记未解析，不扩展猜测表。历史实例可能依赖握姿和单手项目，不能套用双手中手默认值。

## 3. 纯文本记号

### 推法后缀

统一使用小写 `p`，紧跟完整转动：`U'p`，不用 `pU'` 或 `U' p`。以下是双手中手下的目标对应：

| 纯文本 | 指法 | 富文本对应 |
| --- | --- | --- |
| `Up` | 左食指推 U：`L2` + 推 | 下划线 U（推法用例） |
| `U'p` | 右食指推 U'：`R2` + 推 | 下划线 U'（推法用例） |
| `Dp` | 右无名指推 D：`R4` + 推 | 下划线 D（推法用例） |
| `D'p` | 左无名指推 D'：`L4` + 推 | 下划线 D'（推法用例） |

D'p 的用指在原教程有明文；Dp 是对应的左右镜像规格。其它握姿、单手项目、180° 推法和其它转动的 `p` 不据此自动推定。

### 手指、路径与换握

- 明确手指和路径沿用 [FINGERTRICKS.md §7 的 FTN `[...]` 规范](../core/packages/client/app/[lang]/sim/engine/hands/FINGERTRICKS.md)，不再为中指、拇指另造一套字母后缀。
- FTN 使用 `L3` / `R3` 表达中指、`L1` / `R1` 表达拇指；删除线或斜体自身没有手别和路径，不能凭空补齐成可执行 FTN。仅指定手指、不指定路径的短写尚未实现，也未在本轮另立语法。
- `p` 与 FTN 中的推技法 `.p` 表达同一动作；FTN 的完整表达能力与当前解析器支持范围必须分开（第 5 节）。
- `/sim` 的 `↑↓·` 按现有空白规则判断手别：紧贴后续字符为右手，后随空白或串尾为左手。原文空格必须保留。
- **历史冲突**：原教程 `↑↑/↓↓` 表示上上手/下下手；现有模拟器将相邻箭头逐个按空白手别规则执行。导入时标记来源约定，禁止将教程双箭头原样传入后宣称握姿已正确转换。单箭头在历史文本中也不能仅凭排版空格推定手别。

## 4. 统一处理与 AI 编辑规则

1. 先读本文，再读所改运行时的实现。记号含义查教程表和用户明确约定，不能仅从按钮名或 HTML 标签名推断。
2. 富文本和纯文本都应先解析出第 1 节的信息，再选择显示或播放方式；不让 HTML 标签直接成为动画枚举，也不让动画反过来定义历史记号。
3. 仅在含义确定且目标写法能完整表达时转换。删除线/斜体、波浪线、接力、握姿等无法用 `p` 表达的信息必须保留；不能输出一条纯公式就声称指法已无损保存。
4. 同一动作角色的互斥标记（如既要求仅拇指又要求仅中指）应报告冲突并保留原文，不静默选一个；不同维度（如中指 + 推）可以组合。明确指定的多指协作、不同阶段接力或双手并发须分别保留，不当作冲突。明确指法优先于默认用指，但仍需检查握姿与动画能力。
5. 区分“仅转动公式”与“带指法公式”导出。求解器/状态计算可剥除手部记号；带指法复制、存储、转交 AI 时须保留语义和未解析的原始标记。沿用当前 `alg` + `algHtml`，本规范不要求迁移 DB 或覆盖历史数据。
6. 镜像、逆序、合步后重新核对手别、手指、握姿、接力及贴块路径；不能只改魔方字母后原样附回指法。不能无损变换时报告未支持，保留源数据。
7. 新增记号时先补本文的含义、适用条件、对应写法、未知/冲突行为及实现状态，再改唯一解析入口与消费者；不得在各页面复制一份转换表。
8. 验收分别检查格式保留、语义解析、纯转动终态、实际用指、动画接触和穿模。未知指法即使按默认动作播放，也须作为未支持记录，不得当作指定指法已通过。
