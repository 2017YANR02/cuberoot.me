# 魔方空间跟踪

更新日期：2026-09-06

## 当前目标与范围

- 基于现有 Three.js `/space`，复用 `/sim` 的魔方模型，让用户摆放、移动魔方并切换视角。
- 八种可选场景：镜面简约、赛博朋克、现代住宅、复古宅邸、意大利别墅、纽约顶层公寓、日式庭院、我的公司。风格选择和魔方布局一同保存。
- 住宅保留 U 形主体并增加东侧配套翼，客厅、书房、卧室、卫生间、车库、影音室、健身房、庭院和建筑外观均有直接入口；高层场景加入承托完整建筑的楼体和城市。公司按用户提供的六张实拍重建办公室 406、公共休息区和电话亭。
- 用户随后要求多轮迭代，场景必须非常精美、有电影质感。功能可用与画质达标分开记录，不能用测试通过替代美术验收。
- 顶级大别墅与公司复刻仍以画面为验收依据；已有完整四房间网页，家具、植被和灯光尚未达到离线概念图的写实程度。公司尺寸由照片推算，不能标为已完成 1:1。
- 魔方必须能真实转层：复用 `/sim` 的模型和手势判定，保留摆放旋转与拧魔方两个不同操作模式；动作支持撤销、重做、刷新恢复及导入导出。
- 可切换 19 种天气，天空、室外粒子、雾、光照及露天材质联动；天气和动态开关随布局保存。极端天气为视觉演示，不含建筑破坏或流体物理求解。
- 六段提示词和三张概念图保留作为美术参考；下文另外记录真实网页截图。概念图不等于网页画质承诺。

```text
Use case: stylized-concept.
为可交互 Three.js 魔方空间设计房屋环境概念图，写实建筑可视化，精细但清爽的高品质 3D 渲染。
生成一张宽幅 2:1 双联图，两个等宽画面之间只有一条细分隔：左边完整建筑外观，右边同一建筑的室内。两张画面的建筑形体、窗框、材料和灯光必须一致。外观采用略抬高的三分之四视角，室内采用约 26mm 广角的房间角落视角，垂直线端正，不用鱼眼。
房间是可以进入和环绕观察的真实封闭建筑空间，有墙、顶、门和窗；中间留有大片连续地面用于拖动、摆放魔方。魔方为独立可移动物体，建筑本体用方块比例和网格呼应魔方，但不把整栋房子变成一颗玩具魔方。
核心是非常鲜明的镜面反射：地面清楚倒映魔方、窗框和灯光，镜墙反射有正确透视，镜面金属有真实高光。镜面、透明玻璃和哑光结构在视觉上可以分辨；不做泛白过曝，不让反射掩盖物体边界。
放置标准彩色三阶魔方和金色镜面魔方，面片分格清楚、几何规整，颜色鲜明；适量展台与低矮家具，保留走动和交互空间。
无人物、无文字、无标签、无品牌、无水印、无网页按钮或 HUD。概念图只呈现房屋和魔方。
```

## 初版实装边界（历史记录，以下限制已由最新迭代更新）

- 图中的高质量建筑反射是视觉目标；浏览器实时效果需要在设备上验证，不将离线概念图当作实测性能承诺。
- 三套房间使用相同尺寸的摆放区，模型、布局和操作复用现有实现。房间风格独立于网站明暗主题，工具栏和选中提示继续使用全站主题。
- 房间应留出可摆放的连续地面；镜墙与真实空间边界必须可辨，避免拖动和视角操作混淆。
- 生成图中的魔方分格和配色仅作占位，部分未严格符合真实魔方；实装继续使用现有模型，不照图重建魔方。
- 室内视角显示屋顶并限制相机在房间范围；全景、正面、侧面、俯视使用剖开屋顶的编辑视图，后方观察时隐藏背墙。外观视角显示完整建筑。
- 镜面使用 Three.js 已安装的 Reflector，每面只反射一次，避免镜墙之间无限递归；桌面镜面纹理为 1536，窄屏为 768，静止时不持续渲染。
- 环境高光由当前房间烘焙生成，切换风格时刷新；不包含可移动魔方，魔方的实时倒影由平面镜承担。无外部 HDR、贴图或模型下载。
- 当前是程序化建筑原型，保留原布局允许的室外庭院摆放。没有家具碰撞、魔方堆叠或步行导航；原有展台仍通过包围盒承托魔方。转层交互暂未开始。

## 第十一轮：ABYSSAL 天气接入与六轮视觉迭代

2026-09-06。用户回复“可以 接入”，接受上一轮提出的 ABYSSAL 方案。本轮将天气子系统接入实际 `/space` 场景，使用已有 Three.js，不是 iframe，也不是仅下载演示。

### 实际接入范围

- 上游 [ABYSSAL](https://github.com/Token-Gremlin/natural-disasters) 固定版本 `d2bae38301ff43bc1d43bfdfd9477a552ca5420b`。天气源码位于 `space/abyssal/`，保留 MIT LICENSE，改造清单见 `UPSTREAM.md`，统一致谢已登记。未增加 npm 依赖，程序化纹理在本地 GPU 烘焙，无运行时 CDN 依赖。
- 使用上游 Weather、大气散射查找表、体积云射线步进、SkyRenderer、实例化雨幕、递归分叉闪电和体积龙卷风；闪电联动云层与建筑补光。原有本地天空、雨线、闪电和龙卷风实现由这些模块替代。
- 保留全部 19 个天气预设及现有存档契约。雪、冰雹、沙尘、泥石流、彩虹和表面湿润/积雪仍是本地补充，不宣称这些来自 ABYSSAL。未引入上游海洋、浪花、海啸或演示导演系统；没有真实建筑破坏或流体模拟。
- 共享 uniform 改为场景实例持有，增加烘焙取消与渲染资源释放；主相机使用屏幕空间云，镜面使用独立的全景云探针，天空、闪电条带和龙卷风使用各自渲染相机。雨幕遮挡直接复用房屋平面与公司的屋顶范围。
- 桌面雨幕预算 24,000，窄屏 9,000；云使用半分辨率，宽度最多 900 像素，反射探针最多每秒更新四次。天气调度仍约 30 帧/秒上限；这些是预算，并非实体手机的实测帧率。

### 实测结果

- client `typecheck` 通过；`vitest run tests/cube_space.test.ts` 共 14 项通过。新增检查覆盖上游闪电实例隔离、活动/排队闪电清除与残余闪光归零，保留全部九类魔方与 19 种天气存档回归。
- 真实菜单完成八种风格乘 19 种天气的 152 个组合；引擎均为 ready，未发现着色器编译失败。结果见 [验证数据](../core/.tmp/png/abyssal-validation.json)。现代住宅全部 19 种留存截图；功能切换通过不等于每个画面都通过写实验收。
- 暴雨中点击三阶 `R`，已保存动作从 `R` 变为 `R R`，天气时间继续推进；撤销后完整布局 JSON 与转动前一致。客厅、卫生间、公司办公室分别检查了室内遮雨。
- 关闭动态天气及模拟系统减少动态效果时，天气时间均稳定在 `32.2345` 秒，待渲染帧、闪光强度、活动闪电与排队闪电均为 0。
- 相同现代外观机位连续两轮“晴天→泥石流→龙卷风→下雪→晴天”，几何体计数每轮均 `419→422→420→420→419`，纹理均为 88，没有逐轮增长；计数不等于显存字节数。
- 375px 重新加载确认窄屏雨幕预算为 9,000，雷暴中实际实例数 9,000、云启用、无着色器错误。375px/320px 天气菜单均有 19 项、可滚至末项、边界在视口内，没有横向溢出。
- 最终自然雷暴观察窗口 6.5 秒内出现一次闪电，最多 322 个通道片段，建筑闪光峰值 `0.9315`；该检查没有延长或手动触发闪电。最终浏览器错误和警告均为 0。
