# 聊天助手的回答与工具设计

核对时间：2026-10-23。实现入口为 `core/apps/api/src/utils/site_assistant.ts`，工具输入契约在 `site_assistant_tools.ts`，模型适配在 `site_assistant_model.ts`。本页描述设计与能力边界，不以文档替代线上配置或实测。

## 采用的通用架构

同一个对话模型负责理解问题，并按需要选择直接回答、站内检索、结构化数据工具或联网搜索。解释、翻译、写作、一般交流不必先查知识库。网站入口、用户成绩、最新事件等外部事实必须通过对应工具取证。工具能力以可复用的数据操作定义，避免为每种问法添加分支。

RAG 是获取站内资料的一种工具。数据查询承担筛选、去重、聚合和计算；联网搜索负责公开站外信息。工具输出保留来源与范围，空结果、失败和缺少资料分别处理。对话历史用于理解追问，身份由认证上下文提供，不根据模型猜测用户身份。用户停止、时限、调用次数与成本预算贯穿整个请求。

## 思考、上下文与交互

2026-10-26 本地改进（基线 `a387bd0096543427058996ba32087a1cd823b3a0` 加未提交修改）：工具说明只在原生工具契约中发送一次，已进入工具对话的结果不再重复塞进上下文；服务端补充实际 `runtime.model/provider`，模型身份不靠猜测。普通查询结束后不再额外做一次模型复核；现场分析仍必须核对口径和实际输出。实现与实测限制见 [第二阶段记录](benchmarks/site-assistant-phase2-2026-10-26.md)。

计算器从表达式和中间关系推导计数单位，例如成绩轮次、比赛、选手、城市名称；模型自拟表头不能证明统计口径正确。独立复核返回 `reviewedSourceIds`，未经复核或明确未通过的分析表不得展示；保留经过复核的资料缺口说明与独立可回答部分。网站正文、新闻、联网、赛事与纪录等工具产生有效来源时，最终答案再做一次不可调用工具的证据核验，核验前不流式展示其草稿；已有分析复核的不再叠加该轮。普通聊天、导航与简单个人成绩读取不因此新增核验轮次。这里的语义复核仍由模型完成，不等于数学证明或保证所有答案正确。

站内资料检索默认排除 `/dev` 文档；明确的开发问题可以指定 `audience:developer`。检索同时保留原问题的约束，避免模型改写搜索词时遗漏关键条件。资料返回值明确说明片段覆盖不完整，缺少描述不能推出功能不存在。索引保留页面的功能描述，导航草稿缺少取证时先发现相关入口，再决定是否需要阅读正文。时区只解释日期，不作为用户所在地；“最近一个月”等时间范围不能被识别为结果条数。

| 用户选择 | 调用策略 | 总请求时限 |
| --- | --- | --- |
| 自动（默认） | 首轮快速；模型选择深入推理、结构化分析、联网证据综合，或回答进入核验/修复时启用思考 | 60 秒 |
| 快速 | 保持非思考请求；需要真实数据时仍调用工具 | 30 秒 |
| 深入 | 支持该能力的供应商从首轮启用思考 | 90 秒 |

模式偏好保存在当前浏览器。主对话与首页入口使用同一配置；监控区分用户选择和每轮实际调用参数。DeepSeek 与受支持的百炼 Qwen3.8 配置分别适配；未知兼容供应商不假装启用思考。思考过程不作为正文或监控内容展示。自动模式由实际工作触发，而非按一串问句关键词硬分流。

SSE 每 15 秒发送一次不可见的协议保活注释，避免深入思考期间没有正文而触发代理空闲断开；完成、失败或取消时清理。保活不会重置请求时限，也不会被算成首段回答。

客户端历史传输仍最多保留最近 10 条消息和 40,000 字符；服务端有合法父请求及记忆快照时，沿同账号、同会话的成功请求父链补齐最多 5 轮文本，不从会话最新记录拼接重新生成的旁支。模型请求再按强／弱相关性选择最近 5／1 轮，超预算强相关最低保留 2 轮（不足则全部保留）；未回答的用户消息独立保留，不能冒充完整轮次。具体分层、压缩与来源边界见下节。问题最多 8,000 字符，单次回答最多 12,000 字符。超长写作给出有实质内容、自然结束的第一部分，明确剩余内容，由用户继续触发下一段；不通过截断 JSON 伪造成功。已有图片、停止、编辑重问、重新生成和评价能力继续复用，服务端历史恢复不恢复图片字节，仍由客户端传入经过鉴权的图片。

客户端按最终 JSON 的 UTF-8 字节数控制 3,300,000 字节请求预算。超限先移除旧历史，不改写本轮问题和图片；仍超限则发送前明确报错。兼容旧服务的重试只在 `400 invalid_question` 且未进入付费调用时移除新增字段；已接受的请求不会隐式重发。

实际网站行为必须读取页面内容，导航目录只证明目标入口存在。尚未取证的站内解释不会先流式展示。来源由数据适配器提供，模型只能选择来源 ID；无效来源不会回退成“引用全部已读资料”。对话、检索、失败、用量及搜索费用继续写入现有管理员监控，详见 [监控口径](../../operations/observability/assistant-monitoring.md)。

## 停止、补充与消息引用

2026-11-15 第一里程碑实现，尚未部署。用户消息以独立 `messageId` 保留；停止、失败或尚未输出回答不再删除原问题。后续请求只自动携带完整回答，未完成文字仅保留展示；显式引用时以用户材料传递。历史仍受上述消息数、字符数和传输预算限制。

Web 在执行中继续允许输入、添加图片与引用；第一里程碑中，有草稿时显示“停止并发送”，旁边保留停止按钮。发送补充先取消旧执行，等服务端终态且旧请求结束后，携带原问题、补充和引文重新回答。停止尚未确认时保留输入及引用，不自动启动新任务。停止等待期间禁止重复提交，允许继续编辑草稿；该交互已由下述第二里程碑的持久收件与任务补充替代。

`POST /v1/site-assistant` 的 `runId` 在上传和请求之前生成，并与 `conversationId` 配对。`site_assistant_runs`（迁移 `0334`）独立于脱敏监控，只保存归属、执行状态和时间；携带 run ID 的新协议请求中，同账号同会话的运行／停止中执行由数据库唯一索引串行化。重复 run ID 不会再次调用模型。`POST /v1/site-assistant/runs/:id/cancel` 接收取消，`GET /v1/site-assistant/runs/:id` 查询实际状态；两者鉴权且核对账号归属。取消早于请求入库时保存停止标记，阻止迟到请求启动。

执行进程每 250 ms 串行读取取消状态，通过本轮 AbortController 传入模型和工具。控制接口跨进程共享 PostgreSQL 状态；`stopping` 只表示已接受取消，执行 Promise 退出后才能标记 `cancelled`。完成与取消通过同一行的原子更新裁决；旧执行不能覆盖新执行或误取消新任务。两分钟失效执行标记 `interrupted`，不能伪称已停止，迟到结果也不能提交。终态记录在该账号下次启动／取消时清理一天前的数据，账号注销级联删除。此表不承诺任务恢复或跨设备恢复消息。

消息和选区引用保存 `messageId`、`messageVersion`、原角色、`selectedText` 和 `sourceStatus` 的固定快照。输入框可移除引用或跳转原消息，发送后保留引用关系；回答引用包含正文及可导出的结构化结果。超过 12,000 字符时要求选择较短片段，不静默截断。当前消息存储仍由浏览器维护，因此服务端明确将所有此类引文标为“用户提供、未核对服务端原文”，不把消息 ID 当成读取其他用户数据的凭据，也不把引文中的指令或事实升级为系统指令／可信证据。当前显式引用单独进入模型输入，不参与普通历史窗口裁剪；不支持新协议的旧后端返回错误，禁止兼容重试悄悄丢弃引用或 run ID。

OpenAI 的 Chat Completions 与 Responses 中转函数已在 `vercel.json` 显式配置 `supportsCancellation`；这是 [Vercel Node.js 取消机制](https://vercel.com/docs/functions/functions-api-reference#cancel-requests) 所需的部署配置。源码继续传递 `request.signal`，本地测试覆盖首段输出前中止及流式透传；Vercel 部署后的断连传播和供应商侧停止／用量仍需线上验收。

本地验收：真实 PostgreSQL 隔离 schema 检查跨实例取消、完成竞态、归属与唯一约束、过期执行及迟到结果；前端回归检查未回答需求保留、停止未确认时保留草稿、旧消息选区引用和流式快照；模型传输夹具确认引文原样进入用户上下文而非系统提示。Chromium 在实际 `/zh/chat` 页面使用隔离账号及 SSE 夹具走通“统计 → 引用 → 停止并发送 → 新回答”，并检查 390px 与四种深浅主题组合；未调用生产模型或写入生产聊天数据。

### 第二里程碑：持久收件与恢复（2026-11-15，仅本地）

Web 改用 `conversations/:id/messages` 持久收件接口，消息 UUID 重试去重；收件提交后返回 202。运行中的消息可选择“调整当前任务”或“加入队列”。关闭页面、刷新和网络断开不取消服务端任务；停止操作暂停当前任务和整个队列，执行结束确认后可恢复。旧流式接口继续供已有客户端使用。

迁移 `0335_assistant_durable_queue.sql` 保存账号隔离的会话、按序消息、工具检查点和进度。API 后台 worker 每 2 秒扫描待办，PG 行锁与 45 秒执行租约串行化同一会话，每 750 毫秒检查停止与续租；HTTP 服务正常关闭时释放租约，进程异常退出在租约过期后恢复。所有进度写入和最终提交检查租约；最后答案还检查补充消息序号，不能越过新要求。恢复前重新检查账号绑定及封禁，模型调用继续走日配额、超时、供应商和地区准入。

补充要求在下一个工具／模型步骤开始前按接收顺序应用，正在运行的步骤先结束。最终答案前再次核对收件序号。恢复重新规划任务，复用已成功读取、参数相同且五分钟内的工具结果；页面、分析、联网及图片工具另绑定完整请求范围。改动筛选参数、明确要求刷新／最新数据、失败、部分结果、超时和过期证据重新读取。每任务最多保存 10 个工具结果、350 KB 检查点，用户界面标明复用；不保存或恢复供应商内部推理状态，不保证已发出的上游请求只执行一次。

每会话最多 100 条消息、每个活动任务最多 8 条补充；累计问题限制 24,000 字符，图片最多 3 张、引用最多 9 条且累计不超过 36,000 字符，超限拒收且保留输入。自动恢复最多尝试 3 次，失败暂停后由用户恢复；任务正文和检查点保留至会话闲置 30 天，账号删除级联清理。检查点及模型历史不通过状态 API 返回，图片继续只保存私有附件引用。状态按单调版本返回，未变化时返回 304；前端拒绝迟到的旧版本。浏览器保留最近 30 个未置顶会话的入口与未确认发送标识，以便刷新后重新读取服务端状态。

2026-11-15 真实模型本地验收：使用百炼 Qwen、隔离 PostgreSQL、真实 Hono/worker 与站内公开工具读取，验证连续两条补充、刷新保留、停止后恢复及强制结束 API 后租约恢复；参数不变时复用检查点，数量从 3 条改为 1 条时重新取数。修复了旧数量覆盖补充要求、模型重试前未检查新消息、跨语句误判只给链接、持久 worker 首进度／首回答计时遗漏及回答换行被页面折叠的问题。该验收只覆盖选定场景，不代表任意模型指令均可确定执行，也不代替未来生产迁移和发布验收。

本轮不改小程序与安装客户端交互；尚未部署，不代表生产环境已具备上述能力。

## 独立会话并发与模型恢复（2026-11-16）

持久 worker 收件后立即认领所有可运行的独立会话，取消原来的 4 个执行槽；扫描期间的新收件触发补扫，不必等待 2 秒兜底轮询。旧问答接口同时取消全站 4 个并发、30 次/分钟和共享 IP 限额。每账号短时保护仍保留：旧接口 6 次/分钟，持久收件 30 次/分钟；全站每日 1000 问和同一会话的顺序、租约、停止与账号隔离不变。解除应用准入上限不等于供应商 RPM/TPM、数据库和机器容量无限，实际高峰延迟仍需发布后测量。

模型步骤的短暂网络错误、429 和 5xx 在同一截止时间内最多重试两次，使用带抖动的指数退避并遵守短 `Retry-After`；超过 5 秒的供应商等待要求直接保留失败，不提前重试。输出格式另有一次修复预算，不因网络重试切换为更慢的思考模式。单个字符串来源 ID 可无损转为数组，一般回答未提供来源时归一为空数组，之后仍执行来源与证据校验；不补造来源、不接受截断回答。Qwen 低强度思考预算为 1024 tokens，较高强度保持 4096，减少简单复核耗尽总时限的风险。额外重试可能增加模型费用，且不能保证供应商持续故障时仍成功。

本地回归覆盖 32 个账号同时通过旧接口、13 个独立会话同时执行、扫描期间收件、账号或模型失败时的会话隔离，以及连续两次上游故障和格式修复；这些是隔离夹具验证，不是生产吞吐量或延迟测试。发布状态及线上容量以对应提交的部署和实测记录为准。

## Memory Graph 与分层上下文

2026-11-15 本地实现，基线 `b625db4d19`；尚未提交或部署。已完成 [48 条真实模型对照](benchmarks/assistant-context-evaluation-2026-11-15.md)：本组完整达标 15/24 → 21/24，总 token 减少 10.1%，但耗时中位数和 P95 变慢，不能宣称整体提速或普遍降本。只作用于站内助手，不修改开发工具 Codex 的提示词、记忆、配置或 Hook。实现为 `core/apps/api/src/utils/site_assistant_memory.ts`，通过 `site_assistant_model.ts` 接入每次真实模型请求，通过 `site_assistant_context.ts` 复用私有快照存储。

同日后续已修复词条定义被误套页面引用义务、部分无关公式预取与显式分钟总额检查。[72 条复测及 12 条边界补测](benchmarks/assistant-context-followup-2026-11-15.md)比较上一版 Memory Graph：主表完整达标 29/36 → 34/36，总 token 减少 17.2%，平均完成耗时 2.13 → 1.64 秒；首次答案中位数 0.88 → 1.15 秒，因受限计划先校验后展示。普通成功问题的平均耗时基本持平，不能外推为所有问题提速；仍未发布。

最新本地候选在同次百科读取中补入最多 4 个唯一的一跳缩写释义，原文与派生全称分开并绑定全部来源；歧义、缺失或预算裁掉依赖时不保留展开。受限计划默认减少重复说明，详细格式仍服从用户要求，展示前校验不变。[88 条对照及 8 条最终补测](benchmarks/assistant-context-expansion-latency-2026-11-15.md)中，主表完整达标 37/44 → 44/44，首答中位数 1.502 → 1.304 秒；简单受限计划为 2.061 → 1.502 秒。总 token 仅下降 0.7%，部分百科和详细计划变慢；这些开发样本不证明普遍提速或任意约束均可强制执行。仍仅本地。

后续本地优化让明确的百科缩写查询直接进入既有读取和隔离核验链路，省去模型选择工具的一轮；混合页面义务与最终校验保持。详细计划减少父子层重复说明，明确要求的步骤、理由与字数仍保留。[同步后 104 条对照及 4 条查询补测](benchmarks/assistant-glossary-plan-latency-2026-11-15.md)中，百科组平均 2.688 → 1.748 秒，详细计划组 3.046 → 2.788 秒，总 token 减少 20.7%。完整达标 48/52 → 49/52；仍有复杂计划错误假设、子步骤数量不符及一次超出词条证据的附加条件，不代表语义约束已全面解决。仍未提交或发布本轮修改。

复杂计划后续加入明确列表数量与英文词数检查，静态状态指导服从当前转动权限，无外部证据的格式返修保留草稿、避免自动重核验；闭合词条字段请求只渲染已读内容及完整展开来源。[120条主测与8条定向补测](benchmarks/assistant-plan-source-contracts-2026-11-15.md)按最终生效路径覆盖，完整达标49/60 → 55/60，复杂计划7/12 → 9/12、平均3.413 → 2.846秒。预设分组耗时门槛通过，但整体完成中位数增加约132毫秒，仍有5条来源语义、领域细节或子项算术未完全达标；不代表语义校验已完备。本轮仍仅本地。

| 当前需求 | 保留本轮原始问题和图片；关联到的旧用户限制单独保存原句，当前纠正优先 |

| 滑动窗口摘要 | 从窗口外片段选择完整去重句子，传输时每个角色片段最多 280 字符，标注角色、来源轮次和覆盖是否省略；不递归生成摘要，不携带持久化索引与问题 hash |
| 活摘 | 根据问题中的实体找到旧片段，再沿连续追问关系扩展一跳；只召回关联片段，不载入整张图 |
| 长期记忆 | 本轮只承载用户明确声明的持续语言、详略偏好；同类较新偏好替代旧值。公共稳定知识仍经现有 RAG 工具读取，不自动把对话断言变成事实 |
| 历史主题 | 仅保留未展开片段的实体标签及轮次指针；没有内容时不发送 |
| 资源／RAG | 复用现有站内检索、知识库、网页和数据工具；必要证据及当前工具调用／返回对作为预算固定部分，不裁掉引用正文而保留引用资格 |

图保存至已有 `assistant_context.memory` JSON 字段，无新数据库表、图数据库、供应商或依赖。节点为会话片段及其实体索引，关系为连续追问；片段携带用户问题的脱敏 hash、原角色、摘录及来源 ID。来源 ID 只用于追溯，不能凭旧摘要直接取得本轮引用资格。图最多 24 个片段、20,000 UTF-8 字节，整个证据快照仍限制 48,000 字节；持久化超限优先淘汰派生片段，证据快照没有空间时省略可选图。该保留上限不代表无限历史记忆。

相关性最终只有 strong / weak。当前分类使用多语言分词、显式标识、实体交集和追问指代规则，无额外付费分类调用；这是可测试的初始检索策略，不保证理解所有同义改写。最近窗口之外的同主题内容由实体关系召回。客户端历史仅在首次建立图时补充旧片段，之后以经过账号、会话、父请求验证的服务端图为准。用户／助手文字始终是带归属的会话数据，不提升为系统指令；独立证据复核不携带图中的旧助手正文。

每次模型调用都重新估算系统提示词、当前需求、历史、工具 schema、当前工具调用链、资源及图片的输入成本。`SITE_ASSISTANT_CONTEXT_WINDOW_TOKENS` 默认 64,000，可由服务端配置；它是编排上限，不是宣称模型窗口。预算扣除输出预留和 2,048 安全余量。文本按 ASCII / 非 ASCII 混合估算，图片每张暂预留 4,096 tokens；这些是保守工程估算，供应商实际计数继续由原用量监控记录。

超预算依次移除历史主题和长期记忆、活摘、滑动摘要，最后将最近强相关完整对话从 5 轮逐步降到 2 轮，弱相关保留 1 轮。相关的旧用户限制保留原句。系统提示词、当前问题和当前必需工具证据不截断；最低集合仍超预算时，在发出该次模型请求前返回既有 `request_too_large` 错误，不隐式重试付费请求。已有资源工具继续在采集边界按 `site_assistant_evidence.ts` 限制可选资料和引用资格。

图沿用私有上下文的 30 天 TTL，沿父链继承时不续期；不跨账号、会话或重新生成的兄弟分支读取，不扩大历史授权。清理、账号删除及磁盘 completion journal 重放继续复用现有流程。生成物不进入 JSON/SSE 正文、公开分享或知识库。凭据脱敏与监控共用 `site_assistant_privacy.ts`；不宣称任意自然语言都已匿名化。

对可识别的阿拉伯数字分钟上限，计划生成时明确传入总额，并在展示前核对顶层列表的分钟分配之和；超限只修正一次，仍超限返回输出错误。总项与嵌套子项不重复计时，上限所在分句区分总额和每项限制，当前更正优先。该保护不等于任意自然语言约束的全面执行保证；其他单位、自由正文中的附加活动与一般语义要求仍需模型遵守和进一步验证。

监控 `metrics.contexts` 只记录相关性、轮数、各层条数、估算 token、预算与压缩步骤，不记录摘录正文。定向测试覆盖窗口、压缩次序、超限拒绝、来源隔离、脱敏、真实供应商请求格式（mock）、父链恢复和 PostgreSQL 用户／分支／过期边界。真实模型对照使用同一模型、合成历史和冻结公开资料；尚未覆盖真实流量分布、数据库恢复耗时、生产向量 RAG 及浏览器体验。约束执行、标题证据核验和前置历史解析的缺口见上述评测记录；单元测试不作为效果证明。

## 联网搜索适配器

`site_assistant_web.ts` 仅调用固定受信的百炼北京端点，使用 `qwen3.8-flash` 的原生 `multimodal-generation` SSE 协议。发送短公开查询，不发送账号资料、完整聊天历史、图片或站内私有数据；明显凭据、邮箱、电话号码、图片数据及私有 URL 在请求前拒绝。当前账号标识与上下文中可识别的凭据只用于服务端拒绝列表，不发送给搜索供应商。该检查是有限的模式保护，不能宣称能识别所有自然语言中的私密信息。网页内容作为不可信数据处理，不具有操作指令权限。

一次搜索最多等待 16 秒、读取 512 KB、生成 1,200 tokens、保留 6 个有实际引用的安全 HTTPS 来源。请求同时受整个聊天的取消与截止时间约束；不抓取模型提供的任意 URL，不跟随带凭据请求的重定向，不自动重试付费搜索。来源必须同时存在于供应商 `search_info` 和引用标记中，不能用模型编造的 URL 充当来源。未引用的段落、引用不安全或已被裁剪来源的段落会丢弃，随后清除未再使用的来源。另要求供应商返回结构化的相关性判断：没有直接匹配问题的证据时丢弃综述和来源，不用其他话题填充；这个判断仍由模型完成，不等同于独立事实核查。

百炼此接口返回的是搜索来源元数据与模型整理的带引用综述，不是逐条原始网页片段。出版日期和原文片段没有结构化返回时保存为 `null`；检索时间不能冒充发布时间。Qwen3.8 的 `recency` 是搜索偏好，不是强制日期过滤。需要确定某周的 WCA 官方公告时，已有官方 RSS 工具可按真实发布时间筛选；广泛新闻检索不得把日期不明的旧闻标成当周消息。

配置默认复用完整的 `SITE_ASSISTANT_VISION_API_KEY` / `SITE_ASSISTANT_VISION_BASE_URL` 或 `SITE_ASSISTANT_API_KEY` / `SITE_ASSISTANT_BASE_URL` 百炼组合。可用 `SITE_ASSISTANT_WEB_API_KEY` / `SITE_ASSISTANT_WEB_BASE_URL` 显式指定；`SITE_ASSISTANT_WEB_MODEL` 选择适配器支持的 Qwen 多模态模型；`SITE_ASSISTANT_WEB_ENABLED=0` 禁用。配置、模型权限、来源返回中的任何一项不满足时，返回明确的不可用结果，不把内部配置或供应商错误正文暴露给用户。

模型 tokens 与搜索调用分别记账。百炼北京 turbo 检索的文档标价为每千次 3 元，另计模型 tokens；`usage.plugins.search.count` 是搜索意图次数，不代表结算次数，故只能用于保守费用估算，正式费用以账单为准。该事实与接口边界来自上述百炼官方文档，变更供应商或策略时需重新核对。

## 统计维护元数据

`statistics_metadata` 读取 API 自带的小型生成目录；`statistics` 继续读取统计结果。全目录调用返回登记总数、全部七类、覆盖缺口和来源 ID，按 id 读取附加产物合同及来源 SHA-256。登记覆盖 WCA 重聚合、历史排名/纪录、比赛打乱、精确分布/全状态数据、LSLL、双底 ZBLL 和求解表依赖；不宣称枚举了所有实验任务。

生成器为 [build-statistics-metadata.ts](../../../scripts/assistant/build-statistics-metadata.ts)，口径由 [definitions](../../../scripts/assistant/statistics-metadata-definitions.ts) 维护。cron/job 条件、HEAVY_STATS、命令及产物从对应配置提取；仓库级生成器只读取小型源码，API 运行时不跨包读取文件。修改来源后运行 `node scripts/assistant/build-statistics-metadata.ts --write` 并审阅口径；轻量 drift workflow 检查内容哈希，不启动计算。

成本/生成/更新问题优先预读全目录，补充实现资料使用 developer 范围。维护主张允许引用元数据；页面操作仍需页面正文，引用 ID 和最终证据复核保持有效。统一拒答原因写入已有请求 metrics.answerRejections。

配置视图默认不读取运行状态。`view:runtime` 通过固定公开地址独立读取 GitHub Actions、当前静态快照清单、历史排名 PG 导入时间、WCA 二进制数据截点及双底 ZBLL 清单。实际状态问题先读配置再读 runtime；引用运行事实必须选 runtime 的来源 ID。响应包含 observedAt，缓存最长 15 分钟；过期后读取失败不使用旧成功结果冒充当前状态。

WCA 最近运行只比较 main 的 schedule/workflow_dispatch，各取最近 10 次；代码 push 的语法检查不参与。最近成功在成功候选中最多核查 5 次的实际 attempt/job/steps，排除跳过生成或发布步骤的局部任务。较新候选读取失败时不把更老结果标为“最近成功”；找不到时明确 bounded-history 缺口。允许 stats_filter 的任务只证明选定范围的流程成功，不等于全部统计重算。

当前静态版本取实际服务中的文件清单 SHA-256，涵盖多个发布 owner，不能当成 WCA 专属更新时间、源码版本或数据库版本。独立的数据库导入时间可能晚于最近完整流程成功。发布结束由 [snapshot-deploy.ts](../../../scripts/wca-data/snapshot-deploy.ts) 在 active inventory 旁原子写 publication.json；读取端核对版本/commit 后才采用 publication-finalized 时间。恢复确认可能晚于初次激活；重复 finalize 保留原时间；旧快照无回执则发布时间未知，不回填猜测。
