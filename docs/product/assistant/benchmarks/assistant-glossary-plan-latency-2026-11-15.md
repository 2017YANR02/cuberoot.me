# 百科核验与详细计划耗时复测（2026-11-15）

状态：本轮 Agent 优化仅本地，未提交、推送或部署。承接[缩写展开与首次答案复测](assistant-context-expansion-latency-2026-11-15.md)。本轮只改 `core/apps/api/src/utils/site_assistant.ts` 的查询选择和回答指导，增加对应查询回归；不更改 Codex、上下文分层窗口或压缩优先级。

## 原因与改动

实际阶段记录显示，百科问题通常先调用模型选择 glossary，再调用模型根据证据核验并生成正文；混合页面请求也存在这次规划开销。详细计划通常已经只有一次模型调用，等待来自正文生成，以及展示前必须完成的时长检查。

- 对明确要求查百科且含 1–4 个英文大写缩写的请求，直接选择 glossary 读取。复用原有工具执行、预算、来源登记、隔离核验、失败处理和最终校验，不直接编造答案。模糊词句、否定或条件查询仍交给模型规划；混合页面义务保留。图片和仅导航请求不走这条预取路径。
- 词条回答要求完整全称、对应含义与全部展开来源；只有缺失所需事实时才说明正文为空。用户要引用原标题时仍保留原标题，不把派生全称冒充原文。
- 详细计划父标题只放名称和总时长，子项承载动作、时长和所需理由；理由默认写短因果句，明确的详细程度、字数、步骤和格式要求继续优先。当前要求的行动类型要真正执行，不能把准备工作算作该行动。
- 没有删除或放宽展示前的分钟总额检查，没有把未校验正文提前流出，也没有用进度提示充当首答。任意自然语言语义、子步骤数量和字数仍不是该时长守卫的确定性覆盖范围。

## 最后查询边界补测

主测中发现“分别用一句话”仍被否定规则里的“别用”误判，组合词条 G01 没有省掉规划调用。最终仅修正该谓词，并用完整原句加入回归；主测的回答指导、来源处理和校验均未再改变。

G01 两版各 2 次，共 **4 条**补测：两版均 2/2 完整，候选每条 1 次模型调用，基线每条 2 次；平均 2.514 → 2.118 秒，总 token 54,399 → 29,098。候选第一次仍比基线慢，因此减少调用不保证每次延迟更低。补测不混入 104 条主表。
