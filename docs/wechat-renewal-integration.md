## 接口与流程

- `GET /v1/membership/subscriptions/availability`：不缓存，返回开放状态及协议版本。
- `POST /v1/membership/subscriptions/enroll`：登录、限流、显式同意和价格版本检查；服务端决定模板、账号与价格。先落库，再请求微信 H5 签约；重试复用未完成协议，已有有效协议须先管理或取消。
- `POST /v1/membership/subscriptions/mini-link`：网站登录后生成 10 分钟、绑定账号及套餐的签名票据，通过微信 URL Link 打开原生签约页；不包含会话凭据。
- `POST /v1/membership/subscriptions/mini-context`：小程序登录同一账号后解析票据及价格。
- `POST /v1/membership/subscriptions/mini-enroll`：再次明确同意协议，验证微信登录 code 所属 UnionID 与账号一致，复用已有合约预留和幂等规则，再返回官方签约小程序参数。
- 原生 `pages/membership/index` 跳转微信官方 `wxbd687630cd02ce1d`；客户端返回不作为付款或签约证据，返回后向服务器查证。抖音构建排除此页和微信跳转清单。
- `POST /v1/membership/subscriptions/wechat/notify`：签约与解约通知。APIv2 验签，匹配已保存的协议，再查微信确认状态。浏览器跳转不授予会员。
- `POST /v1/membership/subscriptions/wechat/payment-notify`：扣款通知验签后主动查单，核对商户、订单、币种、金额和交易号，在一个数据库事务内更新订单、会员与下一周期。
- 原有本人查询和取消接口保留。管理页区分签约与扣款状态；取消意图先持久保存，然后请求微信解约。

签约成功后申请首期扣款；只有确认到账才发放权益。后续在当前已付有效期结束前 24 小时申请扣款，由微信按模板通知及延迟执行。单次购买延长了有效期时，申请时间随有效期后移。永久会员不发起自动扣款。

每个合约、周期仅有一个订单。请求前持久化 submitted 状态，进程崩溃、超时或 ACCEPT 都只进入查单，不创建新的扣款请求。重复通知不会重复延长会员。取消已记录后不再发起新请求；已提交请求若之后支付成功，仍为实际付款发放对应权益。

## 运维及待验收

- 停止新增扣款：关闭 DEBIT 或 RELEASE；保留 SYNC 和密钥，以继续查询已有交易和取消授权。
- submitted 长期不确定、请求提交前进程崩溃、ORDERNOTEXIST 或失败周期：停止该周期自动重试。人工核对原商户订单；不得换订单号尝试补扣。当前未提供自动补扣或管理员补扣按钮。
- 未完成签约且微信无法确认不存在的协议会保留 pending，不凭本地超时删除；人工核实后处理，避免把未收到回调误认为无授权。
- 退款由现有人工售后流程处理；本次不增加自动退款、退款撤销权益或退款重扣。
- 上线前仍需真实验证商户权限、所选渠道的手机微信签约、拒绝签约、首笔到账、24 小时通知及续费、微信侧取消、网站取消、退款对账与通知到达。模拟接口测试不能替代这些验收。
- 回调仅接受 POST。浏览器地址栏 GET 返回 404 不代表 POST 未部署；无效请求应返回 FAIL，不伪装通知处理成功。
