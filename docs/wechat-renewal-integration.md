# 微信会员签约与自动续费

2026-10-14：月度模板 `225492`（2999 分 / 月）、年度模板 `225493`（29900 分 / 年）已提交审核，截图均为审核中。本次实现保存在工作区；此文不代表已部署、已获 H5 签约权限或已完成真实交易验收。

## 开放边界

默认关闭。需要同时登记两个精确模板 ID 的审核结果、H5 纯签约权限及显式发布开关。模板回调、时间经过和普通会员套餐开关均不能绕过这些条件。签约及扣款使用 APIv2 专用配置，不复用 Native APIv3 密钥。

| 配置 | 含义 |
| --- | --- |
| `WECHAT_PAPAY_APPID` | 已获得 H5 纯签约权限的公众号 / 移动应用 AppID |
| `WECHAT_PAPAY_MCHID` | 对应商户号 |
| `WECHAT_PAPAY_API_V2_KEY` | 对应 APIv2 密钥，通过私密服务器配置注入，不提交仓库 |
| `WECHAT_PAPAY_MONTHLY_APPROVED=225492` | 人工核对月度模板已通过且金额、周期、24 小时模式一致后登记 |
| `WECHAT_PAPAY_YEARLY_APPROVED=225493` | 人工核对年度模板已通过且金额、周期、24 小时模式一致后登记 |
| `WECHAT_PAPAY_H5_APPROVED=true` | 单独核实 H5 纯签约及商户域名权限，H5 支付权限不能替代 |
| `WECHAT_PAPAY_SYNC_ENABLED=true` | 合约同步及已有扣款查证；不独立授权新扣款 |
| `WECHAT_PAPAY_DEBIT_ENABLED=true` | 周期扣款开关，仍受上述审核及发布条件约束 |
| `WECHAT_PAPAY_RELEASE_ENABLED=true` | 最后由维护者显式开放；审核中不得设置 |

两项模板审核通过后仍须核对商户配置、域名、通知模式和价格。必要发布按仓库部署流程执行，推送前 pull --rebase；迁移 `0276_membership_renewal_pipeline.sql` 随 API 部署运行。确认迁移、API 与前端部署后，受控验收真实签约、付款、取消和退款处理，再向公众展示套餐。当前没有执行真实签约、扣款、退款或修改线上开关。

## 接口与流程

- `GET /v1/membership/subscriptions/availability`：不缓存，返回开放状态及协议版本。
- `POST /v1/membership/subscriptions/enroll`：登录、限流、显式同意和价格版本检查；服务端决定模板、账号与价格。先落库，再请求微信 H5 签约；重试复用未完成协议，已有有效协议须先管理或取消。
- `POST /v1/membership/subscriptions/wechat/notify`：签约与解约通知。APIv2 验签，匹配已保存的协议，再查微信确认状态。浏览器跳转不授予会员。
- `POST /v1/membership/subscriptions/wechat/payment-notify`：扣款通知验签后主动查单，核对商户、订单、币种、金额和交易号，在一个数据库事务内更新订单、会员与下一周期。
- 原有本人查询和取消接口保留。管理页区分签约与扣款状态；取消意图先持久保存，然后请求微信解约。

签约成功后申请首期扣款；只有确认到账才发放权益。后续在当前已付有效期结束前 24 小时申请扣款，由微信按模板通知及延迟执行。单次购买延长了有效期时，申请时间随有效期后移。永久会员不发起自动扣款。

每个合约、周期仅有一个订单。请求前持久化 submitted 状态，进程崩溃、超时或 ACCEPT 都只进入查单，不创建新的扣款请求。重复通知不会重复延长会员。取消已记录后不再发起新请求；已提交请求若之后支付成功，仍为实际付款发放对应权益。

## 运维及待验收

- 停止新增扣款：关闭 DEBIT 或 RELEASE；保留 SYNC 和密钥，以继续查询已有交易和取消授权。
- submitted 长期不确定、请求提交前进程崩溃、ORDERNOTEXIST 或失败周期：停止该周期自动重试。人工核对原商户订单；不得换订单号尝试补扣。当前未提供自动补扣或管理员补扣按钮。
- 未完成签约且微信无法确认不存在的协议会保留 pending，不凭本地超时删除；人工核实后处理，避免把未收到回调误认为无授权。
- 退款由现有人工售后流程处理；本次不增加自动退款、退款撤销权益或退款重扣。
- 上线前仍需真实验证商户权限、手机微信 H5 签约、拒绝签约、首笔到账、24 小时通知及续费、微信侧取消、网站取消、退款对账与通知到达。模拟接口测试不能替代这些验收。
- 回调仅接受 POST。浏览器地址栏 GET 返回 404 不代表 POST 未部署；无效请求应返回 FAIL，不伪装通知处理成功。
