# /regulation 引用阅读页与站内链接

`entries/` 只保存已经读取原始来源、具备实际双语内容的引用资料。`evidence/` 记录来源、读取范围和限制。`contentKind: summary` 是编辑摘要，不是全文译文；页面必须显示“内容摘要”。未取得正文的来源不得创建空阅读页，也不得根据上级简报推测原报告内容。

现有公告、事件日志、当前规则条款、比赛和选手链接复用 `core/packages/client/lib/regulation-links.ts`。该解析器只把有对应内容的阅读链接改成站内链接；官方原文、官方归档、翻译出处与许可声明保留外链。历史规则版本、已删除条款、未支持的子页面/锚点、邮箱和外部操作入口不能丢失语义后强制跳转。

## 维护

在仓库 `core/` 下运行：

```sh
node --import tsx packages/client/scripts/build-wca-references.mts
node --import tsx packages/client/scripts/audit-regulation-links.mts
```

首个命令校验 `entries/*.json`，通过既有 HTML 安全清洗生成 `references.json`、`references-index.json`，并刷新共用 `link-index.json`。文章路由为 `/regulation/reference/<id>`，中文加 `/zh`。站点地图与页面标题使用同一份引用索引。

公告、日志与规则生成器也会刷新链接索引，原始来源 URL 与翻译正文不做破坏性替换。增补引用只需添加有证据的源记录并重建，无需逐篇修改引用它的公告。

第二个命令只读检查全部保存的公告、日志、引用资料、完整规则和翻译参考中的链接。需要逐项清单时加 `--output /tmp/regulation-links.json`；结果含目标路径、来源上下文以及未映射类别。它区分代码/讨论、历史版本、联系邮箱、论坛、文档和其他外链，不把“未收录”误记成“已确认无法访问”。JSX 中的来源链接单列供人工核对。
