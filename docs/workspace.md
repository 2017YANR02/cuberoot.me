团队协作入口 `/admin/team`，中文 `/zh/admin/team`；与 `/admin` 网站管理共用导航。旧 `/workspace` 页面不提供兼容跳转。直接由 CubeRoot 承载，原跳转到 Mira 的规则已移除。

- 登录：既有 CubeRoot 账号与会话。管理员自动获得员工身份，直接记录本人工作并保留管理能力；其他员工由管理员按 CubeRoot ID 开通。管理员只可查看本人草稿及历史修订。
- 数据：CubeRoot PostgreSQL 的 `workspace_*` 表，迁移 `0281_workspace.sql`。Mira 使用自己的身份、会话和 SQLite；没有跨应用成员同步、令牌传递或数据库连接。
- 界面：两个应用共同消费 `@app-foundation/workspace-ui` 的布局、登录外壳、项目、报告、讨论与历史；各自注入传输、路由、品牌、主题和控件。
- 规则：使用已发布的 `workspace-policy@0.1.0`（Foundation v0.6.0）。UI 0.1.0 已发布于 Foundation v0.7.0，两站固定 release URL 与锁文件完整性。
- 权限：员工状态与项目资格每次请求重查；草稿和历史版本仅作者可见；共享报告按成员资格过滤后分页；项目归档后可读但不能写；管理员开通员工和管理项目。
- 审计：所有成员、项目、报告和评论写入审计；版本冲突拒绝覆盖。评论重试按 ID 幂等。身份预览会话不用于员工操作。

## 工作时段

“我的工作”记录同一工作日期内的起止小时，支持 `0:00–24:00`，结束须晚于开始。提交时选择时段；草稿可暂不填写。时段随报告保存、展示和进入历史修订，旧记录保留未填写状态，不推算工时。仍为每人、每项目、每天一条记录。

时段保存在既有报告 `payload` 中，无需 SQL 迁移。共享报告界面沿用 `workspace-ui@0.1.0`，扩展由现有 pnpm patch 管理，源码、运行产物与声明同步生成；不复制报告编辑器。

## 共享清单

入口 `?section=checklists`。直接按名称创建多份清单，公司清单对员工共享，项目清单仅项目成员与管理员可见；有项目资格的成员均可编辑。共享范围创建后固定，避免误将项目内容公开。完成项稳定置底并变灰，取消勾选恢复原顺序。清单可改名、归档、恢复和整份删除；删除弹窗显示名称与事项数量，确认后同时永久删除全部事项，不提供单项删除。归档项目停止写入和删除。新增事项使用清单底部的行内输入与添加按钮，支持回车提交，空白内容不可提交。顶部不设重新加载按钮，保存后自动刷新，加载或保存失败时保留重试入口。

`0291_workspace_checklists.sql` 新增 `workspace_checklists`，`0293_workspace_remove_checklist_categories.sql` 删除旧分类字段，保留清单名称、事项、共享范围、状态和版本。`GET checklists` 按权限与归档状态过滤，以创建时间和 ID 稳定排序，每页返回 20 份；不再返回或筛选分类，旧分类查询参数被忽略。`POST checklist` 不再要求分类，兼容忽略旧客户端的分类字段，仍校验整个清单（最多 200 项）、项目资格和版本；写入复用工作台事务锁及审计。冲突返回 409，界面保留输入并提供重新加载，不自动覆盖。团队内容在账号注销后保留，不新增私人账号关联。部署时须先应用 0293 迁移并更新 API，再使用不带分类的新清单表单。

`POST checklist-delete` 接收 `id/version`，沿用清单编辑权限、项目状态与事务锁；缺失或不可见返回 404，版本冲突返回 409。删除和 `checklist.delete` 审计在同一事务内完成。界面取消或失败时保留清单，成功后移除并刷新，延迟响应不能恢复已删除清单；删除后当前页为空时回到上一页。无需新增数据库迁移，前端删除操作依赖新版 API。

## 总排期

入口 `?section=schedule`，可保存多份排期，通过 `schedule` 和 `scale=fit|day|week|month` 查询参数选择排期与时间尺度。默认总览将整个时间范围适配可用宽度，随容器宽度调整刻度密度；日、周、月视图保留横向滚动查看细节。任务行高 44px，任务名称在左侧单行展示，完整名称、负责人、日期和进度可通过悬停或聚焦查看；时间条仅在空间足够时显示日期和非零进度，避免重复任务名称。点击任务名称或时间条打开同一编辑表单。日期精确到天，结束日期包含当天；每份最多 150 项、跨度最多 732 天。

负责人和管理员可创建、编辑、归档、恢复及删除排期；普通成员只读。公司排期对员工可见，项目排期按成员资格过滤，项目归档后不能写入或删除。共享范围创建后固定。复制排期可选择目标范围和新的开始日期，所有任务及里程碑按相同天数平移，生成新 ID，完成进度归零；原排期保持不变。

设置内提供“删除当前排期”，显示已保存名称及任务数量，二次确认后永久删除排期及全部任务、里程碑；取消或失败保留设置输入。`POST schedule-delete` 接收 `id/version`，检查负责人或管理员身份、项目资格、归档状态及版本，并在同一事务内记录 `schedule.delete` 审计。删除成功后清除选中项并刷新；当前页为空时退回上一页，延迟读取不会恢复已删除排期。无需新增数据库迁移，删除操作需部署新版 API。

总览按业务分组折叠为泳道：日期重叠的普通任务合成阶段条，连续但不重叠的阶段及时间空档保持独立；这是展示汇总，不修改任务或推算进度。点击泳道箭头或阶段条可展开明细，只读成员也能展开。里程碑始终独立显示日期与名称。切换排期重置展开状态，日、周、月视图直接显示完整任务。显示名称省略开头编号和末尾编号依赖，原文仍保存在任务编辑与完整提示中。顶部集中排期选择与操作，共享范围和日期合并为辅助信息行。

`0292_workspace_schedules.sql` 新增 `workspace_schedules`，接口为 `GET schedules` / `POST schedule`。列表每页 20 份，链接指定的排期独立按权限读取。服务端校验日期、进度、重复 ID、两年跨度、资格及版本；采用与报告和清单相同的事务锁、审计和账号生命周期。两个新增表均为团队记录，不建立个人账号外键。发布时由现有部署流程应用增量迁移；应先确认新版 API 就绪再开放新版前端，避免旧 API 忽略小时字段。

本地数据库测试可使用显式的一次性 `WORKSPACE_TEST_DATABASE_URL` 运行 `tests/workspace-planning.test.ts`；无 PostgreSQL 服务时，可将 `WORKSPACE_TEST_PGLITE_MODULE` 指向本机临时 PGlite 模块执行相同 SQL/事务测试。后者不是生产依赖，也不能替代 PostgreSQL 13 部署验证。

JSONB 写入直接传数组，由 `postgres.js` 编码；提前 `JSON.stringify` 会被再次编码成 JSON 字符串，违反清单和排期的数组约束。`workspace-planning.test.ts` 无数据库时仍运行生产驱动序列化回归，覆盖新增空表、填充与清空；PGlite 测试显式复用同一 JSON 序列化器，避免其默认行为掩盖问题。

## 界面与交互

今日记录表单只填写项目、可见范围、工作日期、起止时间与今日进展，不再提供成果链接、需要协助、下一步输入项。历史记录中已有的这三项内容仍在详情中展示，编辑进展时原值保留，不变更持久化结构。

设计参考：[Refactoring UI skill](https://github.com/jaywilburn/refactoring-ui-skill/blob/main/skills/refactoring-ui/SKILL.md)。工作台采用内容优先、适中密度的工具界面，沿用全站主题、字体、圆角与导航组件。

- 层级：正文与输入 16px、辅助信息 14px、分组标题 20px；手册阅读区同步字号，示意图中的缩略示例保留自身比例。
- 布局：筛选从内容区左上方开始，常用操作同排排列；宽屏列表保持左对齐。日期约 12rem、小时约 8rem，下拉框按选项内容取宽度并受容器上限约束；长文本使用编辑器宽度。单行输入、下拉框和日期显示共用 44px 高度与行高，日期组件外层不继承字段标签的小字号。
- 甘特图：月份/年份与日期刻度分为两层，日视图仅展示日号和星期；周刻度从周一开始，月刻度使用真实月长。日期网格、任务与里程碑共用比例坐标，短排期撑满容器，长排期按最小刻度宽度横向滚动；任务列和表头吸顶，淡色分组、周末阴影和今日线辅助对齐阅读。
- 项目：列表最大宽度 900px，名称、状态与设置同排，长名称可换行；配置网址时项目名直接链接到项目。管理员的新建入口位于列表末尾，保留加号与简短文字，空列表同样使用该入口。
- 项目成员：复用 SearchInput 的搜索与清除，使用可直接勾选的成员列表和已选人数；筛选仅改变可见项，提交保留全部选中成员，允许清空。共享面板通过 host 注入选择器，未注入的宿主保留原生多选回退。
- 排期操作：排期、视图、状态筛选连续排列，新建排期位于三个筛选控件之后；新增任务位于当前甘特图的操作区。两者保留加号和短文字，明确作用范围，刷新、设置和复制继续使用图标。
- 编辑：报告、项目、成员、清单设置、清单事项和排期任务使用同一个编辑弹窗。新增清单事项保留一行快捷输入；勾选完成不打开弹窗。列表刷新保留同一路径的旧内容，切换权限或筛选路径时不混用缓存。
- 清单：事项按开头路径的第一段（如 `/timer`、`/recon`）归入可折叠文件夹，默认收起，显示已完成/总数；无路径前缀的归入“其他”。组内未完成事项在前，分组按原始事项顺序排列。展示时省略重复前缀，编辑和保存保留完整原文；修改前缀即可调整归类，不引入新的持久化字段。
- 操作：新增、编辑、保存、复制、刷新与翻页用裸图标（ghost），提供 Tooltip 和无障碍名称。默认无背景、边框或阴影，主要操作以主题色强调，悬停和键盘聚焦才显示浅色背景；44px 点击区域保留。图标按钮不再套用实心 `btn-primary` / `btn-secondary`，避免全站按钮样式反盖。提交工作与保存草稿保留图标和文字，避免混淆。
- 弹窗：原生 dialog 提供模态焦点与背景隔离；复用遮罩关闭逻辑，保存期间禁止关闭，未保存时提供放弃确认，关闭恢复触发控件焦点。移除排期任务需确认。
- 浮层：日期面板和 Tooltip 优先挂载到所属打开的 dialog，避免落在模态层后方；日期面板的 Escape 优先关闭面板。
- 材质：列表以间距和细分隔线分组，编辑弹窗复用全站 popover 表面，不新增颜色或独立玻璃效果。
- 响应式：工具栏换行，短字段保持可读宽度，编辑弹窗限制视口高度并内部滚动，常用操作按钮不小于 44px。减少动态效果偏好禁用按压缩放。
- 实现：共享报告/项目面板、Field、Form 和宿主契约继续通过既有 workspace-ui pnpm patch 扩展，源码、dist 与声明同步；CubeRoot 的图标、弹窗和日期组件由 host 注入，不复制业务面板。`WorkspaceControls` 已登记组件目录。
