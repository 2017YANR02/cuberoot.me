# 文档维护流程

状态：`REFERENCE`。目录与 Agent 导航的当前约定；重要历史、限定条件与授权不得因精简丢失。

## 放在哪里

- 跨模块合同及产品跟踪按[总入口](../README.md)归到 architecture、product、compliance、data、operations 或 design；不要重新把专题文件平铺到 docs 根目录。
- 仅一个 app/package/job/script 使用的实现与命令放在它的 README；内容明显独立且较长时再建局部 docs。共享合同只保留一份，模块文档链接它。
- 当前文档只保留合同、源码入口、当前缺口及必要决策。按日期累积的过程、失败与验收记录放在同主题 history；数据原稿、翻译版本和审校账本保留其结构，不把证据当成可删的旧文档。
- 重要决策包含原因、适用条件、日期、例外、替代关系和证据边界。历史授权不是新任务授权；同一事项的发布、设备及审核状态不得合并成一个“已完成”。

## 合并时保留什么

先确认职责是否相同。重复的当前说明合到唯一合同，其他入口直接链接；合同、操作手册和历史取舍各自有用途，不为减少文件数强行拼成超长文档。当前入口必须明确指向旧决策的保存位置。

已迁出的正文不再保留成百个跳转小节或空旧文件。同步修改调用方到新文件/锚点；若标题改变，记录锚点映射并逐项修复链接。Git 保存版本，topic history 保存需要持续理解的决定，两者不能互相替代。

## 修改与检查顺序

1. 检查 Git 状态及最近提交，保留其他任务的修改。按文件确定 owner、当前入口、历史材料和调用方；不创建工作树。
2. 搜索仓库内完整路径、相对路径、basename、锚点和程序拼接路径。覆盖 AGENTS、skill、README、脚本、测试、workflow、manifest、生成物登记及产品内的源码链接。
3. 移动文件时重算它自己的相对链接。移动可执行脚本还要核对 `import.meta.url`、工作目录及动态路径；不能只替换 Markdown。
4. 用 `node scripts/check-documentation.mjs` 检查归属、相对文件/锚点、旧路径引用与迁移映射。源码或机器登记变更另运行相关现有 guard；不为纯文字改动制造应用部署。
5. 对翻译/原稿迁移运行原有只读 hash/版本验证；不得重建内容来掩盖 hash 变化。数据库迁移和带原始哈希的证据不能为了修注释改字节。
6. 检查 diff 和必要验证结果，按主题暂存与提交；提交不等于 push。报告相关检查及既有失败，不夹带其他任务的改动。

历史 SQL migration 的字节由 `ops/bin/apply_migrations.sh` 校验，旧文档路径保留原文，通过[迁移对照](documentation-migrations.json)定位新资料；这不是兼容文件或运行时别名。迁移表中的 old/source 键同样属于历史定位信息，不按旧引用清理。

## 维护索引

总入口只说明任务、归属和阅读顺序；专题 README 列当前入口、权威源码、必要历史与验证边界。增加/删除专题文档时同步所属索引。Agent 的阅读链应能从根 AGENTS 到专题合同、模块入口、源码证据、最小验证，再回到进度/历史记录，不依赖关键词搜索偶然命中。
