# 全站背景与液态玻璃实施方案

日期：2026-09-10。状态：已按用户授权实施全站共享层与页面适配，逐页视觉验收尚未完成；暂不提交。本文和[逐页审计清单](site-glass-route-audit.md)共同维护。

## 1. 目标和本轮边界

把用户在主页确认的 10 张风景背景及自然取色玻璃推广到现役 Web 前端 `core/packages/client`，统一页面、卡片、工具栏、下拉、弹窗、移动抽屉等自有界面。全页滚动始终有背景，跨页保留选择。

用户已授权按 MD 继续实施。背景和玻璃引擎已从主页提取到共享 components 并在根 layout 单次挂载，外观菜单全站复用，保留原偏好 key 和资产。页面 Agent 已适配 128 个页面 CSS，共享 Agent 补齐控件、浮层和 Platform。未提交或推送；共享工作区其他 AI 的改动保留。

## 2. 视觉与交互契约

| 对象 | 目标 |
| --- | --- |
| 默认风景 | 自动模式下，页面实际浅色用「雪山初晴」，实际深色用「蓝夜远山」；手动选择的图优先，不因换页或主题而被覆盖 |
| 全站选择 | 复用同一外观菜单，背景直接展开；桌面位于配色右侧，多行多列，手机纵向排列并可滚动；保留「随明暗切换」「无背景」和「比较全部」 |
| 玻璃颜色 | 来自背后的真实风景或场景，不加前景渐变，不画单侧泛白高光，不用高饱和滤镜把所有表面染色 |
| 光学效果 | 模糊和折射仅作用于背后画面，文字、图标、魔方贴纸、点击区域保持清晰稳定；不把整个组件截图后扭曲 |
| 内容可读性 | 普通卡片沿用主页材质；密集正文、表格和输入区域可以使用同一材质体系内的均匀 token 遮罩提高可读性，不另画彩色渐变 |
| 内容结构 | 沿用已有卡片和面板，不为每段文字、表格单元格或图标新增玻璃外框；不以视觉统一改动业务布局、权限和交互 |
| 背景遮罩 | 保留用于阅读的景层遮罩，作用于风景；与用户禁止的卡片前景渐变分开。不要每个页面再叠一套装饰渐变 |
| 层级 | 背景不接收指针；卡片手柄留在所属卡片层内；菜单、弹窗和抽屉始终盖住页面内容；浮层内的子菜单不被玻璃裁切 |
| 无背景 | 去掉风景，保留正常主题底与可读表面；不强行制造空背景上的折射纹理 |
| 降级 | Safari/iOS、Firefox 使用现有兼容路径；无 backdrop-filter 或减少透明度时退为 token 实底；减少动态时关闭装饰位移和动画 |

统一的是视觉规则、材质来源和交互质量。现有 Web 实现有浏览器降级，不能把它描述成各内核都等同原生 iOS 的渲染。

## 4. 实施结构

### 4.1 景层、偏好与 SSR

1. 把主页景层与光学入口移入 `components/` 并改用中性名称；hook 和数据保持各自现有职责，不创建新的主题管理框架。移动前确认文件未被其他 AI 修改，实施时按仓库规则用 `git mv` 提取；它会暂存自有文件移动，需在批次记录中说明，不连带提交或暂存他人的内容。
2. 在静态根布局内挂载一个不含文案的客户端景层/引擎，使 portal 到 body 的组件也能使用其变量；背景选择器放在已有语言环境中的外观入口。全站只挂一个风景和一个页面表面引擎，不随每张卡片创建。
3. 保留 SSR 固定快照，初始 HTML 使用主题底，hydration 后恢复已选风景；不在 render 读取 localStorage、当前时间或随机值。图片加载失败回退主题底，切换到另一张图能够恢复。
4. 不把背景图片塞进 `--background` 颜色 token；景层独立定位，避免颜色计算、图表读 token、打印及 meta theme-color 被破坏。不全局给页面祖先加 transform/filter/opacity，防止改变 fixed、sticky 和 backdrop root。
5. 认证回调当前已有上一页 iframe 背景，单独去重并保留成功、失败、等待界面；不可删除认证行为。根级错误页不依赖故障中的景层引擎，应有可读的降级表面。

### 4.2 页面实际明暗

自动模式的输入必须反映页面最终主题，顺序为：有效手选图 → 无背景 → 自动解析页面明暗。明暗解析继续尊重现有配色和暗锁规则，不另维护一份通过 URL 猜测的页面表。

优先在现有主题模块中复用实际样式同步思路，把页面主题变化作为有限事件处理：路由切换、主题/配色确认、菜单临时预览及恢复、系统主题变化、跨标签变化、延迟渲染的锁色页面根出现。必要时用明确的页面主题标记或窄范围观察，避免轮询全 DOM。不要把当前 `ThemeColorSync` 当成已覆盖这些事件的完整监听器，它现在只是一条可复用的实现线索。

验收必须包含：偏好浅色进入实际暗锁页时自动选蓝夜；返回普通浅页时自动选雪山；手选任一图后以上路径都不改选择；预览配色退出后背景正确恢复。不能仅检查 localStorage 的值。

### 4.3 表面应用与层级

修订现有 `glass-material.css`，用根级可继承材质变量覆盖 body portal，再让已有表面显式消费共享规则。页面内配色比较样本继续局部解析 token，不能被根变量绑定成同色。

禁止全局匹配 `div`、`[class*="card"]` 或所有 `::before/::after` 强改背景。每个共享组件先确认伪元素和定位归属：已有业务伪元素就保留；滤镜只作用在专用装饰层。不要复制主页的 `position: relative` / `overflow: hidden` 到 fixed 弹窗、sticky 表头或拥有外溢菜单的容器。

按页面现有区域消费同一材质：导航/工具栏/菜单，普通卡片，阅读/表格面板。密集内容可调均匀遮罩强度，色相、边缘和降级规则仍共享。优先处理公共消费者，再处理页面局部实底，避免共享组件已变玻璃但外层不透明导致看不见背景。

## 5. 全站覆盖策略

完整模板与运行时目录在[逐页审计清单](site-glass-route-audit.md)。2026-09-10 快照为 335 个页面模板（330 个语言模板、5 个认证回调），其中 62 个含业务动态参数；模板不是实际 URL 总数。

| 页面族 | 改造对象 | 必须保留/额外检查 |
| --- | --- | --- |
| 主页、账户、课程、论坛、画廊、会员、站点入口 | 背景、已有卡片、搜索、操作菜单、弹窗 | 登录与匿名两套内容；空态、加载和错误态；图片区保持原图 |
| 规则、Wiki、教程、数学、开发长文 | 景层、现有导航/阅读区域及互动控件 | 长文底部始终有景；不为每段文字套框；公式、代码、链接清晰 |
| WCA、统计、排名、比赛、复盘列表 | 表格外围、筛选、吸顶表头、弹出信息 | 暗锁、横滚、图表数据色；不为每个单元格创建滤镜 |
| 公式库、训练、识别、打乱与求解 | 外壳、列表、设置、结果面板 | 状态色、训练反馈、魔方贴纸、动画交互、计算进行中；求解核心不因视觉更改 |
| 计时器、模拟器、Space、比赛模拟 | 工具栏、侧栏、移动抽屉、菜单、非场景背景 | 全屏、键盘计时、触摸拖拽、3D raycast；3D 自身天空/场景可充当玻璃背景，不覆盖场景画面 |
| 视频会议、音乐、逐帧、绘图、拼图、表格/文档编辑器 | 控件与面板及画布以外景层 | 视频、canvas、编辑纸张和导出内容保持正确，不能通过降低画面透明度冒充玻璃 |
| Platform、机构、学习、管理、私密库 | 公共产品壳、业务卡片、表单、权限提示、弹窗 | 每个注册页面/权限形态分别留证；匿名登录提示不代表业务页验收通过 |
| `IframePage` 的 16 个入口 | 自有标题栏、可见边缘和容器 | 内嵌文档是独立运行时；fork 不擅改，外部文档不能透传 CSS；标注「仅自有壳覆盖」而不是全页完成 |
| 认证、错误、加载、无效参数、404 | 自有状态界面的背景和可读操作 | 不影响 OAuth 跳转/重试；崩溃时优先可用 fallback，不强依赖 SVG 引擎 |

Platform 的 catch-all 要展开当前注册表，而不是只验一个模板；WCA 动态统计要展开有效 `stats/index.json` 条目及其渲染分支。动态详情使用真实有效或隔离 fixture 数据，每种模板至少有正常内容；空态、非法参数、权限不足另记。数据实体很多的模板不要求遍历每条业务记录，但所有模板、注册子页和渲染分支必须覆盖，不能抽几个热门页替代。

### 不能掩盖的覆盖限制

- 受保护 fork 的内部样式若也要一致，按仓库规则需另行取得修改 upstream 的批准；本次先完成自有 wrapper，不要求为已授权的自有代码再次批准。
- 外部独立应用的内部 UI 需要对应项目能力与权限；标记边界及地址，不虚报完成。
- 登录角色或有效数据不足时继续处理和验证其他页面，把对应行保持受阻。不能为了截图修改线上账号角色、创建订单或发送消息。
- 打印、图片导出、视频导出属于内容输出，不把装饰风景烧进内容；这类无玻璃输出是明确的功能策略。

并行时最多占用当前可用 Agent 槽位，不和其他任务抢共享文件：主 Agent 独占 root layout、theme、材质和共享控件；页面 Agent 各自认领不重叠目录；Reviewer 只读。基础层稳定后再并行页面批次，避免各 Agent 重复造背景组件。

当前他人 WIP 已涉及 `SortableCard.tsx`、`DeskPet*`、`useModalDismiss.ts`、`CompactSelect.tsx`、Platform 路由、Drive、训练和模拟等本方案潜在交叉处。每批编辑前重读 status/diff，重叠时只暂停无法安全分离的文件，其余继续。无需为文档等待所有其他工作结束。

本任务暂不 commit/push，也不暂存他人的内容。未来若决定提交，先重读 status、逐文件/逐 hunk 审核，仅提交本任务已验证内容；不要用一次全仓 `git add` 汇集并行工作。

## 7. 验收矩阵与证据

### 7.1 每一页面条目

每行至少保存：源码入口、实际 URL 或 fixture 标识、身份、表面/渲染分支、桌面与窄屏、浅深背景、关键交互、截图路径、执行人、审核人、结果与阻塞原因。身份信息仅记角色，不记录令牌或私密业务数据。

- 1440px 桌面与 390px 手机逐页看首屏和末屏；有中间特殊面板的补对应位置。320px 对每个独立布局、表格、菜单和编辑器检查边界，不以390px截图代替。
- 普通双主题页检查实际浅、深两种外观；暗锁页确认锁色与自动图对应，保留手动图选项；所有页面确认无背景后仍可读。
- 打开页面实际拥有的菜单、弹窗、抽屉、吸顶表格、全屏状态；检查滚动、键盘焦点、点击、拖动、中键链接。页面无此交互时写不适用原因。
- 检查正文字号、弱文字、选中/禁用态、焦点与业务色；背景最亮、最暗和复杂纹理处都清楚。用合成后的实际画面验对比，不能只算透明 token 的数值。
- 使用授权的只读/隔离 fixture 查看登录后内容；提交、支付、删除、消息发送等不能为了视觉验收触发真实业务。

### 7.2 共享能力全矩阵

| 维度 | 必测集合 |
| --- | --- |
| 明暗 | 系统浅、系统深、显式浅+系统深、显式深+系统浅；暗锁路由切换另测 |
| 背景 | 10 张图全部选择、auto、none；图失败与恢复；刷新、跨页、跨标签、禁用存储 |
| 配色 | 当前全部配色、标准/低对比、菜单预览/取消/确认；比较页局部样本互不串色 |
| 层级 | 主页手柄与外观网格、body portal、nested menu、modal遮罩、移动键盘、安全区、sticky横滚 |
| 兼容 | Chromium、WebKit、Firefox；减少动态、减少透明度和不支持 backdrop-filter 的 fallback |
| 长页面 | 首屏、中间、页尾都有景；路由返回无重复景层/滤镜；无背景模式不残留失效引用 |
| 输出 | 打印和已有导出流程保持原内容，装饰层不影响尺寸/颜色 |

所有共享测试 fixture 全量跑。跨浏览器需覆盖每个独立表面实现与布局分支，不能只把 UA 改成 Safari 视为 WebKit 渲染验收；iOS 真机未测须明确记录。逐页覆盖与共享组合矩阵分开记账，均不能因为模板复用推断为已经看过。

### 7.3 工程与性能验证

- 实施批次运行适用的 client typecheck、定向测试、CSS 解析和 diff 检查；不在运行中的 dev 目录执行 next build。
- 后续改 TS/TSX 逻辑，在 `core/` 运行 `pnpm --filter @cuberoot/client typecheck`；CSS-only 批次不跑 typecheck。
- 复用 `tests/home_background_choice.test.ts`、`tests/theme_preview.test.ts`，为实际新增的主题解析/存储边界加有效用例；单文件用 `pnpm --filter @cuberoot/client exec vitest run <path>`，不运行无关全量求解测试。
- 保持静态 layout、AppLink、共享控件和中英文契约；新增共享入口同步 `/dev` catalog。不为视觉改造加新的运行时框架或外部 CDN。
- 浏览器先复用本地 dev 和 Playwright MCP；dev 在跑时不 `next build`，不擅自重启他人的服务。截图与调试输出放 `.tmp/png/`。
- 涉及性能测量时使用 `perf-test` 技能，以同一设备、同页内容、同视口记录迁移前后长表滚动、计时和 3D 操作的 trace；若新增合成/绘制开销造成可感知回退，先减少独立 blur 层或使用现有 CSS fallback。没有实测前不承诺帧率。
- 不给整个长文/长表整页套大面积 SVG 位移，不逐单元格 blur；不预载全部原图；只有选中背景进入全屏景层，缩略图按菜单/画廊用途加载。

### 7.4 完成定义

附录每个自有页面模板与展开项必须达到「实现并视觉审核通过」，或明确列为不能完成的受阻项；受阻项存在时不能说全站已全部完成。仅 wrapper 覆盖、输出刻意无景、第三方边界单独列出，不混入完整通过数。

独立 Reviewer 对实现者的结论可以复核并退回；最终交付列出已通过/失败/受阻数量、截图证据和未覆盖范围。修复必须重新检查受影响页面及共享消费者，不靠一句“共享样式已改”关闭全站任务。
