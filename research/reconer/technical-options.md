# 真实速拧视频复盘：技术选择与证据边界

本轮建议仍以**可见实例 → 几何与中心对应 → 带未知项的时间观测 → 物理约束搜索**为主线，但必须分别证明这些环节有效。训练出一个分割模型是中间产物；它不会自动得到中心身份、动作边界、真实执行轨迹或整把复盘。

本文按 25 类组件讨论技术选择及失败证据；从输入视频到可交付产品的完整组合、九条实现路径及分步代码计划见 [implementation-paths.md](implementation-paths.md)。组件可替换、可组合，不能把组件数量当成独立产品方案数量。

本文写于 2026-10-24，依据 `7f85b1ab4a` 及本轮阅读时的工作区，复核了 [AGENTS](AGENTS.md)、[plan](plan.md)、[roadmap](roadmap.md)、[human](human.md)、[prior_art](prior_art.md) 和有关失败脚本。历史数字均来自既有记录，本文没有重跑实验。本轮按用户要求只做方案、源码阅读和基础实现准备，不测试、typecheck、训练、benchmark 或下载权重。正在开发的接口与后续运行证据由 [README](README.md) 和实施报告同步；下文“推荐”“可实现”均不表示已经验证可用。

## 1. 任务、输入和成功标准

### 要恢复的是实际动作，而不是任意解法

同一初态与终态可以连接许多动作序列。只证明输出能复原，不能证明视频里做过这些动作；手滑、回拧、连续同面转动、宽转、整体转体及同时动作都属于待恢复的信息。后处理不能把 `U U'` 消去后宣称准确率提高，也不能把含转体的执行路径改写成更短宽转路径再当作原动作。

输出应保留动作事件、完成时刻或区间、证据来源、备选路径、拒判原因和人工修改记录。原始记谱与固定的逐 token 拼写规范分数同时保存，例如 `U2' → U2`、`Rw → r`；事件顺序和事件数不变。旧 `UD'`、`L2'x'` 等捆绑记谱的事件定义须在数据接收时固定；动作事件数、转动数与去转体步数不能混成一个分母。尾部人为添加的朝向校正应与视频里真实发生的转体分开保存。

| 模式 | 允许作为推理输入 | 应独立报告的边界 |
| --- | --- | --- |
| 已知初态、自动边界 | 视频、粗 ROI、视频范围、独立提供的打乱/初态及其朝向约定 | 第一条产品主线；用户选起止范围不等于逐步人工分段 |
| 已知初态、人工边界 | 上述输入加人工动作边界 | 隔离观测与搜索问题的诊断组，不能称为全自动 |
| 未知初态、自动边界 | 视频及允许的观察期、粗 ROI、视频范围 | 另行恢复初态与朝向；不可借真实解法反推初态后仍记为未知模式 |
| 未知初态、人工边界 | 上述输入加人工边界 | 单独诊断，不与前面三组混算 |
| 多视角、智能魔方或人工几何辅助 | 明确记录额外输入 | 可用于标注或增强产品，但不能冒充普通单目输入成绩 |

终态也必须有来源。只有视频/用户输入足以支持已复原时，才把 solved 当硬锚；截断、未复原、放下后完全遮挡的片段不能沿用 [human.md](human.md) 的“最后必然还原”假设。该文提供逆推思路，不构成“60% 分类必然能提升至 80%”的数学保证。

未知初态有两种待验证入口：从观察期多时刻的可见中心/色块和转体对应积累部分状态，再用角块、棱块及合法状态约束筛出候选；或从有证据的复原终态倒推，把初态也保留为待推断变量。前者可能缺面，后者可能有多条解释路径，都应返回候选或请求补看一面。即使最终恢复了初态，也只能得到该状态或一条代表性生成公式，不能声称恢复了视频拍摄前实际用过的打乱历史。

### 1080p50 的含义

主目标是 **1080p、每秒 50 个真实时间采样帧**。须保留原片 PTS、导出时间与真实时间之间的映射，并清点重复帧、变帧率和慢放倍率。文件写着 50 fps 不代表原始拍摄具有这一时间采样能力；100 fps 抽帧也不能完全模拟原生 50 fps 的曝光模糊、压缩和噪声。4K 原片可以辅助定位问题，但“4K 能看清、1080p 看不清”的区域不能作为 1080p 可读真值。

旧 [roadmap.md](roadmap.md) 的“1080p30、4 倍慢放”是历史计划，不能取代当前规格。先用目标规格固定短段回答可辨识性问题，再讨论提速；更多像素、插帧或去模糊都不能凭空增加真实观测。10 秒视频在 20–40 秒内完成是质量通过后的性能目标，尚无本轮实测承诺。

### 80% 的冻结定义

沿用 [plan.md](plan.md) 与 [独立评分器](src/evaluation.ts)：非空真值视频的主分数为

```text
videoScore = 1 - Levenshtein(predictedEvents, trueEvents) / max(Npredicted, Ntrue)
mainScore  = 所有冻结视频的 videoScore 等权平均
```

插入、删除、替换都计入编辑距离；失败、拒判、超时和缺失预测记 0，不从分母删除。空真值单列。原始拼写分数、规范拼写分数、整把完全正确率、每把人工修正量分别报告。**80% 指逐视频等权的序列分数，不是 80% 视频整把全对，也不是某个 LL 字典中真解排前 1%。** 同一冻结配置用于全部视频，逐视频最优配置只作诊断。

动作时间标注指**转动完成时刻**。区间宽度 ≤20 ms 才具备当前时序评估资格，可评估真值须覆盖至少 80% 动作；其中至少 90% 须正确匹配且预测落在区间或其前后 20 ms 内。漏步和错步不能从该分母去掉，插步另列；过宽区间、时间映射不明和覆盖不足均不能判时间线通过。动作分数与时间分数分别报告。

## 2. 目前的 GT 能证明什么

| 数据 | 能监督或验证什么 | 不能自动得到什么 |
| --- | --- | --- |
| 旧 `*.splits.txt` 的动作记谱 | 原实际动作序列、事件定义、离线序列评分 | 可见色块 mask、中心身份、相机姿态；动作到像素的对应 |
| 旧 splits 帧号 | 当时人工分段及粗对齐 | 严格的完成时刻 GT；历史记录存在手动作起点与层转动相差 0–8 帧 |
| 新完成时刻/不确定区间 | 漏切、过切和完成时刻误差 | 被遮挡期间的逐帧可见性和颜色 |
| 独立可见像素标注 | 实际可见 mask、色类、遮挡/歧义、中心身份及其可读性 | 未露出的 54 格状态或完整动作历史 |
| 独立关键点/面四边形/中心对应 | 可见几何、格位身份及姿态误差 | 仅凭两个彩色点就唯一得到连续 6DoF |
| 智能魔方日志 | 经同步核对的层转动顺序、部分时间辅助 | 视觉中的完整转体/换握、每格像素位置、天然准确的相机时钟 |
| 模型、VLM 或物理反投的提案 | 加速人工审核、训练组弱监督 | 未经审核的独立真值；测试答案反推的标签不能变成盲测输入 |

当前已落地的像素契约只接收可见证据：六色类别为 `1:W, 2:Y, 3:R, 4:O, 5:B, 6:G`，与物理状态里的面/颜色编号不是同一编号体系。颜色不明或同色粘连无法分实例时，应保留 `unknown/ignore` 和原因，不画出并不存在的边界，也不把这些像素当背景负例。`is_center` 允许 `null`；绿色区域不是天然的绿色中心。

旧 RGB 普查和网格样本能帮助找失败模式，不能替代实例 mask。`reviewed`、`annotation_complete`、审核人和像素来源都必须真实。当前训练基线会拒绝含 ignore 区域的训练帧，以避免默认损失把未知区域当背景；这是一项暂时限制，并非已经解决难遮挡训练。若长期只收清晰帧，会引入容易样本偏差，后续需要实际支持忽略损失或经过独立审核的有效裁剪。

### 推理和评分隔离

训练组可使用动作及像素 GT，验证组用于选阈值和配置，保留测试组仅供冻结后的评分。同一原片、裁剪、转码、相邻帧、增广及同录制组不能跨集合。旧五把已反复调参，只能称开发回归/按视频留一实验，不能恢复为新盲测。

独立推理入口只读取视频、模型、允许的元数据和产品输入；先保存不可变预测，再由另一个入口读真值评分。不能注入真实候选、真实长度、真实转体标签、答案反推初态、答案拟合颜色/对应或“真路径掉出束就停止”。GT 调试与 oracle 上限实验可以保留在明确诊断入口中，但产物必须标明辅助条件。替换评分答案不应改变预测文件或算法停止条件。

新几何 sidecar 若含人工面四边形、人工中心对应或从其传播的轨迹，必须标为人工几何诊断。只有经过像素支持的实例才能投到面格；缺几何时输出未锚定观测，缺时间映射时输出未解析时间。拒绝补齐网格不等于放弃解码，而是把“没有证据”与“证据反对”分开。

下表是继续研发的约束，不是给每个领域下永久否定结论。旧脚本中的“唯一杠杆”“几何全修好”“颜色墙已封死”等判断，被后续像素审计部分推翻。不能原样重跑后改名为新路线。

| 既有路线和证据 | 本轮不能重复的做法 | 足以重新考虑的重大变化 |
| --- | --- | --- |
| [roadmap §11](roadmap.md)：冻结 ResNet18+HS 特征约 57.6% LOO，MLP 约 60.3% LOVO；229 个非转体段严重失衡 | 在同批特征/旧五把上继续扫 KNN、MLP、SVM 超参并宣称泛化 | 独立录制数据、严格组内预处理、任务相关监督和真正更新的视觉表示；旧预处理曾使用全量数据，历史数字也非干净新基准 |

| [gain-ceiling.ts](scripts/gain-ceiling.ts)：用 GT 优化每观测色相/饱和度增益仍不足 | 把全局白平衡、色相偏移当作主要解法 | 改变采样支持、局部反光/材质/遮挡模型；该脚本只限制旧 patch 上的特定增益模型，不否定所有可微渲染 |

| [orient-probe.ts](scripts/orient-probe.ts)：晶格事件 AUC 约 0.63，高置信面分类仍不稳定；GT 拟合面标签也有噪声 | 靠晶格长宽比/切变猜面身份，或只在记谱转体时更新相机朝向 | 像素级中心/角点对应、连续手腕姿态、遮挡重定位及独立几何标签 |

| 4K 修正位置后 LL rank 35/4/18/1/5；不同通道逐视频最佳可到 35/2/2/1/1，仍无统一赢家 | 把逐视频最优 rank、部分末步成功或到达 solved 写成整把准确率 | 单一冻结配置、独立输入、完整序列及新保留集；单列候选是否含真实路径 |
| [backward-decode.ts](scripts/backward-decode.ts) 等诊断脚本读 GT 候选/长度/状态 | 包装旧调用链并改名“零 GT 自动推理” | 独立数据契约、输入白名单、保存后评分；历史 oracle 只用于层级归因 |

## 4. 25 个可考虑的技术路线或组件

它们属于不同层，有些互为替代，有些只帮助标注；不是 25 个可简单相加的增益。下文的验收问题是用户允许恢复实验后的计划，本轮不执行。

### 01. 可见色块实例分割与六色分类

**定位：推荐主线；独立像素监督路线尚无本项目效果证据。** 在魔方附近保留上下文，输出每个实际可见色块的 mask、颜色和置信度；Mask R-CNN 是当前单一基线，不先并行训练许多架构。

与旧冻结分类器的重大区别是监督对象和损失发生变化：学“哪块像素属于哪个可见色块”，不是从整段 pooled 特征猜 U/R。衣服、皮肤、桌垫、相邻同色块、反光和部分遮挡需要明确样本。当前代码只预测六色实例，`center_identity=not_predicted`、`is_center=null`；不得把标注字段存在等同于中心头已训练。

关键问题是固定 mask IoU≥0.5 且颜色正确的一对一匹配下，能否达到暂定 95% 精度、80% 召回，并改善真实片段动作。少量极清楚实例带来的高精度不能掩盖大段零覆盖。

### 02. 语义分割加实例边界或距离场

**定位：01 的备选，尚未验证。** 先分颜色/魔方/手/背景，再用实例边界、距离场或嵌入区分同色相邻块，可能适合固定小物体裁剪。

它更依赖真实边界标签；没有黑缝的无贴纸魔方不能强行按暗线分块，同色面上不存在的纹理也不能编造。若01主要失败是同色合并，才做同数据、同预算对照；若主要失败是长遮挡，换成语义分割不会增加可见信息。

### 03. 提示分割与视频 mask 传播

**定位：优先作为标注助手，自动推理为备选。** SAM 2 提供提示式图像/视频分割及带记忆的视频传播能力，可把人工点选的可见区域向邻近帧传播，减少重复画 mask。[SAM 2 原论文](https://arxiv.org/abs/2408.00714)

它不天然识别六色、中心或 cubie 身份，可能跟着手、合并相邻同色块或在消失后换对象。传播结果仍是提案；逐帧审阅状态与人工提示来源必须保存。手工点选后得到的序列属于辅助标注/辅助推理，不计为无提示自动能力。

### 04. 可见性、未知项与置信度校准

**定位：主线必需；具体模型尚待验证。** 将“未看到”“看到了但颜色不明”“颜色确定但格位未定”分开表达；按可见 mask、遮挡、模糊和几何支持设置拒判，必要时单独学习可读性。

它修复的是错误证据进入搜索的问题，不是把未知填成六色均匀噪声后继续算满格。校准阈值只能由验证集选择；要同时看精度、召回、时间覆盖及连续缺失长度。历史整链删格伤害 v3，说明要在实际污染发生的帧处理，并核对删票是否意外改变锚点与候选长度偏置。

### 05. 有对象上下文的读色与光照建模

**定位：推荐随01实施，额外复杂度由失败决定。** 先确保像素在色块内，再比较实例内稳健汇聚、局部纹理上下文和六色分类；保留白、黄、橙、红易混关系及饱和反光的未知状态。

仅调 HSV/kNN/每视频白平衡已经失败；重新考虑的条件是支持区域、监督和特征真正改变。可以使用允许输入里的独立清晰参考帧校准，但不能从测试真实状态拟合颜色。更多颜色概率精度只有在整段动作同时改善时才有价值，不能以逐格准确率单独决定融合权重。

### 06. 面角点、四边形与局部格位对应

**定位：推荐主线；自动关键点检测尚未验证。** 预测可见面角点、边和实例之间的邻接关系，得到受像素支持的面四边形/单应关系，再分配有证据的格位。输出应包含支持实例、残差和未覆盖格。

这与旧“找到仿射晶格就外插9格”不同。转动中的层可能不共面，四角被遮挡时应保留不完整几何，避免从两个 blob 猜出满面。首要验收是独立格位身份和绝对位置，而不是拟合线看起来整齐；人工四边形只用于上限诊断。

### 07. 中心身份和离散朝向锚定

**定位：推荐主线；作者转述支持方向，不等于实现披露。** 中心判断需要实例位置、面几何和时间关系，不能仅凭颜色。在配色关系已知、层对齐、两个相邻中心及各自面方向均已确认时，可消除离散立方体朝向歧义。

两个彩色像素点本身不足以恢复连续 6DoF，也不能推出隐藏色块。中心未同时出现时，可沿可信轨迹延续或保留少量几何候选；不要求每帧必须看见两个中心。需要统计双中心、单中心、无中心覆盖及最长缺失区间，防止仅在容易帧成立。

### 08. 连续 6DoF 与模型驱动姿态估计

**定位：几何备选；在平面对应不足时投入。** 用已知立方体尺寸/相机内参和真实2D–3D对应估计连续相机姿态；OpenCV 的 PnP 求解明确依赖对象点、图像点、内参等条件，点数与退化情况取决于算法。[OpenCV solvePnP 文档](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)

完整 CAD 姿态跟踪可参考 FoundationPose，但原论文路线使用 RGB-D，且主要估计刚体变换；不能把“给 CAD 即用”搬到普通 RGB 速拧视频。魔方旋转对称、纹理随层转改变，层转期间更不是单一刚体。[FoundationPose 原论文](https://arxiv.org/html/2312.08344v1)

新的有效证据应是独立中心/角点重投影及遮挡后的身份恢复，不能再次用真实动作产生伪面标签来证明姿态好。多个可见面的对应应属于同一个帧级姿态假设；仅把各面的面内旋转候选做笛卡尔积、排除格位重叠，仍不足以证明它们在几何上兼容。若06+07足够，不必同时训练重型6DoF模型。

### 09. 长期点轨迹与实例关联

**定位：主线候选；有别于旧短程光流，尚未验证。** 从可信可见实例内部选择点，跟踪位置和可见性，结合面几何做重新检测/关联。CoTracker3 的原论文使用真实视频伪标签补充合成训练，说明跟踪可采用不同于旧 Farneback 的学习路线。[CoTracker3 原论文](https://arxiv.org/abs/2410.11831)

跟踪点不是 cubie 身份证明；遮挡后的同色新块和旋转层会造成身份交换。需要遮挡重现、90°/180°快转和手部干扰的真实对应标签。评价必须包含错误续接、失踪长度及动作结果，不能仅看轨迹平滑。跟踪失效时断轨并保留未知，比平滑地跟错对象更可取。

### 10. 分层运动、渲染比较与曝光积分

**定位：研究备选，代价高。** 同时描述整体刚体姿态和活动层角度，由候选物理状态渲染可见区域；必要时将曝光期间的运动积分到图像预测中，而非假设糊帧是清晰瞬时帧。

这是对旧 `gain-ceiling` 的重大扩展：几何、遮挡、层运动和曝光发生变化，不能只换一组色相增益就声称尝试过完整渲染。风险包括材质/光照域差、对称局部极值、相机标定和昂贵搜索。先问正确姿态与已知短序列下，渲染残差能否区分真/假动作；若不能，不扩成全局优化。中心 logo 仅在图案清晰且非对称时可提供附加角度证据，不能成为所有视频的前提。

### 11. 完成边界、层对齐状态与时长模型

**定位：自动主线必需，旧运动峰不足。** 将“层开始动—中间运动—重新对齐”与整体手腕活动分开，输出多个完成边界候选及不确定区间；用状态变化、局部层运动和时长约束支持候选，不先固定一步一峰。

真实高速连续转动可能没有清晰静止帧，180°可能跨过90°位置，双转/同时动作不能被机械拆分。需要完成时刻标签与漏切/过切诊断。第一版可以只产“此区间可见状态变化”的建议；在边界覆盖和动作对齐未过门槛前，这不是完整自动分段。

### 12. 局部时序动作分类器

**定位：动作候选生成备选，旧冻结特征版本已失败。** 在短时间窗口内联合RGB实例、相对几何和时间特征，预测动作/方向/角度的分布，供搜索使用；可选轻量时序卷积或Transformer，但先选一个基线。

重启条件是独立新录制、正确时间标签、类别覆盖及任务微调，不能只把旧229段喂更大网络。至少分开“面识别对、方向错”“180°拆错”“真实动作不在top-K”。候选裁剪会永远排除的真动作，后续搜索无法救回；应保留受预算约束的低概率回退。

### 13. CTC 或其他完整序列转写模型

**定位：与显式几何主线并行的备选，尚未验证。** 视频编码器直接输出动作序列，可减少逐帧完整监督；CTC 用序列标签对齐未分段输入，但输出峰不自动等于转动完成时刻，重复动作及 blank 折叠规则必须正确处理。[CTC 原论文](https://www.cs.toronto.edu/~graves/icml_2006.pdf)

用户分享中的 DeepCube 官方仓库确实面向 sequential action recognition，包含按帧动作、时间定位标注与 CTC 解码依赖，不能误写为只做慢速R/U/F三分类。[DeepCube 官方仓库](https://github.com/deep-cube/deep-cube)

本项目的风险是录制数少、模板先验吞掉手滑/重复动作，以及背景/选手记忆。可加物理状态辅助损失或候选验证，但验证通过不等于轨迹正确。首先与同输入、同数据的12和显式主线比较；不把通用视频大模型的名称当成效果证据。

### 14. 已知初态/终态的物理约束搜索

**定位：推荐主线，已有引擎可复用，真实端到端效果未成立。** 复用物理置换语义，把独立初态、可信终态、时间观测与合法动作连接起来。前向、后向或双端策略取决于哪一端有证据，不能永远假设尾部干净。

搜索预算、停止条件和候选生成只依赖输入与固定配置，保留失败/超时。尤其不能按 cube state 合并掉所有不同路径：两条轨迹到达同态可能包含不同回拧与实际事件。状态去重策略、同态路径保留预算、步数/时间上限都要显式；“找到一个可达解”与“足以唯一辨认实际轨迹”分开输出。有限束留下的候选间分差只反映幸存者，单候选也可能是剪枝结果；它们不是校准后的正确概率。

### 15. 时间、姿态、状态的联合概率推断

**定位：14 的研究升级，尚未验证。** 把连续相机姿态、离散立方体朝向、层状态、边界和可见性作为联合变量，采用因子图/粒子或分层束搜索，减少先分段、再定位、再搜索的错误锁死。

收益是保留互相约束的候选，代价是状态空间和模型误差。旧每帧自由24朝向已经展示过错误假设找补空间；新路线必须有像素支持的转移、可见性与时间平滑，不能自由拟合所有变量。重复相邻帧、同一像素派生的色类和轨迹并非独立证据，不可简单相乘放大置信度。

### 16. CFOP/公式字典与动作语言先验

**定位：可选弱先验，不能承担真值恢复。** 已知常见触发、阶段和公式能帮助排序或建议修正，但可能漏掉个人指法、Roux、手滑、回拧和未收录变体。

旧 LL 字典排名在候选覆盖、已知长度/对齐等条件下成立，其中还有注入GT的路径。生产候选必须由允许输入生成，并保留脱离字典的路径。先验权重只在验证集定；若模型输出更“标准”而事件编辑距离更差，就属于负改动，不能用终态合法为其辩护。

### 17. 指尖接触与手—魔方联合建模

**定位：低优先备选，旧手部统计路线已失败。** 可探索手指到可见层的接触点、相对位移、受力方向代理与握持关系，而不是仅从左右手速度猜L/R。

这需要独立接触/局部运动标签与魔方几何；两手在9TPS附近持续活动，手部检出率不代表转动分类能力。遮挡时接触也可能不可见，只能增加有来源的软证据。若新特征与现有视觉错误高度相关，融合仍可能变差；应先证明它在旧失败片段中提供了别的通道没有的信息。

### 18. 领域内自监督预训练

**定位：数据量足够后的备选。** 用训练组未标注视频学习时空表示，再接动作/实例监督，可能改善通用特征与高速魔方的域差。VideoMAE 是可参考的掩码视频预训练路线，其论文“小数据”结果约为3,000–4,000条视频，不能理解成五把旧视频就足够。[VideoMAE 原论文](https://arxiv.org/abs/2203.12602)

仅恢复外观容易学到背景而非层运动；仍需真实下游GT和按录制分组。即使没有动作标签，也不能偷偷把保留测试视频用于预训练后继续称完全未见。先用现成预训练模型微调；从头领域预训练需要新数据和明确资源收益证据。

### 19. 合成数据与域随机化

**定位：补真实数据缺口的备选，不先造大渲染器。** 可生成准确的mask、中心、层角度、可见性与动作时间，定向覆盖稀有D/L、遮挡、手腕姿态和连续动作；灯光、材质、背景、曝光和相机需变化。

OpenAI的魔方机器人论文展示了ADR支持模拟到现实的状态估计/控制，但它使用专用平台，视觉系统含三相机，部分实验还依赖特殊中心贴纸或改装智能魔方，不能当普通单目速拧复盘已解决的证据。[Solving Rubik’s Cube with a Robot Hand](https://arxiv.org/html/1910.07113v1)

本项目可以先只合成少量几何/运动难例；真实手遮挡、反光、磁定位及拍摄模糊是域差。最终改进必须落在未用于调参的真实1080p50素材上，合成高分不能抵偿真实退步。

### 20. 弱监督、自训练和物理一致性伪标签

**定位：真实小标注基线成立后的备选。** 使用训练组整段动作、可信初态、时序连续或高置信教师给未标帧提案，可降低逐帧标注量。

物理可达只排除不可能状态，无法唯一证明像素位置、实际路径或可见颜色。伪标签应保留教师版本、置信度和来源，与 `human-visible` 分开；定期抽取低置信/冲突样本人工审核。不得把解码自己的答案投回图像后当新独立证据，再报告循环增强的“准确率”。

### 21. 主动学习与针对性标注

**定位：推荐的数据投入策略，不是单独识别模型。** 用不确定性、不同模型分歧、低覆盖时间段和新场景选择待标片段，再去除近重复；可优先问“这是中心吗”“此处属于手还是色块”“完成发生在哪两帧之间”。

不能只挑模型已有覆盖的容易样本，也不能从最终保留集挑失败例修好后继续用原保留集声称泛化。第一批200–400个独立审核帧是试验规模，不是已证明足够；扩到2,000–5,000帧也须由错误构成决定。以单位人工时间带来的覆盖和序列改善衡量，不以标注帧总量衡量。

### 22. 智能魔方同步辅助动作标注

**定位：推荐的新增训练数据来源，视频推理仍可保持单目。** 用户现有 GAN 16 UI 可作为默认采集设备；录制视频同时保留原始动作事件、设备时间/接收时间和同步过程，之后由人审阅丢包、补包、半转组合与明显错位。

蓝牙事件到达时刻不能直接当视频完成时刻，需要估计偏移、漂移及设备事件语义；整体转体/换握也不一定由层转日志完整表达。智能魔方日志只进入标注/训练或明确硬件辅助产品模式，盲测时不能作为视频预测输入。普通魔方仍须有保留样本，避免只学会某一外观、logo或录制方式。

### 23. 多视角、深度与受控拍摄

**定位：改变输入条件的备选，可先作为标注上限。** 同步两台以上相机可让一处被手挡住的动作在另一路可见；标定/对齐后联合几何，或用辅机帮助审核主机GT。深度可能支持姿态，但需要真实传感器输入，单目估计深度不是独立量测。

代价是同步、标定、设备、重复曝光差异和新的产品门槛；不能把多视角成绩混进单目80%。OpenAI论文中的多相机与特殊硬件条件提醒我们应明确区分这些设定，而非直接搬其成功率。[原论文的视觉状态估计](https://arxiv.org/html/1910.07113v1#S7)

若目标仍是任意既有视频，主线不能要求重拍；若用户愿意按约定角度拍摄，可以限定可读中心/魔方像素尺寸等条件并如实报适用范围。事件相机等新传感器仅属远期另一产品输入，不是当前RGB文件的补丁。

### 24. VLM 做局部审核和弱标注

**定位：推荐用于排查，完整动作转写为低优先备选。** 历史VLM叠图盲读发现网格落在衣服/手上，这证明它适合帮助定位错误来源；并没有证明其逐动作时序精度或所有颜色判断可靠。

给定短窗、原图和明确问题，可提议mask/中心/遮挡审核项；答案应包含像素位置和不确定性，并由人或独立证据核查。不要直接把几十秒视频交给VLM生成顺畅公式后当真值，也不要给出答案再问“是否一致”作为盲审。模型版本、抽帧、图像缩放和交互成本会影响结果，均须保存。

### 25. 人工修正与最少询问的复盘助手

**定位：推荐的产品闭环；不能冲抵自动指标。** 把不确定片段、两条有证据的路径及对应视频帧交给用户，允许改动作、边界、朝向或可见性，并只重算受影响区间。问用户一个关键锚点往往比让其重写整把更有价值。

必须保留自动原稿与修正后版本，分别计算自动分数、修正动作数、操作次数和耗时；不能把人工改完的结果登记为自动成功。歧义完全不可观测时给出多个候选/拒判，不靠默认最短解伪造唯一轨迹。复盘播放器和分析可复用已有能力，但只有可信动作以后才谈TPS、停顿与训练建议；停顿本身不能证明用户在想什么。

## 5. 如何组合，以及何时换路线

| 方案包 | 组成与前提 | 主要风险及转向依据 |
| --- | --- | --- |
| 主线：可解释观测加物理搜索 | 01、04–07、11、14；09在跟踪有效时加入，21/22/25支持数据与修正 | 关键是绝对位置、中心身份和边界覆盖；先证明正确观测能改善固定片段，再扩大训练 |
| 几何强化 | 在主线身份/朝向失败时选08，必要时研究10/15 | 输入条件与计算成本大幅增加；若像素本就完全不可见，几何优化不能造信息 |
| 序列学习 | 12或13，18/19/20按数据与误差选择 | 少样本模板记忆、漏重复动作、时间不准；与相同输入模式的主线公平比较 |
| 采集强化 | 22辅助标签，23另列多视角/受控产品模式 | 可以显著改变可观测性，但增加的输入必须显式披露 |

01和02通常是前端替代项；03首先是标注工具。06+07未失败前不急着同时堆08和10。12和13代表局部候选与整体转写两类学习目标。15不是“再开大一点beam”；它要求重新定义概率与变量。17、24只能在证明独立信息以后融合。把同一错网格派生的RGB、光流、颜色票全部相加，可能只是重复计算同一个错误。

当前优先级取决于可验证的瓶颈，不按模型新旧排名：位置错误先修位置，正确位置仍读错再修读色，观测正确而轨迹错再查对应/候选/搜索，人工边界过但自动边界不过才集中做时间模型。没有观测数据时，增加网络和损失数量无法判断进展。

## 7. GT 到位后的决策顺序（本轮不执行）

1. **接收与冻结。** 清点原片、独立打乱、原动作GT、时间来源；核对记谱事件和旧帧号，按录制/选手/场景分组。先取10–20条代表素材审核，不要求一次标完约100条。
2. **先辨别可辨识性。** 按 [plan.md](plan.md) 固定v1/v3各两段失败短窗及v2两段对照，共六段。候选、边界、预算不变，分别替换位置/可见性、颜色、像素支持的中心对应；GT导出短段初态只记诊断上限。
3. **观察因果改善。** 原定门槛是4个失败窗至少3个真路径排名改善、六窗总编辑距离下降、两个对照不新增错误。真实动作未被候选覆盖时先报告候选缺口；人工补全不可见几何只算oracle，不能并入自动成绩。
4. **支持观测路线才训练小基线。** 以200–400个独立审核帧起步，固定验证阈值和数据划分；若难例大量ignore，先决定损失/裁剪策略。训练完成后评位置/颜色/中心/覆盖，再评动作，不只看训练loss。
5. **逐项移除人工辅助。** 明确给定初态的5–10步片段、LL、整把逐级推进；人工边界与自动边界分开，中心/几何人工提示也另列。未知初态观察期恢复最后单独验收。
6. **固定版本再验保留集。** 保存预测后评分，包含所有失败与超时，再记录完整处理时间、冷启动、常驻状态、内存与错误构成。若依据保留集调参，该集合降为开发数据，另补新保留集。

当前本机与历史RTX配置不同，模型框架兼容、资源和时延须在实际设备上另行验证；文档、启动hook与监控不能代替操作系统防换出保证。本轮不启动训练或长计算，也不根据论文公开速度许诺本机速度。之后任何计算仍按仓库既有本地资源政策执行。
