# 魔方视频自动复盘 技术方案

## 当前计划：2026-09-14 基于失败证据的重启方案

本节是下一轮研发入口，汇总此前失败复核、作者回复及本轮素材和速度要求。后面的 v4 内容保留为历史方案，不代表当前已经实现的产品能力。此次只更新方案；没有重跑历史实验、训练模型或修改推理代码。

### 方案和第一笔投入

建议采用“可见色块检测与读色 → 中心锚定和几何对应 → 带未知项的时序观测 → 魔方物理约束搜索”。视觉部分从预训练模型微调，搜索部分复用已有实现；最终输出实际执行的动作、时间戳、置信状态和需要人工修正的位置。

第一笔投入限定为六段短视频的人工观测对照。先回答：**在用户实际需要的 1080p50 上，把位置、遮挡和颜色读对，现有候选是否更容易选中真实动作？** 只有证据支持检测/读色能解决当前错误，才投入模型标注和微调。模型变准但整段仍错，也必须能定位到对应、分段、候选或评分中的具体一层。

当前没有新增训练完成、整把自动成功或 20–40 秒完成的证据。约 100 条新素材是用户可提供的资源，尚未完成接收与清点；不把素材数量、人工修正后的结果或历史候选排名写成产品能力。

### 2026-09-14 作者补充：中心块作为朝向锚点

用户转述作者：使用几种方法，主要通过读出至少两个中心，再确定其它色块；因此视频角度非常重要。这是作者对主方法的说明，尚未披露如何检测中心、估计面几何或在中心不可见时衔接，也没有确认具体网络架构。

我们的解释是：在配色关系已知、层对齐且两个相邻中心已与各自面几何关联时，可以确定离散面朝向，进而给可见色块分配面和格位。固定面方向后，24 种刚体离散朝向在确认一个中心对应时剩 4 种，确认第二个相邻中心对应时剩 1 种；此前以正交轴枚举验证了该计数。仅有两个彩色像素点不足以唯一恢复连续三维姿态或透视网格，更不能推出遮挡色块的当前颜色。

阶段 A 增加中心锚定的对照：先按该阶段要求冻结六段，再标注可见中心、可读颜色、所属面和几何支持，统计双中心可读覆盖、仅单中心区间以及最长不可用时段；保持原候选、预算和边界条件，比较加入独立图像证据确定的中心朝向前后的格位对应与动作结果。模型标注同时保留中心身份，不把“颜色相同”视为“都是中心”。不从 GT 状态倒推这些像素标签。

中心不足时可尝试延续之前可信的跟踪，置信度不足则保留朝向候选或拒判；这是我们的待验证方案，不能归为作者已披露的方法。不要据此增加“每帧必须同时看到两个中心”的硬限制。可读双中心是优先检查的视频条件，中心附近面区域的透视、模糊和遮挡也要一起记录。

### 输入边界和评估隔离

先做已知打乱模式：视频、用户圈定的大致魔方区域、开始/结束时刻、独立提供的打乱。观察期识别初态及未知打乱模式后置，分别验收。用户选视频范围不等于人工标每一步。

现有五把可继续用于开发回归和按整段视频留一的迁移试验，但已经被多轮调参使用，不能再称为从未见过的盲测。同一原片的裁剪、转码、相邻帧和增广图必须同组；有独立录制素材后再冻结真正保留集，没有新素材时不宣称跨场景泛化。

| 当前辅助位置 | 下一轮处理 |
| --- | --- |
| `real-eval.ts:347–363` 用真实解法反推初态；637–655 行用真实边界状态拟合颜色映射 | 初态改由明确的产品输入提供；颜色映射从允许的观察帧/几何估计获得。旧反推初态仅保留在标明条件的诊断实验 |
| `real-eval.ts:941–970` 按手工 splits 和真实转体类别组织观测 | 诊断组可以保留，自动组必须从视频产生时间候选，不能暗中复用 |
| `backward-decode.ts:188–196、550、557` 用真实 LL 长度限制候选，并可能补入真实序列 | 独立推理不读答案长度、不注入答案；分别报告字典覆盖率与已有候选中的排名 |
| `backward-decode.ts:716–718` 在真实路径掉出束时停止 | 独立推理使用固定预算与可观测停止条件；答案只交给运行结束后的评估进程 |
| `backward-decode.ts:426` 的可选双通道配对使用端点，旧端点由 `real-eval.ts:1123–1131` 借真实状态选出 | 重新定义不依赖答案的时间/观测标识再接双通道，不能把旧双通道成绩直接搬到盲测 |
| `backward-decode.ts:232` 的 `Sstate` 未用于最终硬约束 | `--full` 不视为整段双端约束已完成；整段闭环时单独接入并验证 |

真实解法用于离线评分、训练集监督和明确标记的上限实验是正常研究方法；问题在于混入独立推理后仍称自动识别。`anchored-search` 的剪枝后 GT 调试输出和排除测试视频的颜色训练也应分别处理，不能一概删掉。

推理与评分应分开入口、分开数据目录。冻结原片来源、训练分组、配置、模型权重和代码版本；固定随机种子，加入检查：替换评估答案不得改变推理输出或算法停止条件，不要求实测墙钟耗时逐次相同。所有视频运行同一套配置，逐视频最优只作诊断参考。

### 素材安排：100 条原片如何使用

先接收本地文件夹路径，不要求先上传网站或一次标完全部素材。保留 4K 原片，清点后先选 10–20 条代表不同机位、选手、背景、快转和遮挡程度的素材审核；已有五把只作失败回归。没有新素材也能先做阶段 A 的旧失败诊断，但不能完成新素材泛化验收。

| 项目 | 本轮约定 |
| --- | --- |
| 主验收规格 | 1080p、每秒 50 个真实时间采样帧；核对时间戳、是否重复帧及慢放倍率，不把 50 fps 慢放文件当成真实 50 fps 拍摄 |
| 清单字段 | 原片路径/指纹、录制组、选手/机位组、分辨率、帧率、时长、魔方在画面中的像素尺寸、模糊/遮挡、打乱和人工复盘标签是否可用 |
| 分组 | 约 70% 训练、15% 验证、15% 保留测试，优先按独立录制和选手/场景分组，比例允许为避免泄漏而偏离；同原片裁剪、转码、相邻帧和增广全部同组 |
| 使用权限 | 训练组拟合权重；验证组选择模型/阈值和固定解码配置；保留组只在版本冻结后验收。测试失败后若据其调参，明确降为开发数据，并补充独立测试组 |
| 4K 与 1080p | 4K 用于诊断及辅助审核，生成的 1080p50 副本用于目标规格试验；只在 4K 读得出的颜色不能算 1080p 的可读标签。最终还需真实 1080p50 素材验证拍摄模糊、噪声和压缩差异 |
| 标注规模 | 首批 200–400 个去除近重复的帧用于小规模试验；通过后按主要错误逐批增补，可规划到 2,000–5,000 帧，但不是开跑前必须完成的最低量，也不保证达标 |

100 条同机位近重复视频不能视为 100 种场景。若每条 10 秒、50 fps，则约有 50,000 帧，但相邻帧高度相关；标注应覆盖困难变化，而不是平均抽大量静止帧。训练可以稀疏选帧，推理不能据此默认跳过高速转动帧。100 fps 降到 50 fps 也不会自动重现真实 50 fps 相机的曝光模糊。

标注保留原片 ID、PTS 时间戳、坐标变换、可见掩码、颜色或未知、中心身份或未知、可确认的面/格位及轨迹。像素可见性由当前规格图像判断，真实动作另作评分标签；模型分数与人工标签分开保存。先复核少量标注歧义，再扩大标注，不用旧网格或解法答案自动制造“金标”。

### 阶段 A：先证明正确观测能改善判别

首轮预算限定为两个旧失败视频 v1/v3 加较好视频 v2 的对照，不重跑全部参数组合。每把各选两个含连续 5–10 步的短片段，共六个，覆盖静止、快转、转体、遮挡、重新出现；在修改观测前冻结时间范围及基线结果，通过后再扩到整段。

中间片段需要自己的起止状态，不能直接使用整把打乱态。本阶段允许从 GT 推导片段状态，但必须记录为人工边界、已知片段状态的诊断实验；所有观测对照组使用相同状态条件。它只回答“正确观测能否改善判别”，不计入独立视频识别成绩。

1. 对同一冻结片段同时保留原片与 1080p50 版本，分别审核实际可见区域、可读颜色、可见性和真实时间戳；主判据使用 1080p50，原片结果只解释分辨率损失。只有能从图像及邻帧确认时才标面内格位/轨迹身份，不可确定的项标未知。
2. 旧网格、`bestAssign`、GT 状态回填颜色、解码器自举标签不得作为这套像素金标。已有 RGB 普查和错位裁片可用来选困难样本，但不等于实例分割标签。
3. 固定手工动作边界、候选和计算预算作为控制变量，比较：旧观测；修正实际采样位置/可见性后沿用旧读色；正确位置加独立审核颜色。必要时增加明确标为上限的正确格位对应组，区分检测不足和身份对应不足。
4. 同时报告采到魔方外像素的比例、格位对应正确率、颜色错误、每个边界的有效覆盖、正确路径与竞争路径分差及片段动作编辑距离。不能只报颜色准确率，或仅保留有答案的容易边界。

开跑前冻结通过口径：v1/v3 的四个片段应覆盖旧观测下仍判错的案例，其中至少三个真路径排名改善；六个片段的总动作编辑距离下降，v2 两个对照片段的编辑距离不增加，同时报告背景误采和覆盖变化。该门槛对每个干预组分别计算，不合并各组最佳结果。排名使用同一候选集，分差只作辅助，不能将改变观测数量后的分差直接等同于质量提升。若片段基线已全对，应先定位更长时序下的失败，不靠另挑结果漂亮的样本宣布通过。

| 哪一组达到门槛 | 下一笔投入 |
| --- | --- |
| 修正位置/可见性、沿用旧读色即改善 | 进入阶段 B，优先学实际可见实例定位和背景拒判 |
| 还需独立审核的正确颜色才改善 | 进入阶段 B，同时训练读色，分别复核颜色混淆与位置错误 |
| 只有加入图像可确认的中心/面对应才改善 | 先做阶段 C 中心锚定的短段验证，再确定阶段 B 所需的中心和几何监督 |
| 只有人工给定完整格位身份的上限组改善 | 暂不凭此扩大检测器训练；先证明自动几何对应能够保留这项收益 |
| 只在 4K 改善，1080p50 无效 | 先定位目标规格的信息损失和可支持拍摄条件，不按 4K 成绩宣布通过 |
| 所有正确观测组仍无效 | 检查时间对齐、候选覆盖和评分，暂停扩大标注与训练 |

六段是决定下一笔投入的工程筛选，不是泛化证明。交付须包含固定片段清单、独立标注、各对照组原图叠加、逐段排名/编辑距离及失败归因；没有这些产物不能只报一个平均准确率。

若真路径不在候选集，先记为候选生成失败；可另设两组共享的补入真路径评分上限实验，但不能据缺少候选直接否定视觉。若独立审核的正确观测仍无增益，先核查时间对应、姿态歧义和评分，暂停扩大训练。人工边界、GT 片段状态及补入真实候选必须在结果中标明，不能作为独立识别成绩。

### 阶段 B：微调可见色块模型

阶段 A 的定位/读色对照有效后才训练；仅格位身份上限组有效时，按上表先验证对应关系。先复用一个预训练实例分割实现做基线，例如 TorchVision Mask R-CNN；它支持自定义实例的框、类别和像素掩码，见 [PyTorch 官方微调教程](https://docs.pytorch.org/tutorials/intermediate/torchvision_tutorial)。选它是为了建立可复现对照，不是认定它最适合速拧，也不是认定 solve.vision 使用它。暂不同时比较多个网络家族。

- 首批训练/验证标注合计约 200–400 个去除近重复的帧，按已冻结分组选择，优先覆盖新素材及旧失败中的相同问题；这是可行性试验的投入上限，不承诺这些数据足以训练成产品。旧五把与阶段 A 的审核帧不能冒充未见测试集；正式保留测试标注另行安排。
- 输出可见色块实例掩码、颜色分布和检测分数；低可信区域允许拒判。检测分数不直接当作校准后的概率。不要预测被手完全挡住的贴纸颜色，也不强制输出完整 54 格。
- 标注仅包含实际可见区域。衣服、手和相似颜色的背景是重要负例；转动中的层可能不共面，不能先强制套一个刚性 3×3 平面。相邻同色色块确实无法分辨时记录歧义，不画出不存在的可见边界。
- 初版允许用户圈定大致区域，保持足够上下文，原始分辨率裁剪按需解码；暂不额外训练整帧定位器，不先造大规模合成数据渲染器。
- 暂定工程门槛为可读可见实例的联合位置/颜色精度达到 95%，同时召回不低于 80%。开训前冻结一对一匹配规则：预测按置信度排序，与未匹配标注取最大 mask IoU，IoU≥0.5 且颜色正确算 TP；错色计 FP 和对应 FN，重复框计 FP。精度为 TP/(TP+FP)，召回为 TP/(TP+FN)，零分母单列，不计作通过。置信阈值只在验证组选择。
- 无法读色、同色粘连无法分实例的区域先固定忽略规则，并单列数量、覆盖和模型在这些区域的输出，不可事后把错误改成忽略。另报逐视频及汇总结果、中心身份/位置错误、拒判比例和逐边界覆盖，避免靠只读极少色块提高精度。门槛是试验目标，不是已证明能保证解码成功的定律；在固定短段中替换观测后还须改善动作结果，单格达标不能直接扩量。
- 基线失败后只针对主要错误类别做一次有理由的调整；若仍不能在未参与训练的视频上同时改善精度和覆盖，回到标注/数据差异审计，不转去加大搜索束宽。

本机已检测到 RTX 3080 Laptop GPU，显存 16 GiB，内存约 32 GiB，可安排本地小规模微调试验；训练框架兼容性、实际批量与速度仍需短试跑验证。使用现有预训练权重微调，不从零训练大模型；本地训练与推理不需要按语言模型 token 付费。CPU 重任务最多 14 线程并低优先级运行。

### 阶段 C：连接几何对应与时间线

检测到“一块绿色区域”还不知道它是哪一面的哪一格。将实例按几何关系组成可见面、建立短时跟踪，在遮挡/重新出现处重估；连续相机姿态与离散魔方转动分开表示。图像中的左/右/上面不固定等于 R/L/U，初始 24 种离散朝向也不能替代连续手腕姿态。

优先复用 `src/sticker-blobs.ts`、`src/lattice-track.ts` 中可用的数据结构和 `RawFaceObs` 的未知/概率接口，但新的可见实例不能被适配器强行补成旧满网格。对应不确定时保留少量有几何证据的假设，遮挡不作为反证；不恢复到每帧任意自由指派所有面来凑分。

先在短片段、明确给定初态的条件下测自动观测与动作解码，再去掉人工动作边界。保留候选边界和时间对齐容错，覆盖漏切、过切、连续双转、转体、回拧和无清晰静止帧；不能假设旧运动峰检测已经解决分段。

交付内容是叠回原视频的检测/对应结果、自动动作时间线及失败原因。先验证 5–10 步连续片段，再验证 LL，最后扩到整把；LL 阶段的通过不等于完整产品通过。

本阶段先锁定阶段 A 的六段作集成回归，再从开发/验证组预选十段独立录制的短段/LL，不使用最终保留测试集调试。人工边界组与自动边界组分别评分：前者过、后者不过，就只查时间线；不能回退手工分段后仍称自动通过。进入整把前，自动组逐片段动作分数的平均值须达到 80%，相对同输入条件的旧基线改善，且六段回归无新增动作错误；同时报告中心缺失时段和格位误配。

动作时间统一记录转动完成时刻；人工可给不确定区间，预测落在区间内记零误差，其余计到最近端点的距离。暂定区间宽度不超过一个目标帧（50 fps 下为 20 ms）才可评估，且可评估动作须占全部真值动作至少 80%；更宽区间和长遮挡单列为时间不可判定，覆盖不足则不能判时序通过。在全部可评估真值动作中，至少 90% 须被正确匹配，且预测时刻落在标注区间或其前后一个目标帧内；漏步、错步不能从该分母删去，插步另列。以上是工程试验门槛，在查看自动组结果前冻结，不能靠扩大人工区间或只统计少数匹配动作达标。

### 阶段 D：整段复盘与产品接入

复用 `src/rotation-perms.ts` 的物理置换和现有 `anchored-search`，保持宽转、转体及相机坐标语义一致。先验字典可以排序或缩小常见候选，但必须报告未收录的实际执行，并保留手滑、回拧等视频动作；不能只寻找任意一条能复原的短解。

接通独立打乱初态与复原终态约束，验证 Cross/F2L/LL 的整段输出，再处理未知打乱及观察期输入。视频结束时未复原、视频截断、全遮挡、无法确定初态、解码存在多个等价候选时给出明确状态，不强行返回唯一成功。

在动作与时间线质量通过后，再接已有复盘播放器与分析能力，补低置信步骤人工修正。前端图表不作为本轮算法先导的交付前置条件。

阶段 D 用冻结后的版本一次运行全部保留视频，以独立打乱、粗 ROI 和开始/结束范围为唯一人工辅助；不提供真实动作数、LL 长度、转体标签或逐步边界。失败、超时和拒判均保留在总样本分母中；约 15 条保留视频只是首轮验收，须给出样本数和逐把结果，不据此宣称所有拍摄角度通用。

### 速度和部署：先测本机，再决定服务器

当前性能目标是：对 **10 秒的 1080p50 视频，质量达标后争取在 20–40 秒内生成复盘**。这来自用户的产品预期，尚无本项目实测支持；后文历史“单把 ≤5 分钟”不再是当前体验目标，也不能据网站演示反推其硬件。

| 实测瓶颈 | 有证据后才做的优化 |
| --- | --- |

## 5. 五条技术路线

### 路线 A: 区域颜色直方图差分

**思路**: 不定位 facelet，只看颜色像素面积变化

```
split_N → ROI 内颜色直方图
split_N+1 → ROI 内颜色直方图
差分 → 哪些颜色增减了 → 匹配动作指纹
```

**能力**: 可区分转动面，难区分方向 (U vs U')
**优势**: 最简单，对遮挡容忍度高
**劣势**: R/F 信号弱，方向盲
**降级**: 全局直方图太粗 → 改为分区域 (9 宫格)

### 路线 B: 光流旋转分析

**思路**: 在运动帧中分析像素流动方向

```
运动帧序列 → 稠密光流 → 旋转分量 → 旋转轴+方向+角度
```

**能力**: 直接读取旋转方向 (CW/CCW) 和角度 (90°/180°)
**优势**: 不依赖颜色，可消歧方向
**劣势**: 10 TPS 每动仅 4-10 帧，手指噪声大
**降级**: 稠密光流太噪 → 稀疏光流追踪角点 → 帧差法

### 路线 C: Facelet 精确定位

**思路**: 检测 3×3 网格，逐格读颜色

**能力**: 信息量最大
**优势**: 可精确推理动作+方向
**劣势**: 遮挡时大量格不可读，透视校正难
**降级**: 自动检测失败 → 手动标定第一帧角点 → 光流追踪

### 路线 D: 视频片段分类 (DL)

**思路**: 截取每步动作的 5-15 帧短片，送入分类器

**能力**: 理论上限最高
**优势**: 端到端，不需手工特征
**劣势**: 需要训练数据
**降级**: 真实数据不够 → 3D 渲染合成 → 或 few-shot 迁移

### 路线 E: 魔方约束搜索

**思路**: 利用打乱状态 + 解法结构约束 + 前几步信号，搜索最优序列

**能力**: 可修复个别识别错误
**优势**: 数学最优，天花板最高
**劣势**: 不知打乱状态时受限，计算量大
**降级**: 不知打乱 → 从已识别步骤反推 → 或只在 LL 做模式匹配

## 6. 推荐执行策略: 渐进融合 + 降级决策树

### 6.1 执行优先级

| 阶段 | 路线 | 做什么 | 通过标准 |
|------|------|--------|----------|
| **P1** | A | 颜色差分 → 粗定面 | 能区分 B/L/U/D |
| **P2** | B | 光流方向 → 消歧 | top-1 > 50% |
| **P3** | A+B | 融合 | top-1 > 70% |
| **P4** | E | 约束修复 | 整体 > 85% |
| **P5** | C/D | 兜底长尾 | 按需 |

### 6.2 降级决策树

```
P1 颜色差分
 ├ 有效 → P2 光流方向
 │  ├ 有效 → P3 融合 → P4 约束修复 → 搞定
 │  └ 无效 → 改用帧差法判方向
 │            ├ 有效 → P3 → P4 → 搞定
 │            └ 无效 → 人工标注方向, 训练小模型(路线D)
 └ 无效 → 转 路线 C (facelet)
            ├ 有效 → 直接推理动作 → P4 约束 → 搞定
            └ 无效 → 路线 D (视频分类器)
                      ├ 有效 →搞定
                      └ 无效 → 半自动: 置信度排序 + 人工确认
```

**最终兜底**: 即使全自动失败，有了分段 + 候选动作 + 约束搜索，
用户只需手动确认少数低置信度步骤即可，仍然远优于完全手动复盘。

### 10.2 实验结果汇总

| 版本 | 特征 | 维度 | LOO 最佳 | LOVO 最佳 |
|------|------|------|----------|-----------|
| P3-P4 | CNN 模板匹配 | — | 31.1% | — |

> **当前最优: LOVO 64.2%** (PCA50 K=5 cosine), 但已被 git reset 回 P6 基线。

### 10.3 各版本所用特征详解

#### CNN 中间帧 (512d)
- ResNet18 去最后 FC 层, 输入段中间帧的 ROI, 输出 512 维全局特征
- 单独识别率约 40-50%, 是最重要的基础特征

#### HS 颜色直方图差分 (96d) — 当前基线
- 段首帧/末帧的 ROI 分上下两区域, 各计算 HS 联合直方图 (12×4=48 bins)
- 末帧减首帧 = 颜色变化信号, 上下两区域共 96d
- 效果: 对 U 效果好 (顶行颜色变化明显), 对 R/L 效果差

#### 3×3 网格色差 (162d) — 已回滚
- 将 ROI 分 3×3=9 个网格, 每格计算 HS 直方图(6×3=18 bins) 差分
- 比全局直方图多了空间信息, LOO +3.1%, LOVO +4.8%

#### 光流 HOF (72d) — 已回滚
- 段中 2 帧计算光流, 分 3×3 网格各统计 8 方向幅度直方图
- 表达运动方向分布, LOVO +1.4%, 但计算很慢

#### 动态锚点 LR 差分 (2d) — 已回滚
- 用饱和度掩码找"魔方重心 x", 以此分左右区域统计垂直光流幅度
- 理论上 L 转右侧运动大, R 转左侧运动大
- 实际效果微弱 (+0.4%), 因为锚点被绿色外套等污染

### 10.4 关键发现

#### ✅ 已验证有效
1. **CNN + 颜色直方图差分** 是稳固基线, 能达 ~58% LOO
2. **3×3 网格空间划分** 比全局直方图显著提升 (+3-5%), 值得恢复
3. **光流 HOF 有正收益** (+1-2%), 但计算开销大
4. **PCA 降维 + cosine KNN** 效果优于 euclidean

#### ❌ 已验证无效 / 未成功
1. **饱和度掩码定位魔方** — 被绿色外套严重污染 (选手穿绿衣)
2. **帧差热力图定位 B 面** — 手部运动噪声 >> 贴纸信号, 包围盒膨胀到全帧
3. **ROI 三等分 ≈ B 面三列** — 错误假设, B 面只占 ROI 很小一部分
4. **每段帧差质心作为 B 面中心** — 质心被手部运动偏移, 不稳定

#### 🔴 核心瓶颈: L/R 混淆
- L 只有 29 段, R 有 81 段, 3:1 不平衡
- 从相机看: R 转 → B 面**左列**变色, L 转 → B 面**右列**变色
- 但 B 面左/右列在 ROI 中被手部大面积遮挡
- 当前模型把 60-80% 的 L 错判为 R
- **这是准确率突破 65% 的最大障碍**

### 10.7 下一步建议

#### 短期 (提升 L/R 区分)
1. **手动标注 B 面角点** — 在每个视频第 1 帧标 4 个角点, 透视变换得到正面化 B 面, 精确分 3 列
2. **数据增强** — L 只有 29 段, 可尝试左右水平翻转 R 段来增广 L 样本
3. **恢复 3×3 网格色差** — 已验证有效 (+5%), 之前回滚是因为和其他实验混在一起

#### 中期 (突破 70%)
4. **多帧时序特征** — 当前只用首/中/末 3 帧, 丢失了时间信息
5. **分类器升级** — SVM 或轻量 MLP 可能优于 KNN
6. **F 面特征** — F 面完全不可见, 但 F 转会影响 L 面右列和 U/D 面, 需间接推断

#### 长期 (突破 85%)
7. **魔方约束搜索 (路线 E)** — 用置换群验证 + CFOP 结构先验修复低置信度步骤
8. **视频分类器 (路线 D)** — 用 3D-CNN 或 TimeSformer 直接分类短视频片段
