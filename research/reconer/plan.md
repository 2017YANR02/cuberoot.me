### 2026-09-14 作者补充：中心块作为朝向锚点

用户转述作者：使用几种方法，主要通过读出至少两个中心，再确定其它色块；因此视频角度非常重要。这是作者对主方法的说明，尚未披露如何检测中心、估计面几何或在中心不可见时衔接，也没有确认具体网络架构。

我们的解释是：在配色关系已知、层对齐且两个相邻中心已与各自面几何关联时，可以确定离散面朝向，进而给可见色块分配面和格位。固定面方向后，24 种刚体离散朝向在确认一个中心对应时剩 4 种，确认第二个相邻中心对应时剩 1 种；本轮以正交轴枚举验证了该计数。仅有两个彩色像素点不足以唯一恢复连续三维姿态或透视网格，更不能推出遮挡色块的当前颜色。

阶段 A 增加中心锚定的对照：先按该阶段要求冻结六段，再标注可见中心、可读颜色、所属面和几何支持，统计双中心可读覆盖、仅单中心区间以及最长不可用时段；保持原候选、预算和边界条件，比较加入独立图像证据确定的中心朝向前后的格位对应与动作结果。模型标注同时保留中心身份，不把“颜色相同”视为“都是中心”。不从 GT 状态倒推这些像素标签。

中心不足时可尝试延续之前可信的跟踪，置信度不足则保留朝向候选或拒判；这是我们的待验证方案，不能归为作者已披露的方法。不要据此增加“每帧必须同时看到两个中心”的硬限制。可读双中心是优先检查的视频条件，中心附近面区域的透视、模糊和遮挡也要一起记录。

真实解法用于离线评分、训练集监督和明确标记的上限实验是正常研究方法；问题在于混入独立推理后仍称自动识别。`anchored-search` 的剪枝后 GT 调试输出和排除测试视频的颜色训练也应分别处理，不能一概删掉。

推理与评分应分开入口、分开数据目录。冻结原片来源、训练分组、配置、模型权重和代码版本；加入检查：替换评估答案不得改变推理输出或停止时刻。所有视频运行同一套配置，逐视频最优只作诊断参考。

### 阶段 A：先证明正确观测能改善判别

首轮预算限定为两个旧失败视频 v1/v3 加较好视频 v2 的对照，不重跑全部参数组合。每把各选两个含连续 5–10 步的短片段，共六个，覆盖静止、快转、转体、遮挡、重新出现；在修改观测前冻结时间范围及基线结果，通过后再扩到整段。

中间片段需要自己的起止状态，不能直接使用整把打乱态。本阶段允许从 GT 推导片段状态，但必须记录为人工边界、已知片段状态的诊断实验；所有观测对照组使用相同状态条件。它只回答“正确观测能否改善判别”，不计入独立视频识别成绩。

1. 在原始分辨率和真实时间戳上审核色块，标注实际可见区域、可读颜色、可见性。只有能从图像及邻帧确认时才标面内格位/轨迹身份，不可确定的项标未知。
2. 旧网格、`bestAssign`、GT 状态回填颜色、解码器自举标签不得作为这套像素金标。已有 RGB 普查和错位裁片可用来选困难样本，但不等于实例分割标签。
3. 固定手工动作边界、候选和计算预算作为控制变量，比较：旧观测；修正实际采样位置/可见性后沿用旧读色；正确位置加独立审核颜色。必要时增加明确标为上限的正确格位对应组，区分检测不足和身份对应不足。
4. 同时报告采到魔方外像素的比例、格位对应正确率、颜色错误、每个边界的有效覆盖、正确路径与竞争路径分差及片段动作编辑距离。不能只报颜色准确率，或仅保留有答案的容易边界。

开跑前冻结通过口径：v1/v3 的四个片段应覆盖旧观测下仍判错的案例，其中至少三个真路径排名改善；六个片段的总动作编辑距离下降，v2 两个对照片段的编辑距离不增加，同时报告背景误采和覆盖变化。排名使用同一候选集，分差只作辅助，不能将改变观测数量后的分差直接等同于质量提升。若片段基线已全对，应先定位更长时序下的失败，不靠另挑结果漂亮的样本宣布通过。

若真路径不在候选集，先记为候选生成失败；可另设两组共享的补入真路径评分上限实验，但不能据缺少候选直接否定视觉。若独立审核的正确观测仍无增益，先核查时间对应、姿态歧义和评分，暂停扩大训练。人工边界、GT 片段状态及补入真实候选必须在结果中标明，不能作为独立识别成绩。

### 阶段 B：微调可见色块模型

阶段 A 有效后才训练。先复用预训练实例分割实现做一个基线，例如 TorchVision Mask R-CNN；它支持自定义实例的框、类别和像素掩码，见 [PyTorch 官方微调教程](https://docs.pytorch.org/tutorials/intermediate/torchvision_tutorial)。选它是为了建立可复现对照，不是认定它最适合速拧，也不是认定 solve.vision 使用它。

- 首批标注预算约 200–400 个去除近重复的帧，覆盖五把的好坏案例和转动过渡帧；这是可行性试验的投入上限，不承诺这些数据足以训练成产品。按整段视频分组，预处理、颜色校准和阈值选择只使用训练/验证组。
- 输出可见色块实例掩码、颜色分布和检测分数；低可信区域允许拒判。检测分数不直接当作校准后的概率。不要预测被手完全挡住的贴纸颜色，也不强制输出完整 54 格。
- 标注仅包含实际可见区域。衣服、手和相似颜色的背景是重要负例；转动中的层可能不共面，不能先强制套一个刚性 3×3 平面。相邻同色色块确实无法分辨时记录歧义，不画出不存在的可见边界。
- 初版允许用户圈定大致区域，保持足够上下文，原始分辨率裁剪按需解码；暂不额外训练整帧定位器，不先造大规模合成数据渲染器。
- 暂定工程门槛为可读可见实例的联合位置/颜色精度达到 95%，同时召回不低于 80%；实例匹配与忽略规则在训练前冻结，例如 mask IoU≥0.5 且颜色正确算命中。另报中心误差、逐视频结果、拒判比例和逐边界覆盖，避免靠只读极少色块提高精度。门槛是试验目标，不是已证明能保证解码成功的定律。
- 基线失败后只针对主要错误类别做一次有理由的调整；若仍不能在未参与训练的视频上同时改善精度和覆盖，回到标注/数据差异审计，不转去加大搜索束宽。

本机已检测到 RTX 3080 Laptop GPU，显存 16 GiB，内存约 32 GiB，可安排本地小规模微调试验；训练框架兼容性、实际批量与速度仍需短试跑验证。使用现有预训练权重微调，不从零训练大模型；本地训练与推理不需要按语言模型 token 付费。CPU 重任务最多 14 线程并低优先级运行。

### 阶段 C：连接几何对应与时间线

检测到“一块绿色区域”还不知道它是哪一面的哪一格。将实例按几何关系组成可见面、建立短时跟踪，在遮挡/重新出现处重估；连续相机姿态与离散魔方转动分开表示。图像中的左/右/上面不固定等于 R/L/U，初始 24 种离散朝向也不能替代连续手腕姿态。

优先复用 `src/sticker-blobs.ts`、`src/lattice-track.ts` 中可用的数据结构和 `RawFaceObs` 的未知/概率接口，但新的可见实例不能被适配器强行补成旧满网格。对应不确定时保留少量有几何证据的假设，遮挡不作为反证；不恢复到每帧任意自由指派所有面来凑分。

先在短片段、明确给定初态的条件下测自动观测与动作解码，再去掉人工动作边界。保留候选边界和时间对齐容错，覆盖漏切、过切、连续双转、转体、回拧和无清晰静止帧；不能假设旧运动峰检测已经解决分段。

交付内容是叠回原视频的检测/对应结果、自动动作时间线及失败原因。先验证 5–10 步连续片段，再验证 LL，最后扩到整把；LL 阶段的通过不等于完整产品通过。

### 阶段 D：整段复盘与产品接入

复用 `src/rotation-perms.ts` 的物理置换和现有 `anchored-search`，保持宽转、转体及相机坐标语义一致。先验字典可以排序或缩小常见候选，但必须报告未收录的实际执行，并保留手滑、回拧等视频动作；不能只寻找任意一条能复原的短解。

接通独立打乱初态与复原终态约束，验证 Cross/F2L/LL 的整段输出，再处理未知打乱及观察期输入。视频结束时未复原、视频截断、全遮挡、无法确定初态、解码存在多个等价候选时给出明确状态，不强行返回唯一成功。

在动作与时间线质量通过后，再接已有复盘播放器与分析能力，补低置信步骤人工修正。前端图表不作为本轮算法先导的交付前置条件。

### 最终验收与停止条件

| 层次 | 必须分别记录 |
| --- | --- |
| 视觉 | 位置/颜色联合精度、召回、拒判率、覆盖空洞、魔方外误检、格位身份错误 |
| 动作 | 包含漏步、插步、替换的完整序列编辑距离；主分数定义为 `1 - editDistance / max(N预测, N真值)`，空输出单独处理；整把完全正确率另列 |
| 物理一致性 | 已知初态到终态是否可达、各步状态是否吻合视频；只到达复原态不等于执行动作正确 |
| 记谱与时序 | 预先固定物理等价记谱归一化规则，保留时间顺序，不用跨步消去隐藏实际回拧；另报动作时刻误差和人工修正量 |
| 产品 | 延续原目标：已声明支持范围内动作分数至少 80%，允许人工修正；整把正确率、人工步骤数和未知打乱模式单独验收 |
| 运行资源 | 分别测解码、视觉推理、搜索的耗时与峰值资源；质量通过后优化到单把 ≤5 分钟。旧耗时记录不作为本机当前承诺 |

`src/reconstruct.ts:129–145` 旧逐位对比只在两边都存在动作时计分，不适合新主指标；`src/cli.ts:75–79` 从预测反推初态再执行预测的复原检查只证明自洽，不能证明识别正确。物理等价与原始记谱成绩应同时保留，不能靠合并动作抹掉视频中的实际错误。

每轮明确“改了什么证据、固定了哪些变量、改善哪些失败样本”。正确观测无效就查对应和解码；正确观测有效但模型无效就查训练与检测；单格指标提高但路径更差就查覆盖和评分。没有新的因果证据，不重复 HSV/kNN 阈值扫描、同类光流/手部统计分类、盲目加大 beam 或按五把答案选配置。

下一轮只推进阶段 A 与必要的评估隔离，形成可复核的原图标注和固定条件对照结果；达到通过条件后再启动阶段 B。当前尚无训练完成或自动整把成功的新增证据。

        +---+                                +---+

## 4. 相机模型与可见面分析

### 4.1 视角几何 — 第三人称镜像

**关键**: 第三人称视角下，面名与选手视角的关系如下：

```
           选手视角                        相机视角 (第三人称)
        +---+                                +---+
        | U |                                | U |
    +---+---+---+                        +---+---+---+
    | L | F | R |      ← 相机在这边 →     | R | B | L |
    +---+---+---+                        +---+---+---+
        | D |                                | D |
        +---+                                +---+
```

所以相机实际看到的是：

| 相机中的位置 | 实际面名 | 可见程度 |
|-------------|---------|----------|
| 正对面 (最大) | **B 面** | ★★★★★ 大面积可见 |
| 画面右侧 | **L 面** | ★★★ 透视缩短，部分可见 |
| 画面左侧 | **R 面** | ★★ 偶尔可见侧边 |
| 顶部边缘 | **U 面** | ★★ 仅边缘 |
| 底部 | **D 面** | ★ 偶尔 |
| 远侧 | **F 面** | ✗ 不可见 |

### 4.2 各动作的可见变化指纹

以 B 面 (主可见面) 和 L 面 (次可见面) 为基准：

| 动作 | B 面变化 | L 面变化 | 可见总变化 | 辨识度 |
|------|---------|---------|-----------|--------|
| **B/B'** | **全 9 格旋转** | 左列 3 格 | 12 格 | ★★★★★ |
| **L/L'** | 右列 3 格 | **全 9 格旋转** | 12 格 | ★★★★★ |
| **U/U'** | 顶行 3 格 | 顶行 3 格 | 6 格 | ★★★★ |
| **D/D'** | 底行 3 格 | 底行 3 格 | 6 格 | ★★★★ |
| **R/R'** | 左列 3 格 | 不变 | 3 格 | ★★☆ |
| **F/F'** | 不变 | 右列 3 格 | 3 格 | ★★☆ |

**关键发现**:
- **B, L** 是最容易识别的 — 整面旋转，变化最显著
- **U, D** 中等 — 两面各一行
- **R, F** 最难 — 仅单面单列，且 R 在 B 面左边缘（常被左手遮挡）

### 4.3 GT 中各动作出现频次

```
F:  3次  (Cross×2, F2L×1)     — 可见变化: L面右列, 辨识度★★☆
L:  9次  (Cross×1, F2L×6, LL×2) — 可见变化: 全面旋转, 辨识度★★★★★ 最好
D:  1次  (Cross)              — 可见变化: 两面底行, 辨识度★★★★ 
U: 14次  (最频繁)              — 可见变化: 两面顶行, 辨识度★★★★
R: 13次  (第二频繁)            — 可见变化: B面左列, 辨识度★★☆ 难点!
f:  2次  (F2L)                — 类似F但多一层, ★★★
```

**风险**: R 出现 13 次但辨识度最低 (★★☆)，是最大挑战。

## 5. 五条技术路线

### 路线 A: 区域颜色直方图差分

**思路**: 不定位 facelet，只看颜色像素面积变化

```
split_N → ROI 内颜色直方图
split_N+1 → ROI 内颜色直方图
差分 → 哪些颜色增减了 → 匹配动作指纹
```

**能力**: 可区分转动面，难区分方向 (U vs U')
**优势**: 最简单，对遮挡容忍度高
**劣势**: R/F 信号弱，方向盲
**降级**: 全局直方图太粗 → 改为分区域 (9 宫格)

### 路线 B: 光流旋转分析

**思路**: 在运动帧中分析像素流动方向

```
运动帧序列 → 稠密光流 → 旋转分量 → 旋转轴+方向+角度
```

**能力**: 直接读取旋转方向 (CW/CCW) 和角度 (90°/180°)
**优势**: 不依赖颜色，可消歧方向
**劣势**: 10 TPS 每动仅 4-10 帧，手指噪声大
**降级**: 稠密光流太噪 → 稀疏光流追踪角点 → 帧差法

### 路线 C: Facelet 精确定位

**思路**: 检测 3×3 网格，逐格读颜色

**能力**: 信息量最大
**优势**: 可精确推理动作+方向
**劣势**: 遮挡时大量格不可读，透视校正难
**降级**: 自动检测失败 → 手动标定第一帧角点 → 光流追踪

### 路线 D: 视频片段分类 (DL)

**思路**: 截取每步动作的 5-15 帧短片，送入分类器

**能力**: 理论上限最高
**优势**: 端到端，不需手工特征
**劣势**: 需要训练数据
**降级**: 真实数据不够 → 3D 渲染合成 → 或 few-shot 迁移

### 路线 E: 魔方约束搜索

**思路**: 利用打乱状态 + 解法结构约束 + 前几步信号，搜索最优序列

**能力**: 可修复个别识别错误
**优势**: 数学最优，天花板最高
**劣势**: 不知打乱状态时受限，计算量大
**降级**: 不知打乱 → 从已识别步骤反推 → 或只在 LL 做模式匹配

## 6. 推荐执行策略: 渐进融合 + 降级决策树

### 6.1 执行优先级

| 阶段 | 路线 | 做什么 | 通过标准 |
|------|------|--------|----------|
| **P1** | A | 颜色差分 → 粗定面 | 能区分 B/L/U/D |
| **P2** | B | 光流方向 → 消歧 | top-1 > 50% |
| **P3** | A+B | 融合 | top-1 > 70% |
| **P4** | E | 约束修复 | 整体 > 85% |
| **P5** | C/D | 兜底长尾 | 按需 |

### 6.2 降级决策树

```
P1 颜色差分
 ├ 有效 → P2 光流方向
 │  ├ 有效 → P3 融合 → P4 约束修复 → 搞定
 │  └ 无效 → 改用帧差法判方向
 │            ├ 有效 → P3 → P4 → 搞定
 │            └ 无效 → 人工标注方向, 训练小模型(路线D)
 └ 无效 → 转 路线 C (facelet)
            ├ 有效 → 直接推理动作 → P4 约束 → 搞定
            └ 无效 → 路线 D (视频分类器)
                      ├ 有效 →搞定
                      └ 无效 → 半自动: 置信度排序 + 人工确认
```

**最终兜底**: 即使全自动失败，有了分段 + 候选动作 + 约束搜索，
用户只需手动确认少数低置信度步骤即可，仍然远优于完全手动复盘。

### 10.2 实验结果汇总

| 版本 | 特征 | 维度 | LOO 最佳 | LOVO 最佳 |
|------|------|------|----------|-----------|
| P3-P4 | CNN 模板匹配 | — | 31.1% | — |
| P5 | CNN+hist | 608d | 51.1% | — |

| P6v2 | CNN + 网格色差(162d) | 674d | 60.7% | 62.4% |

> **当前最优: LOVO 64.2%** (PCA50 K=5 cosine), 但已被 git reset 回 P6 基线。

### 10.3 各版本所用特征详解

#### CNN 中间帧 (512d)
- ResNet18 去最后 FC 层, 输入段中间帧的 ROI, 输出 512 维全局特征
- 单独识别率约 40-50%, 是最重要的基础特征

#### HS 颜色直方图差分 (96d) — 当前基线
- 段首帧/末帧的 ROI 分上下两区域, 各计算 HS 联合直方图 (12×4=48 bins)
- 末帧减首帧 = 颜色变化信号, 上下两区域共 96d
- 效果: 对 U 效果好 (顶行颜色变化明显), 对 R/L 效果差

#### 3×3 网格色差 (162d) — 已回滚
- 将 ROI 分 3×3=9 个网格, 每格计算 HS 直方图(6×3=18 bins) 差分
- 比全局直方图多了空间信息, LOO +3.1%, LOVO +4.8%

#### 光流 HOF (72d) — 已回滚
- 段中 2 帧计算光流, 分 3×3 网格各统计 8 方向幅度直方图
- 表达运动方向分布, LOVO +1.4%, 但计算很慢

#### 动态锚点 LR 差分 (2d) — 已回滚
- 用饱和度掩码找"魔方重心 x", 以此分左右区域统计垂直光流幅度
- 理论上 L 转右侧运动大, R 转左侧运动大
- 实际效果微弱 (+0.4%), 因为锚点被绿色外套等污染

### 10.4 关键发现

#### ✅ 已验证有效
1. **CNN + 颜色直方图差分** 是稳固基线, 能达 ~58% LOO
2. **3×3 网格空间划分** 比全局直方图显著提升 (+3-5%), 值得恢复
3. **光流 HOF 有正收益** (+1-2%), 但计算开销大
4. **PCA 降维 + cosine KNN** 效果优于 euclidean

#### ❌ 已验证无效 / 未成功
1. **饱和度掩码定位魔方** — 被绿色外套严重污染 (选手穿绿衣)
2. **帧差热力图定位 B 面** — 手部运动噪声 >> 贴纸信号, 包围盒膨胀到全帧
3. **ROI 三等分 ≈ B 面三列** — 错误假设, B 面只占 ROI 很小一部分
4. **每段帧差质心作为 B 面中心** — 质心被手部运动偏移, 不稳定

#### 🔴 核心瓶颈: L/R 混淆
- L 只有 29 段, R 有 81 段, 3:1 不平衡
- 从相机看: R 转 → B 面**左列**变色, L 转 → B 面**右列**变色
- 但 B 面左/右列在 ROI 中被手部大面积遮挡
- 当前模型把 60-80% 的 L 错判为 R
- **这是准确率突破 65% 的最大障碍**

U,D,L,R,F,r,f,x,y

### 不涉及的转动层和转体操作
B,E,M,S,z

### 注意
本复盘均不存在z转体
x,y转体不计入步数
x转体不会被单独分段, y转体会被单独分段
UD'中间没有空格, 表示这两步是同时开始(或同时完成的), 在分段里它俩同属于一段, 是2个转动
L2'x'中间没有空格, 表示转动和转体是同时开始(或同时完成的), 在分段里它俩同属于一段, 算1个转体
